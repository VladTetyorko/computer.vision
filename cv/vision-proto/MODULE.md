# vision-proto

Java gRPC codegen (grpc-java) from the shared `proto/vision/v1/cv.proto` contract — the Java↔Python CV service wire format.

**Depends on:** io.grpc:grpc-{netty-shaded,protobuf,stub}, com.google.protobuf:protobuf-java, javax.annotation-api, org.junit.jupiter:junit-jupiter (test) · **Used by:** adapter-cv-grpc
**Build/test:** `./mvnw -B -pl cv/vision-proto test` (codegen + compile, plus one hand-written wire-additivity test class — see below)

## API surface
No hand-written production Java — everything under `com.drones.vision.proto.v1` is generated into `target/generated-sources/protobuf/{java,grpc-java}` from `proto/vision/v1/cv.proto` (`java_multiple_files = true`, `java_package = "com.drones.vision.proto.v1"`):
- Messages: `FrameRequest`, `BoundingBox`, `Detection`, `DetectionResponse`, `TrainingJobSpec`, `TrainingProgress`, `ModelInfo`, `ModelList`, `ModelRefMsg`, `Ack`, `DatasetChunk`, `UploadAck`, `TargetLock`, `TrackingConfig`, `PullControl`, **`GeoTelemetry`, `GeoPrior`, `GeoControl`, `GeoEvidence`, `GeoFix`, `ReferencePackChunk`, `ReferenceIndexStats`, `ReferenceIndexProgress`, `RegionRef`, `RegionInfo`, `RegionList`, `LedgerEntry`, `ObjectEvidence`, `ObjectClaims`, `FrameLedger`, `SessionFacts`, `ProcessFacts`, `InspectRequest`, `InspectResponse`, `ObjectState`, `DetectorTarget`, `DetectRequest`, `DetectResponse`** (`ObjectState` with nested `LabelCandidate`, `Identity`, `Kinematics`, `Belief`, `Provenance`, `Memory`, `Lock`, `Timing`) (each with a generated `*OrBuilder` and `.Builder`).
- Enums: `ImageEncoding` (`UNSPECIFIED`/`JPEG`/`BGR24`), `JobState` (`UNSPECIFIED`/`RUNNING`/`SUCCEEDED`/`FAILED`), `TrackingMode` (`UNSPECIFIED`/`OFF`/`ASSOCIATE`/`FOLLOW`), `TrackState` (`UNSPECIFIED`/`TENTATIVE`/`CONFIRMED`/`COASTING`/`LOST`), `DetectionSource` (`UNSPECIFIED`/`DETECTOR`/`TRACKER`), `DetectorReason` (`UNSPECIFIED`/`ALWAYS`/`CADENCE`/`TRACKER_FAILED`/`NO_LOCK`/`BOX_INVALID`/`COASTED_OUT`), **`GeoStatus`** (`UNSPECIFIED`/`FIX`/`NO_FIX`/`LOW_TEXTURE`/`OUT_OF_REGION`/`NO_INDEX`/`ERROR`), **`LedgerOutcome`** (`UNSPECIFIED`/`RAN`/`SKIPPED`/`FAILED`), **`ObjectLifecycle`** (`UNSPECIFIED`/`TENTATIVE`/`CONFIRMED`/`COASTING`/`LOST`/`DORMANT`), **`EvidenceSource`** (`UNSPECIFIED`/`DETECTOR`/`TRACKER`/`PREDICTED`/`MEMORY`/`REUPDATE`).
- gRPC stubs: `InferenceGrpc`, `TrainingGrpc`, `GeolocationGrpc`, **`DetectorGrpc`**, each with `*ImplBase`, `*Stub`, `*BlockingStub`, `*FutureStub`, and an `*.AsyncService` interface (grpc-java 1.64's async-service pattern).
- Proto services: `Inference.DetectStream(stream FrameRequest) returns (stream DetectionResponse)`, `Inference.DetectPulled(stream PullControl) returns (stream DetectionResponse)`, `Inference.Inspect(InspectRequest) returns (InspectResponse)`; `Training.StartTraining(TrainingJobSpec) returns (stream TrainingProgress)`, `Training.UploadDataset(stream DatasetChunk) returns (UploadAck)`, `Training.ListModels(google.protobuf.Empty) returns (ModelList)`, `Training.PromoteModel(ModelRefMsg) returns (Ack)`; `Geolocation.LocalizeStream(stream GeoControl) returns (stream GeoFix)`, `Geolocation.BuildReferenceIndex(stream ReferencePackChunk) returns (stream ReferenceIndexProgress)`, `Geolocation.ListRegions(google.protobuf.Empty) returns (RegionList)`, `Geolocation.DeleteRegion(RegionRef) returns (Ack)`; **`Detector.Detect(DetectRequest) returns (DetectResponse)`**.
- `DatasetChunk{dataset_id, content}` — one slice of a client-streamed YOLO dataset archive (`docs/plans/done/CV-TRAINING-V2-PLAN.md` §1); the concatenation of every chunk's `content`, in stream order, is a ZIP carrying the `docs/plans/done/CV-TRAINING-PLAN.md` §5 layout (`data.yaml`, `images/<name>`, `labels/<stem>.txt`). `dataset_id` is set on every chunk and must not change mid-stream. `UploadAck{ok, message, dataset_id, bytes_received, file_count}` is the single response once the client half-closes. `UploadDataset` is **additive** — `StartTraining`/`ListModels`/`PromoteModel` and every other message/RPC are unchanged (CV-TRAINING-V2 Wave W0; the Java client (`adapter-cv-grpc` W3) and Python servicer (`cv-service` W2) land in later, disjoint waves — this module only carries the generated shapes).

### Pull-mode control plane (MEDIA-SOT-PLAN wave M1) — additive, `DetectStream` untouched

`docs/plans/done/MEDIA-SOT-PLAN.md` §5.1, applied exactly as frozen. All additive — no existing field number, name or type changed; `DetectStream`'s wire shape and behaviour are byte-identical to before this wave.

- **`Inference.DetectPulled(stream PullControl) returns (stream DetectionResponse)`** (NEW RPC) — the worker dials mediamtx and decodes the stream itself; the client sends declarative desired state instead of frames, and receives the *same* `DetectionResponse` message `DetectStream` uses, with fields 16–21 populated.
- **`PullControl`** (NEW message, 11 fields) — restated on **every** message, same doctrine as `TrackingConfig` (a one-shot control message can be lost with no error and no retry — see `LatestOnlyMailbox` below). `stream_id` (1, also the mediamtx path name), `source_url` (2) and `rtsp_transport` (3) are read from the **first** message of the call only; `model_id`/`model_version`/`confidence_threshold`/`target_fps`/`detect_width`/`tracking`/`camera_pose` (4–10, all hot) take effect as soon as the worker sees them; `stop` (11) requests a clean drain + half-close. `tracking` reuses `TrackingConfig` and `camera_pose` reuses `CameraPose` verbatim — same messages `FrameRequest` uses, unmodified.
- **`DetectionResponse` fields 16–21** (NEW, pull-mode only — always zero in push mode): `decode_millis` (int64, local decode cost), `source_fps`/`achieved_fps` (float, measured rates), `dropped_frames` (int64, latest-wins decode-loop discards), `missed_deadlines` (int64, sampler deadlines with no frame to serve), `capture_skew_millis` (int64, worker's estimate of local-receipt-minus-capture skew; 0 = unknown). Together they are the accounting a Java-side round trip used to give for free and pull mode must now report explicitly, because there is no longer a Java→Python frame round trip to measure it from.

### Tracking (TRACKING-PLAN wave T0) — additive wire contract for the detect-then-track duty cycle

`docs/plans/done/TRACKING-PLAN.md` §4.A, applied verbatim. All additive — no existing field number, name or type changed.

- **`FrameRequest.tracking = 11`** (`TrackingConfig`, NEW) — declarative per-stream tracking desired-state, restated on **every** `FrameRequest` (never a one-shot control message — see `cv/cv-service/MODULE.md`'s `LatestOnlyMailbox` drop behavior). Absent → `TRACKING_MODE_OFF`, byte-identical to pre-tracking behavior.
- **`Detection` fields 4–9** (NEW): `track_id` (int64), `track_state` (`TrackState`), `source` (`DetectionSource`), `velocity_x`/`velocity_y` (float, normalized frame-widths/heights per second), `track_age_frames` (int32).
- **`DetectionResponse` fields 8–12** (NEW): `tracker_millis` (int64), `detector_ran` (bool), `tracker_engine_id` (string), `locked_track_id` (int64), `detector_reason` (`DetectorReason`).
- **`TargetLock`** (NEW message) — which object `FOLLOW` mode should hold, keyed by a monotonic per-stream `lock_seq` (cv-service applies a lock only when strictly greater than the last applied — makes restating idempotent). One of `track_id` / `point_x,point_y` / `release`.
- **`TrackingConfig`** (NEW message) — `mode`, `engine_id` (`""` = server default), `verify_every_millis`, `redetect_iou_threshold`, `max_age_frames`, `min_hits` (each `<=0` = server default), `lock`.

**Sentinels, spelled out once:**
- **`Detection.track_id == 0` means "untracked"** and must never reach the Java domain as a real track. cv-service allocates ids starting at **1** per stream.
- **`DetectionResponse.detector_reason` is `DETECTOR_REASON_UNSPECIFIED`** whenever no detector pass ran on that frame (i.e. whenever `detector_ran == false`) — it is the *why* beside `detector_ran`'s *whether* (docs/extracts/TRACKING-ORCHESTRATION.md §5.1).
- Every new enum's `0` value is its own `*_UNSPECIFIED` — old client / old server / "tracking never touched this message" all read the same way: the zero value.

### Visual geolocation (VISUAL-GEO-V2-PLAN wave H1) — additive, new `Geolocation` service

`docs/plans/done/VISUAL-GEO-V2-PLAN.md` §3.1, applied verbatim (a minimised subset of the parked branch `feat/visual-geo`'s own "Visual geolocation" section — the plan governs, the branch is reference only). Wholly new section; touches no existing message, enum, field number or service. **Pull-only** (D2): the worker dials the video source itself, exactly like `Inference.DetectPulled` — there is no frame payload on this wire, in either direction.

- **`GeoTelemetry`** (NEW, 12 fields, every field `optional` except `sample_millis`) — everything the rectifier and the priors need, restated on every `GeoControl` message: WGS-84 fix (`latitude`/`longitude`), `amsl_meters`/`agl_meters` (mirrors `Telemetry.altitudeMeters`/`.aglMeters`), `heading_degrees`, `groundspeed_mps`, camera pointing in `rectify.py`'s **degrees-from-nadir** convention (`camera_pitch_deg`/`camera_roll_deg`/`camera_yaw_deg` — converted from `Attitude`'s positive-up gimbal pitch exactly once, at the Java codec, VISUAL-GEO-V2-PLAN.md D6), `horizontal_fov_deg`, `gps_radius_meters`.
- **`GeoPrior`** (NEW) — `latitude`/`longitude`/`radius_meters`, restricts retrieval to a disc around where the station already believes the aircraft is.
- **`GeoControl`** (NEW) — declarative per-session desired state, restated on **every** message (same doctrine as `PullControl`/`TrackingConfig`). `stream_id` (1, also the mediamtx path name), `source_url` (2) and `rtsp_transport` (3) read from the **first** message only; `region_id` (4, `""` = search every `READY` region), `target_fps` (5), `telemetry` (6, hot `GeoTelemetry`), `prior` (7, hot `GeoPrior`), `stop` (8, clean drain + half-close).
- **`GeoStatus`** (NEW enum) — `UNSPECIFIED`/`FIX`/`NO_FIX`/`LOW_TEXTURE`/`OUT_OF_REGION`/`NO_INDEX`/`ERROR`.
- **`GeoEvidence`** (NEW, 14 fields) — why the worker believes (or refuses) a fix: `candidate_count`, `match_count`, `inlier_count` (the MAGSAC promotion gate), `inlier_ratio`, `rerank_margin`, `reprojection_rms_px`, `rectified`, `cell_calibrated`, `supporting_frames`, `baseline_meters`, `sequence_converged`, `sequence_spread_meters`, `sequence_updates`, `osm_prior` (the D8 tie-breaker multiplier; `1.0` = inert).
- **`GeoFix`** (NEW) — one localization result. `stream_id`/`sequence`/`frame_millis` (the frame's own `CaptureClock` capture time)/`status`/`region_id`/`tile_id` (`"<z>/<x>/<y>"`), `latitude`/`longitude`/`yaw_degrees`/`radius_meters`/`implied_agl_meters` (all `optional` — present iff `status == GEO_STATUS_FIX`, except `radius_meters` which is present with any position), `evidence` (`GeoEvidence`), `refusal` (`""` iff `FIX`; otherwise names the gate that refused), `telemetry_age_millis` (`frame_millis - telemetry.sample_millis`, signed), `latency_millis`.
- **`ReferencePackChunk`** (NEW) — `region_id` (set on every chunk, identical throughout the stream) + `content` (bytes); concatenation in stream order is a ZIP of `region.json` + `tiles/<z>_<x>_<y>.jpg`.
- **`ReferenceIndexStats`** (NEW, 10 fields) — `tile_count`, `descriptor_count`, `descriptor_dim`, `encoder_id`, self-calibrated `accept_similarity`/`accept_margin`, `holdout_recall_at_1`, `holdout_median_error_meters`, `index_bytes`, `never_accept_cells` (cells the calibration refuses outright).
- **`ReferenceIndexProgress`** (NEW) — `region_id`, `phase` (`"receiving"|"extracting"|"encoding"|"indexing"|"calibrating"|"done"`), `done`/`total`, `state` (reuses `JobState`), `message`, `stats` (optional `ReferenceIndexStats`, present only on the terminal `SUCCEEDED` event).
- **`RegionRef`** (NEW) — `region_id`. **`RegionInfo`** (NEW) — `region_id`, `name`, `zoom`, `stats` (`ReferenceIndexStats`), `built_at_millis`, `north`/`south`/`east`/`west`. **`RegionList`** (NEW) — `repeated RegionInfo regions`.
- **`service Geolocation`** (NEW) — `LocalizeStream(stream GeoControl) returns (stream GeoFix)`, `BuildReferenceIndex(stream ReferencePackChunk) returns (stream ReferenceIndexProgress)`, `ListRegions(google.protobuf.Empty) returns (RegionList)` (reuses the same `Empty` import `Training` already uses), `DeleteRegion(RegionRef) returns (Ack)` (reuses `Ack`).

**Sentinels, spelled out once:** every new enum's `0` value is its own `*_UNSPECIFIED`. A `GeoFix` without `latitude`/`longitude` is never a `(0,0)` position — absence is absence. `refusal` is `""` only on `GEO_STATUS_FIX`.

### CV orchestration (CV-ORCHESTRATION-PLAN waves W0 + W1) — additive; the debug surface and the object mirror

Two waves, one banner in the `.proto` each, both purely additive: no existing field number, name or type changed, and — decision **E8** — **no existing enum gained a value**. That last one is a hard rule for this file, not a preference: `cv/grpc`'s `DetectionFrameCodec` maps `TrackState`/`DetectionSource`/`DetectorReason` with exhaustive Java switch *expressions* that have no `default` branch, so a new value breaks the compile of every Java build, and an already-deployed codec decodes it as `UNRECOGNIZED` and nulls the whole track reference. New meanings therefore arrive as **new enums used only by new messages**.

**W0 — `Inference.Inspect`, the read-only debug surface** (`docs/plans/active/CV-ORCHESTRATION-PLAN.md` §4.4). Off the response path entirely; a client that never calls `Inspect` cannot tell it exists.

| Added | Shape |
|---|---|
| enum `LedgerOutcome` | `UNSPECIFIED`/`RAN`/`SKIPPED`/`FAILED` — what happened to one contributor on one frame |
| `LedgerEntry` | `contributor_id`, `outcome`, `reason`, `cost_ms`, `summary` (`map<string,string>`) |
| `ObjectEvidence` / `ObjectClaims` | one contributor's claim about one object, kept attributed; `ObjectClaims` exists only because protobuf cannot nest `repeated` directly in a map value |
| `FrameLedger` | one frame's complete evidence: ids, `level_served`, `detector_reason`, `eligible[]`, `entries[]` in run order, `objects` (`map<int64, ObjectClaims>`), `drops_since_last`, `gate_wait_ms`, `total_ms`, `halted` |
| `SessionFacts` / `ProcessFacts` | what one live session / the process as a whole is doing |
| `InspectRequest` / `InspectResponse` | empty `stream_id` → process facts + live stream ids; a named one → session facts + the last `frames` ledgers, `found=false` when nobody serves it |
| rpc `Inference.Inspect` | `InspectRequest → InspectResponse` |

**W1 — `ObjectState`, the mirror** (plan §4.5). One message describing one object as the platform currently sees it, so a reader stops reconstructing an identity from a box plus eight scalars.

| Added | Shape |
|---|---|
| enum `ObjectLifecycle` | `UNSPECIFIED`/`TENTATIVE`/`CONFIRMED`/`COASTING`/`LOST`/**`DORMANT`** — `DORMANT` is the state today's wire could never report: a retired identity still held in the per-stream gallery and still recoverable under its own number |
| enum `EvidenceSource` | `UNSPECIFIED`/`DETECTOR`/`TRACKER`/`PREDICTED`/`MEMORY`/`REUPDATE` — a superset of `DetectionSource` in meaning, a separate enum in fact (E8) |
| `ObjectState` | `id`, `lifecycle`, `stream_id` + seven nested group messages: `Identity` (elected `label`, `label_raw`, `candidates[]` as `LabelCandidate{label,weight}`, `stability`), `Kinematics` (`box`/`detector_box`/`tracker_box`/`predicted_box` + `horizon_ms`, `velocity_*`, `displacement_*`, `motion_compensated`), `Belief` (`confidence_raw`, `confidence_smoothed`, `existence`, `since_confirmed_ms`), `Provenance` (`source`, `contributors[]`, `assoc_cost`, `reupdated`), `Memory` (`recovered`, `identity_confidence`, `dormant_ms`, `gallery_matches`, `match_distance`), `Lock` (`locked`, `lock_seq_applied`), `Timing` (`first_seen_ms`, `last_seen_ms`, `last_confirmed_ms`, `age_frames`, `hits`, `misses`) |
| `DetectionResponse.objects = 27` | `repeated ObjectState` — one entry per **live and dormant** identity of the frame. A different set from `detections`: a coasting track with no detection this frame is here and not there, and a dormant identity is here and has never been anywhere |
| `DetectionResponse.ledger = 28` | `FrameLedger`, present **only** when the request asked for it |
| `FrameRequest.trace = 13`, `PullControl.trace = 12` | `bool`, restated every message like the rest of the desired state; `false` at every call site today |

**Sentinels, spelled out once:** every new enum's `0` value is its own `*_UNSPECIFIED`. An absent nested **group** means "this configuration does not compute these facts at all" (`kinematics.predicted_box` in FOLLOW, where the book is never whole-predicted); a zero **field** inside a present group means the fact is genuinely zero. `ObjectState` is keyed by `(stream_id, id)` so a later cross-camera fusion stage consumes it with no wire change (E5). Algorithm-shaped facts (the ego-motion `Transform`, appearance descriptors, per-term association weights) are deliberately **not** here — they are `ObjectEvidence.claim` in the ledger (E7): this message describes the object, the ledger describes the algorithm.

**Deprecated by comment in W1, never renumbered and never removed** (E14) — each is populated by cv-service and read by nobody, and each one's information now has a better home:

| Field(s) | Why dead | Where the information lives now |
|---|---|---|
| `TrackingConfig` 8/9/10 (`motion_engine_id`, `appearance_engine_id`, `memory_ttl_millis`) | no domain field, no REST field, no UI control anywhere in the stack (R4 surprise 3) | `SessionFacts.motion_engine_id`/`.appearance_engine_id` — a *served* engine, which a request field can never report |
| `TargetLock.box` (5) | the REST PATCH surface only ever accepted `trackId`/point/`release`; the codec deliberately never sets it (R4 surprise 4) | unchanged — kept so a non-vision client can still use it |
| `DetectionResponse` 13/14/15 (`detector_roi`, `motion_millis`, `motion_engine_id`) | zero call sites in the Java codec — the whole ego-motion story is computed and discarded end to end (R4 surprise 1) | `egomotion.*` and `detect.roi` ledger entries, with their own `cost_ms` |
| `DetectionResponse` 21 (`capture_skew_millis`) | decoded into `PullTelemetry`, consumed by no JSON DTO (R4 surprise 7) | the ledger |

### CV orchestration (CV-ORCHESTRATION-PLAN wave W4) — additive; the detector/tracker split

`docs/plans/active/CV-ORCHESTRATION-PLAN.md` §4.9, decision E11. A wholly new `Detector` service — the stateless half of a tracker/detector split, so a detector instance may be scaled to N instances behind an ordered target list (§4.9) while the tracker session stays sticky to one stream. Deliberately **not** a variant of `FrameRequest`: that message carries tracking config, camera pose and a stream-scoped contract a detector has no business seeing. Touches no existing message, enum, field number or service **except** widening `ProcessFacts` (still additive — new fields only).

| Added | Shape |
|---|---|
| `DetectRequest` | `stream_id`/`sequence` (accounting only — never keyed state, affinity lives in the caller's ordered target list), `width`, `height`, `encoding`, `data`, `model_id`, `model_version`, `confidence_threshold`, optional `roi` (presence = the ROI rescue crop; absent = full frame) |
| `DetectResponse` | `detections[]` (track fields always unset — a detector has no identity), `inference_millis`, `model_id`, and admission facts on **every** response: `occupancy`, `queue_depth`, `capacity`, `max_queue` (the bound above which this instance answers `RESOURCE_EXHAUSTED`) |
| `DetectorTarget` | one entry of a `pool` client's ordered target list: `target` (`"host:port"` or the literal `"local"`), `served`/`refused`/`failed` counters, `last_error` — **observed**, never probed, so an unused target reads all-zero rather than claiming to be up |
| `ProcessFacts` fields 6–10 (widened) | `gate_occupancy`, `gate_queue_depth`, `gate_max_queue` (0 on a process serving no `Detector`), `detector_targets[]` (empty unless `pool`), `role` (`CV_SERVICE_ROLE`, so "who am I" needs no second call) |
| rpc `Detector.Detect` | `DetectRequest → DetectResponse`, unary — no per-stream state to keep a stream open for, and unary is what makes "try the next target" a one-line failover |

**Sentinel, spelled out once:** a detector never sets any `Detection` track field (`track_id`, `track_state`, velocities, `track_age_frames`) — identity lives only in the tracker session that calls it, never in the detector's own response.

## Conventions
- `protoSourceRoot` points at `../../proto` (repo-root `proto/vision/v1/cv.proto`) — **not** a copy under this module; it is the single source of truth shared with `cv-service`'s Python codegen (`scripts/gen_proto.sh`). Never duplicate or fork the `.proto` file.
- Codegen via `org.xolstice.maven.plugins:protobuf-maven-plugin` (`${protobuf-maven-plugin.version}`=0.6.1), goals `compile` + `compile-custom` (the latter drives the `grpc-java` plugin, `pluginId=grpc-java`). `os-maven-plugin` (`${os-maven-plugin.version}`=1.7.1) resolves `${os.detected.classifier}` to pick the right native `protoc`/`protoc-gen-grpc-java` executables.
- Version pins (root `pom.xml` properties): `protobuf.version`=3.25.5 (both `protoc` and `protobuf-java`), `grpc.version`=1.64.0.
- `src/test/java/com/drones/vision/proto/v1/TrackingProtoAdditivityTest.java` is the **one** hand-written source in this module (added T0). It exists specifically to make proto3's additive guarantee a checked fact rather than a claim: each "expected" byte payload is built field-by-field with the raw protobuf wire format (`CodedOutputStream`, tag = `(fieldNumber << 3) | wireType`) covering only the fields that existed before this wave, independent of the generated classes' own serialization — so the test would catch e.g. a message field accidentally defaulting to a non-empty instance. Covers `FrameRequest` (no `tracking`), `Detection` (no track fields), and `DetectionResponse` (no tracking telemetry), plus one round-trip sanity test that the new fields decode correctly once populated.

## Gotchas
- Regenerate by rebuilding this module (any goal that runs `generate-sources`, e.g. `./mvnw -pl cv/vision-proto compile`) — nothing under `target/generated-sources` is hand-maintained; never edit generated files directly.
- Java's protobuf runtime stays on the `3.25.x` version line while Python's (`cv/cv-service/pyproject.toml`) pins `protobuf>=5.26.1,<6` — different-looking major versions for the **same** underlying release generation (protobuf unified its cross-language version numbering; Java/C++ kept the legacy `3.25.x` line for that generation while Python jumped to `5.26.x`). Not a real skew, and not something to "fix" — both consume the same `.proto` and produce the same wire format.
- This module previously had **no** test dependency declared (`no hand-written sources or tests` was literal). T0 added `org.junit.jupiter:junit-jupiter` (test scope) to `pom.xml` — version comes from the `spring-boot-starter-parent` BOM, same as every other module, so no explicit version pin was needed.
- `cv/cv-service/scripts/gen_proto.sh`'s output (`cv/cv-service/cv_service/gen/`) is gitignored and regenerated on demand from the same `proto/vision/v1/cv.proto` — confirmed re-running clean after the T0 diff (`vision/v1/cv_pb2.pyi` picks up `TrackingMode`, `DetectorReason`, etc.) and again after the M1 diff (`PullControl`, `DetectPulled`, `DetectionResponse` fields 16–21 all present in the regenerated `.pyi`); never commit it, never hand-edit it.
- **`DetectionResponse` field 16 was verified against the real file before this wave, not assumed from the plan** — fields 1–15 were confirmed contiguous with no gaps (last was `motion_engine_id = 15` from TRACKING-PLAN T0), so 16 was genuinely free. If a future wave needs the next free number, check `git diff`-free field list the same way rather than trusting a plan's stated number.
- `PullControl` and `DetectPulled` were placed in the `.proto` file's existing "wave section" idiom (a `// ---- <plan name> wave <id> ----` comment banner ahead of the new message, matching the T0 "NEW messages" precedent) rather than folded into the CHANGED-messages banner that already existed for `FrameRequest`/`Detection`/`DetectionResponse` — those messages are still only *widened*, `PullControl` is wholly new.
- **VISUAL-GEO-V2 H1 is the file's first use of proto3's explicit `optional` keyword on scalar fields** (`GeoTelemetry`'s 11 of 12 fields, `GeoControl.telemetry`/`.prior`, `GeoFix`'s position fields, `ReferenceIndexProgress.stats`). Every prior message got scalar-field presence for free only where a message-typed field already carries it implicitly (e.g. `TrackingConfig.lock`, `PullControl.camera_pose`) — `optional double`/`optional string` etc. needed the keyword spelled out for a `hasXxx()` accessor to exist at all. protoc 3.25.5 (this repo's pin) treats it as stable, no `--experimental_allow_proto3_optional` flag needed; verified by both `./mvnw -pl cv/vision-proto test` (Java) and a manual `grpc_tools.protoc` run against the venv (Python) in the same wave.
- §3.1 was applied **exactly as written in the plan** — no amendment was needed. It compiles clean, every field number is unique within its message, and the section touches zero pre-existing field/message/service.
