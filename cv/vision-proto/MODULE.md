# vision-proto

Java gRPC codegen (grpc-java) from the shared `proto/vision/v1/cv.proto` contract — the Java↔Python CV service wire format.

**Depends on:** io.grpc:grpc-{netty-shaded,protobuf,stub}, com.google.protobuf:protobuf-java, javax.annotation-api, org.junit.jupiter:junit-jupiter (test) · **Used by:** adapter-cv-grpc
**Build/test:** `./mvnw -B -pl cv/vision-proto test` (codegen + compile, plus one hand-written wire-additivity test class — see Conventions)

## API surface

No hand-written production Java — everything under `com.drones.vision.proto.v1` is generated into `target/generated-sources/protobuf/{java,grpc-java}` from `proto/vision/v1/cv.proto` (`java_multiple_files = true`, `java_package = "com.drones.vision.proto.v1"`). Every message gets a generated `*OrBuilder` and `.Builder`; every service gets `*ImplBase`, `*Stub`, `*BlockingStub`, `*FutureStub` and an `*.AsyncService` interface (grpc-java 1.64's async-service pattern).

### Services

- `Inference`: `DetectStream(stream FrameRequest) returns (stream DetectionResponse)` (push — client sends frames); `DetectPulled(stream PullControl) returns (stream DetectionResponse)` (pull — worker dials the source itself, same response shape, fields 16–21 populated); `Inspect(InspectRequest) returns (InspectResponse)` (read-only debug surface, off the response path).
- `Detector`: `Detect(DetectRequest) returns (DetectResponse)` — unary, stateless.
- `Training`: `StartTraining(TrainingJobSpec) returns (stream TrainingProgress)`; `UploadDataset(stream DatasetChunk) returns (UploadAck)`; `ListModels(google.protobuf.Empty) returns (ModelList)`; `PromoteModel(ModelRefMsg) returns (Ack)`.
- `Geolocation`: `LocalizeStream(stream GeoControl) returns (stream GeoFix)` (pull-only, no frame payload either direction); `BuildReferenceIndex(stream ReferencePackChunk) returns (stream ReferenceIndexProgress)`; `ListRegions(google.protobuf.Empty) returns (RegionList)`; `DeleteRegion(RegionRef) returns (Ack)`.

### Enums

`ImageEncoding`(UNSPECIFIED/JPEG/BGR24) · `TrackingMode`(UNSPECIFIED/OFF/ASSOCIATE/FOLLOW) · `TrackState`(UNSPECIFIED/TENTATIVE/CONFIRMED/COASTING/LOST) · `DetectionSource`(UNSPECIFIED/DETECTOR/TRACKER) · `DetectorReason`(UNSPECIFIED/ALWAYS/CADENCE/TRACKER_FAILED/NO_LOCK/BOX_INVALID/COASTED_OUT) · `JobState`(UNSPECIFIED/RUNNING/SUCCEEDED/FAILED — irregular naming, see Gotchas) · `LedgerOutcome`(UNSPECIFIED/RAN/SKIPPED/FAILED) · `ObjectLifecycle`(UNSPECIFIED/TENTATIVE/CONFIRMED/COASTING/LOST/DORMANT) · `EvidenceSource`(UNSPECIFIED/DETECTOR/TRACKER/PREDICTED/MEMORY/REUPDATE) · `GeoStatus`(UNSPECIFIED/FIX/NO_FIX/LOW_TEXTURE/OUT_OF_REGION/NO_INDEX/ERROR).

### Core inference

- **`FrameRequest`**: `stream_id`=1, `sequence`=2, `timestamp_millis`=3, `width`=4, `height`=5, `encoding`=6(`ImageEncoding`), `data`=7(bytes), `model_id`=8, `model_version`=9, `confidence_threshold`=10, `tracking`=11(`TrackingConfig`; absent → `TRACKING_MODE_OFF`), `camera_pose`=12(`CameraPose`; absent → flow-based ego-motion only), `trace`=13(bool; `true` attaches this frame's `FrameLedger` to the response, restated every request, byte-identical response when `false`).
- **`CameraPose`**: `yaw_degrees`=1(camera boresight heading), `pitch_degrees`=2(positive up), `roll_degrees`=3, `hfov_degrees`=4(0 = unknown → pose compensation disabled for this stream), `vfov_degrees`=5(0 = derive from `hfov` + frame aspect ratio), `pose_timestamp_millis`=6(0 = same instant as the frame). Every field is optional in effect; an absent/all-zero `CameraPose` degrades to flow-based ego-motion estimation, never an error — the normal state of a client that hasn't been taught to send one.
- **`BoundingBox`**: `x`=1, `y`=2, `width`=3, `height`=4 — normalized `[0,1]` relative to frame width/height, origin top-left; box occupies `[x, x+width] x [y, y+height]`.
- **`Detection`**: `label`=1, `confidence`=2, `box`=3(`BoundingBox`), `track_id`=4(int64; **0 = untracked**, must never reach the Java domain as a real track — real ids start at 1 per stream), `track_state`=5(`TrackState`), `source`=6(`DetectionSource`), `velocity_x`=7(normalized frame-widths/s), `velocity_y`=8(normalized frame-heights/s), `track_age_frames`=9(frames since this track was born), `identity_confidence`=10(>0 = this id was recovered from memory at this score, 0 = not a recovery), `dormant_millis`=11(how long dormant before recovery, 0 = not a recovery), **12–13 reserved** (`coast_millis`, `motion_confidence` — not yet used), `reupdated`=14(bool; true = this track's gap was reconstructed by ORU this frame).
- **`DetectionResponse`**: `stream_id`=1, `sequence`=2, `timestamp_millis`=3, `model_id`=4, `model_version`=5, `detections`=6(repeated `Detection`), `inference_millis`=7, `tracker_millis`=8(0 = no tracker ran), `detector_ran`=9(false = this frame was tracker-only/duty-cycled), `tracker_engine_id`=10(""=none), `locked_track_id`=11(FOLLOW: the track currently held, 0 = none), `detector_reason`=12(`DetectorReason`; **`UNSPECIFIED` whenever `detector_ran==false`** — the *why* beside `detector_ran`'s *whether*, see `docs/extracts/TRACKING-ORCHESTRATION.md` §5.1), `detector_roi`=13 / `motion_millis`=14 / `motion_engine_id`=15 (dead, see Deprecated fields below), `decode_millis`=16(pull-mode local decode cost), `source_fps`=17(measured rate of the pulled stream), `achieved_fps`=18(measured rate this loop actually infers), `dropped_frames`=19(cumulative frames genuinely dropped — a served frame superseded while still out for inference, or backlog discarded because the detector was busy; excludes frames the deadline sampler simply never selected because the source outran `target_fps`; populated under **both** `DetectStream` and `DetectPulled`, from the same `LatestOnlyMailbox.dropped` counter), `missed_deadlines`=20(cumulative sampler deadlines no frame arrived to serve), `capture_skew_millis`=21 (dead, see below), `reupdate_millis`=22(ORU cost this frame; 0 = none ran), `reupdated_tracks`=23(tracks backfilled by ORU this frame), `detection_lag_millis`=24(measured capture→association lag; 0 = unknown), `capability_level_served`=25(level that actually ran, always ≤ requested), `capability_level_reason`=26(why it was capped; ""=served as requested), `objects`=27(repeated `ObjectState` — one entry per **live and dormant** identity of the frame; a different set from `detections`: a coasting track with no detection this frame is here and not there, a dormant identity is here and has never been anywhere), `ledger`=28(`FrameLedger`; present **only** when the request asked for it via `trace`; zero cost when nobody looks — the ring is filled either way, but nothing serializes it).

### Tracking control plane

- **`TrackingConfig`** — declarative per-stream desired state, restated on **every** `FrameRequest`/`PullControl` (never a one-shot control message — see `cv/cv-service/MODULE.md`'s `LatestOnlyMailbox` drop behavior; a restated state is self-healing if a message is lost): `mode`=1(`TrackingMode`), `engine_id`=2(""=server default for the mode), `verify_every_millis`=3(FOLLOW re-verify cadence; <=0 → default 2000), `redetect_iou_threshold`=4(re-anchor when detector↔tracker IoU ≥ this; <=0 → default 0.3), `max_age_frames`=5(unmatched frames before LOST; <=0 → default 30), `min_hits`=6(detector hits TENTATIVE→CONFIRMED; <=0 → default 3), `lock`=7(`TargetLock`; FOLLOW only, absent = no lock held), `motion_engine_id`=8 / `appearance_engine_id`=9 / `memory_ttl_millis`=10 (dead, see below), `capability_level`=11(0 = auto-probe the highest level this host affords; 1–5 = an explicit **ceiling** — the session serves `min(requested, affordable)`, never more, never a refusal), **12–13 reserved** (`history_size`, `momentum_span_frames` — not yet used), `reupdate_max_gap_millis`=14(<=0 → server default; longest gap, in milliseconds, ORU will reconstruct from the two real observations bracketing it).
- **`TargetLock`** — which object FOLLOW mode should hold, keyed by `lock_seq`=1(int64, monotonic per stream; 0 = no lock ever issued — cv-service applies a lock only when strictly greater than the last one applied, which makes restating idempotent), `track_id`=2(lock onto an existing track; 0 = use point instead), `point_x`=3 / `point_y`=4(normalized `[0,1]` click point, used when `track_id==0`), `box`=5 (dead, see below), `release`=6(true = drop the current lock, fall back to the config's mode policy).

### Pull mode (`DetectPulled`)

- **`PullControl`** — declarative per-pull desired state, restated on **every** message, same doctrine as `TrackingConfig`: `stream_id`=1(vision `StreamId`, also the mediamtx path name), `source_url`=2(`rtsp://{host}:8554/{stream_id}`) / `rtsp_transport`=3(`"tcp"|"udp"|""`=server default) — both read from the **first** message of the call only; `model_id`=4 / `model_version`=5 / `confidence_threshold`=6 / `target_fps`=7(<=0=default; the Java rate controller's output) / `detect_width`=8(<=0=default; worker downscales locally) / `tracking`=9(`TrackingConfig`, reused verbatim including `TargetLock`/`lock_seq` semantics) / `camera_pose`=10(`CameraPose`, arrives at telemetry rate, decoupled from frames) — all **hot**, take effect as soon as the worker sees them; `stop`=11(bool; drain and half-close cleanly); `trace`=12(bool, hot).

### Training

- **`TrainingJobSpec`**: `base_model`=1, `dataset_id`=2, `epochs`=3.
- **`TrainingProgress`**: `job_id`=1, `epoch`=2, `total_epochs`=3, `loss`=4, `map50`=5, `state`=6(`JobState`), `message`=7.
- **`ModelInfo`**: `id`=1, `version`=2, `stage`=3, `metrics`=4(`map<string,float>`). **`ModelList`**: `models`=1(repeated `ModelInfo`). **`ModelRefMsg`**: `id`=1, `version`=2. **`Ack`**: `ok`=1, `message`=2.
- **`DatasetChunk`**: `dataset_id`=1(set on every chunk, must not change mid-stream), `content`=2(bytes) — one slice of a client-streamed YOLO dataset archive; the concatenation of every chunk's `content`, in stream order, is a ZIP carrying the `docs/plans/done/CV-TRAINING-PLAN.md` §5 layout: `data.yaml`, `images/<name>`, `labels/<stem>.txt`. The Java client (`adapter-cv-grpc`) and Python servicer (`cv-service`) that consume this shape live in those modules, not here.
- **`UploadAck`**: `ok`=1, `message`=2, `dataset_id`=3, `bytes_received`=4, `file_count`=5(files extracted, incl. `data.yaml`) — the single response once the client half-closes.

### Inspect debug surface

Off the response path entirely — a client that never calls `Inspect` cannot tell it exists.

- **`LedgerEntry`** — one contributor's row on one frame: `contributor_id`=1(e.g. `"detect.full"`, `"assoc.cost"`, `"follow.lk"`), `outcome`=2(`LedgerOutcome`), `reason`=3(why skipped, or `"<ExcType>: <message>"` when failed), `cost_ms`=4(double — the contributor's own measurement when it has one that reaches the wire, the orchestrator's wall clock otherwise; the two are never summed into a "total"), `summary`=5(`map<string,string>`, free-form facts the contributor chose to record).
- **`ObjectEvidence`**: `contributor_id`=1, `claim`=2(`map<string,string>`) — one claim **one** contributor made about **one** object, kept attributed rather than merged: "who said this" is a question a merged map can't answer. **`ObjectClaims`**: `claims`=1(repeated `ObjectEvidence`) — exists only because protobuf cannot nest `repeated` directly in a map value.
- **`TracedDetection`**: `label`=1, `confidence`=2, `box`=3(`BoundingBox`) — one raw detector box before association. Deliberately **not** `Detection`: that message's track fields (`track_id`, `track_state`, velocities…) would let the tracker's own output back into a fixture meant to test the tracker against detector noise it never saw.
- **`FrameLedger`** — one frame's complete evidence, bounded and in-memory (`CV_LEDGER_RING` frames per session; never persisted, never pushed — a client asks for it or it is forgotten): `stream_id`=1, `sequence`=2(this session's own frame counter, from 0), `captured_at_millis`=3, `level_served`=4(the capability ladder level this frame actually ran at), `detector_reason`=5(string — `DetectorReason`'s own value name, as the response carries it), `eligible`=6(repeated string, contributor **families** the budget allowed this frame), `entries`=7(repeated `LedgerEntry`, in run order), `objects`=8(`map<int64, ObjectClaims>`, track id → what was claimed about it), `drops_since_last`=9(frames the mailbox dropped before this one, push mode), `gate_wait_ms`=10(double, queueing plus inference), `total_ms`=11(double), `halted`=12(bool; a contributor stopped the frame — no model resolved), `detections`=13(repeated `TracedDetection` — `detect.full`'s raw output for this frame, before association, in the frame's own normalized coordinates; populated **only** when the request traced), `frame_width`=14 / `frame_height`=15(int32, source frame's pixel dimensions; 0 = not carried — a pre-W5b response, or an untraced frame).
- **`SessionFacts`** — what one live tracking session is doing right now: `stream_id`=1, `mode`=2(string, `TrackingMode`'s own value name), `engine_id`=3(the associator/follower actually serving, ""=none), `motion_engine_id`=4, `appearance_engine_id`=5, `level_served`=6, `level_reason`=7, `live_tracks`=8, `dormant_identities`=9, `locked_track_id`=10, `frames_processed`=11, `contributors`=12(repeated string, registered ids in run order).
- **`DetectorTarget`** — one entry of a `pool` client's ordered target list; health is **observed**, never probed, so an unused target reads all-zero rather than claiming to be up: `target`=1(`"host:port"` or the literal `"local"`), `served`=2(passes this target answered), `refused`=3(`RESOURCE_EXHAUSTED` — it was up and said no, the caller moved on), `failed`=4(unavailable/timeout/error — the caller moved on), `last_error`=5(""=succeeded since the last failure).
- **`ProcessFacts`** — what the process as a whole is doing, cheap enough to answer while streams are running: `detector_client`=1(`"local"` in-process, or `"pool"` — `CV_DETECTOR_TARGETS` set), `sessions`=2, `gate_permits`=3, `ledger_ring`=4(`CV_LEDGER_RING`, frames retained per session), `stream_ids`=5(repeated string), `gate_occupancy`=6, `gate_queue_depth`=7, `gate_max_queue`=8(the bound above which the `Detector` service answers `RESOURCE_EXHAUSTED`; 0 on a process serving no `Detector`), `detector_targets`=9(repeated `DetectorTarget`; set only on a `pool` client, empty on `local`, ordered exactly as `CV_DETECTOR_TARGETS`), `role`=10(string, `CV_SERVICE_ROLE`, so "who am I" needs no second call).
- **`InspectRequest`**: `stream_id`=1(""=process facts + live stream ids), `frames`=2(0 = the whole ring). **`InspectResponse`**: `process`=1(`ProcessFacts`), `session`=2(`SessionFacts`; set only when the request named a `stream_id`), `ledgers`=3(repeated `FrameLedger`, that session's last `frames` entries), `found`=4(bool; false when a named `stream_id` has no live session).

### `ObjectState` — the object mirror

One message describing one object as the platform currently sees it, keyed by `(stream_id, id)` so a later cross-camera fusion stage can consume a stream of these with no wire change. Algorithm-shaped facts (the ego-motion transform, appearance descriptors, per-term association weights) deliberately do **not** live here — they are `ObjectEvidence.claim` in the ledger: this message describes the object, the ledger describes the algorithm. An absent nested **group** means "this configuration does not compute these facts at all" (e.g. `kinematics.predicted_box` in FOLLOW, where the book is never whole-predicted); a zero **field** inside a present group means the fact is genuinely zero.

`ObjectState`: `id`=1(int64, per-stream track id, matches `Detection.track_id`), `lifecycle`=2(`ObjectLifecycle`), `stream_id`=3, `identity`=4, `kinematics`=5, `belief`=6, `provenance`=7, `memory`=8, `lock`=9, `timing`=10 — seven nested group messages:

- `Identity`: `label`=1(elected, hysteresis-gated — what an operator reads), `label_raw`=2(this frame's own detector label, un-elected), `candidates`=3(repeated `LabelCandidate{label=1, weight=2}`, best-first — the decayed, confidence-weighted vote tally behind the election, comparable only within one frame), `stability`=4(consecutive elections since `label` last changed).
- `Kinematics`: `box`=1(the elected box, identical to the `Detection` box), `detector_box`=2(what the detector claimed this frame; absent if none), `tracker_box`=3(what the single-object tracker claimed; FOLLOW only), `predicted_box`=4(constant-velocity extrapolation to this frame's instant), `horizon_ms`=5(how far `predicted_box` was extrapolated), `velocity_x`=6 / `velocity_y`=7(normalized, as `Detection`), `displacement_x`=8 / `displacement_y`=9(box-centre delta since the previous update, normalized), `motion_compensated`=10(bool; a non-identity ego-motion transform was applied).
- `Belief`: `confidence_raw`=1(this frame's own detector confidence), `confidence_smoothed`=2(EMA across this identity's observations), `existence`=3(`[0,1]` from hits/misses — survives a frame with no detection), `since_confirmed_ms`=4(since the last DETECTOR confirmation, not since birth).
- `Provenance`: `source`=1(`EvidenceSource`), `contributors`=2(repeated string, contributor ids that made a claim about this object on this frame — the ledger's own attribution, summarised), `assoc_cost`=3(the matched pair's total cost; 0 when nothing matched), `reupdated`=4(bool; ORU reconstructed this track's gap this frame).
- `Memory`: `recovered`=1(bool; this frame re-acquired the identity from the gallery), `identity_confidence`=2(the match score that justified it), `dormant_ms`=3(how long it had been dormant — for a DORMANT object, still is), `gallery_matches`=4(dormant identities considered before this answer), `match_distance`=5(best appearance distance across the gallery, `[0,1]`).
- `Lock`: `locked`=1(bool), `lock_seq_applied`=2(int64, the lock generation actually in force) — frame-level `locked_track_id` says *which*; this says so on the object itself, the only form a renderer can use without a second lookup.
- `Timing`: `first_seen_ms`=1, `last_seen_ms`=2, `last_confirmed_ms`=3, `age_frames`=4, `hits`=5, `misses`=6 — the three `*_ms` instants share `DetectionResponse.timestamp_millis`'s timebase (cv-service ages tracks on a local monotonic clock and rebases once, at the wire, onto the frame's own reported capture instant — compare against `timestamp_millis`, never the reader's wall clock); `horizon_ms`/`since_confirmed_ms`/`dormant_ms` elsewhere are timebase-free.

`ObjectLifecycle.DORMANT` is the state today's non-mirror wire can never report on its own: a retired identity still held in the per-stream gallery and still recoverable under its own number. `EvidenceSource` is a superset of `DetectionSource` in meaning but a separate enum in fact (`PREDICTED` = a pure coast with no observation at all, `MEMORY` = a re-acquisition from the dormant gallery, `REUPDATE` = a box ORU reconstructed from the track's own bracketing observations) — no existing enum ever gains a value for this, see Conventions.

### `Detector` service — stateless detector/tracker split

A detector instance holds no identity, no gallery, no lock and no session — it turns pixels into boxes and says how busy it is, which is why it may be scaled to N instances behind an ordered target list while the tracker session stays sticky to one stream. Deliberately **not** a variant of `FrameRequest`: that message carries tracking config, camera pose and a stream-scoped contract a detector has no business seeing.

- **`DetectRequest`**: `stream_id`=1(accounting only — a detector instance never keys state on this; affinity lives in the caller's ordered target list, so two consecutive frames of one stream may legitimately be served by two different instances), `sequence`=2, `width`=3, `height`=4, `encoding`=5(`ImageEncoding`), `data`=6, `model_id`=7(the model **ref**, exactly as `FrameRequest.model_id` means it — comma-separated routes a composite), `model_version`=8(carried for symmetry, not resolved), `confidence_threshold`=9, `roi`=10(`BoundingBox`, optional — presence **is** the option: the ROI rescue crop, absent = full frame; the detector crops and maps boxes back to full-frame coordinates itself, so the caller sends one frame, never two).
- **`DetectResponse`**: `detections`=1(repeated `Detection`; track fields always unset — a detector has no identity), `inference_millis`=2, `model_id`=3(what actually served, may differ from what was asked), `occupancy`=4(passes inside the gate right now), `queue_depth`=5(waiting for a permit), `capacity`=6(the gate's permit count), `max_queue`=7(the bound above which this instance answers `RESOURCE_EXHAUSTED`) — admission facts on **every** response, since the fleet budget is the sum of what instances report, not a shared token.

### Visual geolocation

Pull-only, same doctrine as `DetectPulled`: the worker dials the video source itself; there is no frame payload on this wire, in either direction.

- **`GeoTelemetry`** — everything the rectifier and the priors need, restated on every `GeoControl` message; every field `optional` except `sample_millis`: `latitude`=1 / `longitude`=2(WGS-84 degrees), `amsl_meters`=3(mirrors `Telemetry.altitudeMeters`), `agl_meters`=4(mirrors `Telemetry.aglMeters`), `heading_degrees`=5(clockwise from true north, `[0,360)`), `groundspeed_mps`=6, `camera_pitch_deg`=7 / `camera_roll_deg`=8 / `camera_yaw_deg`=9(`rectify.py`'s **degrees-from-nadir** convention — converted from `Attitude`'s positive-up gimbal pitch exactly once, at the Java codec), `horizontal_fov_deg`=10(0/absent = the region's assumed default), `sample_millis`=11(int64, epoch millis of this telemetry sample — not `optional`), `gps_radius_meters`=12(the raw fix's own 1-sigma, from HDOP when known).
- **`GeoPrior`**: `latitude`=1, `longitude`=2, `radius_meters`=3(>0) — restricts retrieval to a disc around where the station already believes the aircraft is.
- **`GeoControl`** — declarative per-session desired state, restated on **every** message, same doctrine as `PullControl`/`TrackingConfig`: `stream_id`=1(also the mediamtx path name), `source_url`=2 / `rtsp_transport`=3(both read from the **first** message only), `region_id`=4(""=search every `READY` region), `target_fps`=5(keyframe rate; <=0=default), `telemetry`=6(optional `GeoTelemetry`, hot), `prior`=7(optional `GeoPrior`, hot), `stop`=8(bool; requests a clean drain + half-close).
- **`GeoEvidence`** — why the worker believes (or refuses) a fix, logged and served verbatim so an operator can always see *why*, not just *what*: `candidate_count`=1(top-k actually re-ranked), `match_count`=2(correspondences on the winning candidate), `inlier_count`=3(MAGSAC inliers — the promotion gate), `inlier_ratio`=4, `rerank_margin`=5(`(s1-s2)/max(s1,1)` over inlier scores), `reprojection_rms_px`=6(homography residual — the ceiling applies at every N), `rectified`=7(bool; IPM actually applied, false = degraded to raw frame), `cell_calibrated`=8(bool; the winning cell has a real accept threshold, not never-accept), `supporting_frames`=9(distinct frames whose own inliers cleared the floor), `baseline_meters`=10(platform motion spanned by those frames), `sequence_converged`=11(bool), `sequence_spread_meters`=12, `sequence_updates`=13, `osm_prior`=14(the tie-breaker multiplier; `1.0`=inert).
- **`GeoFix`** — one localization result. A `GeoFix` without `latitude`/`longitude` is never a `(0,0)` position — absence is absence; `refusal` is `""` only on `GEO_STATUS_FIX`: `stream_id`=1, `sequence`=2(monotonically increasing per session), `frame_millis`=3(the frame's own `CaptureClock` capture time), `status`=4(`GeoStatus`), `region_id`=5(the region actually searched, ""=none), `tile_id`=6(`"<z>/<x>/<y>"` of the winning cell, for diagnostics), `latitude`=7 / `longitude`=8(optional, present iff `status==GEO_STATUS_FIX`), `yaw_degrees`=9(optional; camera image-up bearing, present only when the homography passed sanity), `radius_meters`=10(optional, 1-sigma horizontal, always present with any position), `implied_agl_meters`=11(optional, from the homography scale — the D-AGL cross-check input), `evidence`=12(`GeoEvidence`), `refusal`=13(names the gate that refused), `telemetry_age_millis`=14(`frame_millis - telemetry.sample_millis`, signed, honest), `latency_millis`=15(worker-side compute cost for this frame).
- **`ReferencePackChunk`**: `region_id`=1(set on every chunk, identical throughout the stream), `content`=2(bytes) — concatenation in stream order is a ZIP of `region.json` + `tiles/<z>_<x>_<y>.jpg`.
- **`ReferenceIndexStats`**: `tile_count`=1, `descriptor_count`=2, `descriptor_dim`=3, `encoder_id`=4, `accept_similarity`=5 / `accept_margin`=6(self-calibrated on held-out tiles), `holdout_recall_at_1`=7, `holdout_median_error_meters`=8, `index_bytes`=9, `never_accept_cells`=10(cells the calibration refuses outright).
- **`ReferenceIndexProgress`**: `region_id`=1, `phase`=2(string: `"receiving"|"extracting"|"encoding"|"indexing"|"calibrating"|"done"`), `done`=3, `total`=4(0 when the phase has no countable unit), `state`=5(`JobState`, reused), `message`=6, `stats`=7(optional `ReferenceIndexStats`, present only on the terminal `SUCCEEDED` event).
- **`RegionRef`**: `region_id`=1. **`RegionInfo`**: `region_id`=1, `name`=2, `zoom`=3, `stats`=4(`ReferenceIndexStats`), `built_at_millis`=5, `north`=6 / `south`=7 / `east`=8 / `west`=9. **`RegionList`**: `regions`=1(repeated `RegionInfo`).

### Deprecated fields

## Conventions

- `protoSourceRoot` points at `../../proto` (repo-root `proto/vision/v1/cv.proto`) — **not** a copy under this module; it is the single source of truth shared with `cv-service`'s Python codegen (`scripts/gen_proto.sh`). Never duplicate or fork the `.proto` file: both ends must agree, and they do so by generating from the identical file.
- Codegen via `org.xolstice.maven.plugins:protobuf-maven-plugin` (`${protobuf-maven-plugin.version}`=0.6.1), goals `compile` + `compile-custom` at the `generate-sources` phase (the latter drives the `grpc-java` plugin, `pluginId=grpc-java`). `os-maven-plugin` (`${os-maven-plugin.version}`=1.7.1) resolves `${os.detected.classifier}` to pick the right native `protoc`/`protoc-gen-grpc-java` executables.
- Version pins (root `pom.xml` properties): `protobuf.version`=3.25.5 (both `protoc` and `protobuf-java`), `grpc.version`=1.64.0.
- **Field-number allocation is additive-only** — never reuse or renumber a field once shipped, even a dead one (deprecate by comment instead, see Deprecated fields above). Before allocating the next number in a message, verify the existing field list is contiguous with no gaps by reading the `.proto` itself, not by trusting a plan document's stated number — small ranges are sometimes left deliberately reserved for a named future field (e.g. `Detection` 12–13, `TrackingConfig` 12–13); check those before assuming the next number is free.
- **No existing enum ever gains a new value.** `cv/grpc`'s `DetectionFrameCodec` maps `TrackState`/`DetectionSource`/`DetectorReason` with exhaustive Java switch *expressions* that have no `default` branch, so a new value breaks the compile of every Java build, and an already-deployed codec decodes an unknown value as `UNRECOGNIZED` and nulls the whole track reference. A new meaning arrives as a **new enum used only by new messages** (e.g. `ObjectLifecycle`/`EvidenceSource` beside `TrackState`/`DetectionSource`). Every new enum's `0` value is its own `*_UNSPECIFIED` — old client / old server / "this feature never touched this message" all read the same way: the zero value.
- A wholly new message/RPC gets its own `// ---- <plan> wave <id> ----` banner ahead of it in the `.proto`; a widened pre-existing message stays filed under the CHANGED-messages banner it already had.
- `src/test/java/com/drones/vision/proto/v1/TrackingProtoAdditivityTest.java` is the **one** hand-written source in this module. It makes proto3's additive guarantee a checked fact rather than a claim: each "expected" byte payload is built field-by-field with the raw protobuf wire format (`CodedOutputStream`, tag = `(fieldNumber << 3) | wireType`), independent of the generated classes' own serialization, covering `FrameRequest`, `Detection`, `DetectionResponse` and `PullControl` as they existed before their own widening waves, plus one round-trip case that the newer fields decode correctly once populated.
- `cv/cv-service/scripts/gen_proto.sh` regenerates the Python side (`cv/cv-service/cv_service/gen/`, gitignored) from the same `.proto` — never commit its output, never hand-edit it.

## Gotchas

- Regenerate by rebuilding this module (any goal that runs `generate-sources`, e.g. `./mvnw -pl cv/vision-proto compile`) — nothing under `target/generated-sources` is hand-maintained; never edit generated files directly.
- Java's protobuf runtime stays on the `3.25.x` version line while Python's (`cv/cv-service/pyproject.toml`) pins `protobuf>=5.26.1,<6` — different-looking major versions for the **same** underlying release generation (protobuf unified its cross-language version numbering; Java/C++ kept the legacy `3.25.x` line for that generation while Python jumped to `5.26.x`). Not a real skew, and not something to "fix" — both consume the same `.proto` and produce the same wire format.
- proto3's explicit `optional` keyword on a scalar field (`GeoTelemetry`'s fields, `GeoControl.telemetry`/`.prior`, `GeoFix`'s position fields, `ReferenceIndexProgress.stats`) is required for a `hasXxx()` accessor to exist at all — a message-typed field gets presence for free (e.g. `TrackingConfig.lock`, `PullControl.camera_pose`), a scalar does not without the keyword. protoc 3.25.5 (this repo's pin) treats it as stable; no `--experimental_allow_proto3_optional` flag needed.
- `JobState`'s values are named `RUNNING`/`SUCCEEDED`/`FAILED` with no `JOB_STATE_` prefix (only `JOB_STATE_UNSPECIFIED` gets one) — inconsistent with every other enum in this file, and not worth "fixing" since renaming a wire enum value breaks the wire.
- `cv/cv-service/scripts/gen_proto.sh` invokes the bare `python` on `$PATH`, not `.venv/bin/python` — on a host where the venv isn't activated first, it fails with "grpc_tools (grpcio-tools) is not installed" even though the venv has it. `source .venv/bin/activate` before running it, or call `.venv/bin/python -m grpc_tools.protoc` directly with the same `-I`/`--python_out`/`--grpc_python_out`/`--pyi_out` flags.
- `junit-jupiter` (test scope) has no explicit version pin in `pom.xml` — it comes from the `spring-boot-starter-parent` BOM, same as every other module.
