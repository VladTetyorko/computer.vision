M0 spike -- mediamtx Control API (v3) transcript against bluenviron/mediamtx:1.19.3
=====================================================================================
Container: throwaway `mtx-spike`, NOT the product docker-compose mediamtx service.
  docker run -d --rm --name mtx-spike \
    -v <this-dir>/mediamtx-spike.yml:/mediamtx.yml:ro \
    -p 18554:8554 -p 9997:9997 -p 8000-8001:8000-8001/udp \
    bluenviron/mediamtx:1.19.3
Host ports 18554/9997 used instead of 8554/9997 because the product's own
`vision-mediamtx-1` container (docker-compose.yml) already holds 8554 on this host.
mediamtx-spike.yml is the DEFAULT baked-in config with two deliberate overrides -- see
CV-PULL-SPIKE.md's "Contract correction: Control API auth" for why they were necessary.

---------------------------------------------------------------------------------------
0. Auth gate encountered BEFORE any of the calls below worked (first attempt, default
   config, MTX_API=yes only):

$ curl -s -w "\nHTTP_STATUS:%{http_code}\n" http://localhost:9997/v3/paths/get/testpath
{"status":"error","error":"authentication error"}
HTTP_STATUS:401

Fixed by mounting a custom mediamtx.yml widening the API/metrics/pprof `any` user's
`ips` from the default `["127.0.0.1","::1"]` to `[]` (any IP) -- see transcript file
mediamtx-spike.yml alongside this one. Confirmed this is genuinely an IP-source check,
not a credentials check: the default "any" user has no password either way.

2. Create path (POST /v3/config/paths/add/{name}):

$ curl -s -w "\nHTTP_STATUS:%{http_code}\n" -X POST http://localhost:9997/v3/config/paths/add/testpath \

Verdict: §5.3's three calls and its documented 400/404 idempotency assumptions are all
CONFIRMED against 1.19.3, verbatim -- see items 2/4 (400 "path already exists") and
6/7/8/9 (404 "path not found"). The one thing §5.3 did NOT anticipate is item 0: the
Control API is IP-gated by mediamtx's own DEFAULT config (not a mediamtx bug), and every
one of these calls 401s until that is addressed. See CV-PULL-SPIKE.md for the correction
this implies for wave M7/M6 (docker-compose.yml + MediamtxControlApi).
