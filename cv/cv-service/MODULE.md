# cv-service

Python gRPC CV service: real-time YOLO detection with a per-track detect-then-track duty cycle, model training/promotion, and visual geolocation — three gRPC services (`Inference`, `Training`, `Geolocation`) defined in `proto/vision/v1/cv.proto`. Falls back to an echo response when no model is loaded, so the service never crash-loops for lack of a model.

**Depends on:** grpcio, grpcio-tools, protobuf; `cv` extra (ultralytics — pulls in torch transitively; `opencv-python>=5.0,<6`, `lap>=0.5.12`, both pinned — see Gotchas); `geo` extra (torch/torchvision/kornia, self-referential on `cv`) adds visual geolocation. Invariant: nothing x86- or CUDA-only may ever enter `cv`/`geo` (this is what keeps the same package deployable to a companion computer). Shared contract: `proto/vision/v1/cv.proto`. · **Used by:** `adapter-cv-grpc` (`cv/grpc/`) — wires `PipelineConfig.model` to `FrameRequest.model_id`; see `cv/grpc/MODULE.md`.
**Build/test:** `python -m cv_service.grpc.server` (run, role=all). `scripts/test.sh` / `python -m pytest` (needs `pip install -e '.[dev]'`; `-e '.[cv,dev]'` for the mock+real-model suites; `-e '.[geo,dev]'` for `tests/geo/**`). Codegen: `scripts/gen_proto.sh` → `cv_service/gen/` (gitignored — regenerate after cloning or after a proto change). Remote/GPU deploy runbook: `cv/cv-service/DEPLOY-GPU.md`.

## API surface

### gRPC services (`proto/vision/v1/cv.proto`)

| Service | RPC | Shape |
|---|---|---|
| `Inference` | `DetectStream` | bidi, push — client streams frame bytes, server streams `DetectionResponse` |
| `Inference` | `DetectPulled` | bidi, pull — client streams `PullControl` (declares a source URL), server dials it itself and streams `DetectionResponse` |
| `Inference` | `Inspect` | unary — read-only debug surface: process facts, one session's facts, and its last N per-frame ledgers. Off the detection path entirely (CV-ORCHESTRATION W0) |
| `Detector` | `Detect` | unary — one frame in, boxes out, plus how busy the answering instance is. Stateless: no session, no identity, no lock. Served only by a `detector`/`all` role process (CV-ORCHESTRATION W4) |
| `Training` | `StartTraining` | unary → stream — fine-tunes a model, streams `TrainingProgress` |
| `Training` | `UploadDataset` | client-stream → unary — lands an exported-YOLO dataset zip |
| `Training` | `ListModels` / `PromoteModel` | roster query / re-point the serving default |
| `Geolocation` | `LocalizeStream` | bidi, pull-only — dials a source itself, streams `GeoFix` |
| `Geolocation` | `BuildReferenceIndex` | client-stream → stream — lands a reference-pack zip, builds a searchable index |
| `Geolocation` | `ListRegions` / `DeleteRegion` | region management |

### Process roles & running (`cv_service/grpc/server.py`, `config.py`)

`Settings.role` / `CV_SERVICE_ROLE` (`all` default | `inference` | `training` | `detector` | `tracker`) controls which servicers `serve()` registers, so a long-running Training/Geolocation job can never share a process (or GIL) with `Inference`'s ~50ms-budget hot path (`docs/plans/active/ARCHITECTURE-AUDIT-2026-08-26.md` R6). `"all"` registers everything (byte-identical to before the split existed). `"inference"`/`"tracker"` register `Inference` only. `"training"` registers `Training`+`Geolocation` only. `"detector"` registers `Detector` only. `ModelRegistry` is always built regardless of role.

| Role | Serves | Holds | Scales |
|---|---|---|---|
| `all` | `Inference` + `Training` + `Geolocation` + `Detector` | everything | the default single box |
| `inference` | `Inference` | sessions + the model | as `all`, minus training |
| `tracker` | `Inference` | sessions; the model only if `CV_DETECTOR_TARGETS` is unset | **one instance per stream** (sticky) |
| `detector` | `Detector` | the model, nothing else | **N instances**, any may serve any frame |
| `training` | `Training` + `Geolocation` | jobs, the region index | one |

`tracker` is `inference` with the detector placed elsewhere: it is the SAME servicer and the same wire, and the only difference is that `CV_DETECTOR_TARGETS` makes `orchestration/detector.py` hand each pass to a pooled `Detector` instead of the in-process gate. `inference` keeps meaning exactly what it meant before W4 (everything but training), which is why the two are separate names for the same registration — the role is what an operator declares they INTENDED, and `Inspect` reports it back (`ProcessFacts.role`).

- `python -m cv_service.grpc.server` — role from env, default `all`.
- `python -m cv_service.grpc.server_inference` / `server_training` — thin entrypoints that default `CV_SERVICE_ROLE` before delegating to the same `main()` (an explicit env var still wins).
- **Docker Compose**: the default `cv-service` service runs combined on host port `50051`, always on. The opt-in `cv-split` profile adds `cv-service-inference` (host port **50061**) and `cv-service-training` (host port **50062**) — same image, `command:` override only. `docker compose up -d --scale cv-service=0 --profile cv-split cv-service-inference cv-service-training`.
- **Java side reaches split targets via `vision.cv.inference.targets`** (ordered `host:port` list, default empty → falls back to `vision.cv.endpoint`'s host/port) **and `vision.cv.training.target`** (single `host:port`, default `""` → same fallback) — both empty by default, so a single-process deployment is unaffected. Failover across `inference.targets` is grpc's own `pick_first` policy on one channel (`cv/grpc`'s `CvChannels.forTargets`/`CvTarget`); no load-balancing logic of this repo's own was written. Full detail: `cv/grpc/MODULE.md`.
- **Known limitation of a split deployment**: `ModelRegistry` is in-memory per process. `PromoteModel` (handled by the training process) persists the new active-model marker to disk but does not propagate it live into an already-running separate inference process — only that process's next restart (which re-reads the marker) picks it up. The combined `"all"` process updates in-process, immediately.
- **Healthcheck**: a plain TCP connect to `localhost:50051` inside the container (no grpc-health-checking tool in the image) — protocol-agnostic, identical across all three deployment shapes.

### `cv_service/config.py`

`Settings` (frozen dataclass) is the **one place** every `CV_*` env var is read. `Settings.from_env()` re-parses `os.environ` fresh on every call (no import-time caching) and is threaded down explicitly from `serve()`; a module constructible standalone (`YoloDetector`, `ultralytics_train`) calls `Settings.from_env()` itself when a value isn't supplied. All parsing is forgiving — unset/garbage falls back to the default, never raises.

### `cv_service/inference/`

- **`concurrency.py`** — pure stdlib. `LatestOnlyMailbox[T]`: single-slot, latest-wins handoff between one producer/one consumer thread; `put()` never blocks (silently replaces an unconsumed value, `.dropped` counts it), `get()` blocks until a value or `close()`. `InferenceGate(max_concurrent)`: a `threading.Semaphore` wrapped as a context manager, gating how many stream-consumer threads may be inside `detect()` at once (not a thread pool). `process_gate() -> InferenceGate` — the lazily-built process-wide gate a bare `InferenceServicer()` falls back to; production always builds and passes one explicitly.
- **`detector.py`** — independent of generated protobuf stubs. `ENCODING_JPEG`/`ENCODING_BGR24: str` (match `ImageEncoding` enum names). `DEFAULT_MODEL="yolo26n.pt"`, `DEFAULT_IMGSZ=416`, `DEFAULT_CONFIDENCE=0.25`. `ModelUnavailableError(RuntimeError)`. `Detection(label, confidence, x, y, width, height)` — normalized `[0,1]`, `x`/`y` top-left. `decode_frame(width, height, encoding, data) -> np.ndarray`. `map_detections(result, frame_width, frame_height) -> list[Detection]`. `YoloDetector(model_name=None, *, model=None, device=None)` — loads once, `model=` injects a test double; `.detect(*, width, height, encoding, data, confidence_threshold=None) -> (list[Detection], inference_millis)`; runs one warmup `predict()` at construction (a warmup failure raises `ModelUnavailableError`, same as a load failure).
- **`registry.py`** (needs the `cv` extra) — `discover_roster(base_dir, default_model) -> dict[model_id, path]` (scans for `*.pt` + `*_openvino_model`, one level, always includes `default_model`). `short_name(model_id)`. `ModelRegistry(roster, default_id, *, detector_factory=YoloDetector)` — lazy `{model_id -> YoloDetector}`; `.resolve(requested_model_id) -> list[(id, YoloDetector)]` (comma-separated composite; drops unknown/failed ids, falls back to the default only when nothing resolved). `detect_composite(resolved, *, gate, ...) -> (detections, inference_millis)` — every member runs through the same `InferenceGate`, concatenated, `inference_millis` summed; when more than one model ran, every label is prefixed `"{short_name}:{label}"`. `build_default_registry(settings) -> ModelRegistry | None` — discovers the roster, applies a persisted promotion from `training.marker.read_active_model`, eagerly loads the default.

### `cv_service/training/`

- **`dataset.py`** — stdlib-only. `DATASET_DIRNAME`, `DATA_YAML_NAME`/`IMAGES_DIRNAME`/`LABELS_DIRNAME` (the exported-YOLO layout contract). `DatasetNotFoundError`. `resolve_dataset_dir(datasets_root, dataset_id) -> Path`. `sanitize_dataset_id`/`is_safe_dataset_id`/`is_safe_zip_entry` (zip-slip guards). `UploadOutcome(ok, message, dataset_id="", bytes_received=0, file_count=0)`. `land_dataset(zip_path, datasets_root, dataset_id, bytes_received) -> UploadOutcome` — validates, extracts to a sibling temp dir, atomically replaces `<datasets_root>/<dataset_id>/`; every failure past the streaming stage is a reported `ok=False`, never raised.
- **`trainer.py`** — stdlib at import scope; `ultralytics` import is lazy inside `ultralytics_train`. `DEFAULT_EPOCHS=50`, `DEFAULT_BASE_MODEL="yolo26n.pt"`. `TrainingSpec(job_id, base_model, dataset_id, epochs, dataset_dir, data_yaml, output_dir)`. `EpochProgress(epoch, total_epochs, loss, map50)`. `TrainingCancelled(Exception)`. `build_spec(*, job_id, base_model, dataset_id, epochs, datasets_root, output_dir) -> TrainingSpec`. `output_model_id(dataset_id, epochs) -> str` — `<dataset_id>-<epochs>e.pt`, deterministic. `TrainFn = Callable[..., Path]`; default `ultralytics_train(spec, *, on_epoch, is_cancelled) -> Path` — device auto via `Settings.from_env()` (never hard-pinned CPU), suppresses Ultralytics' one trailing post-training validation callback (see Gotchas), returns `best.pt`.
- **`marker.py`** — stdlib (`json`). `ACTIVE_MODEL_MARKER="active_model.json"` (under `Settings.model_dir`, gitignored). `read_active_model(model_dir) -> str | None` (forgiving), `write_active_model(model_dir, model_id, version="")`. `build_default_registry()` reads it at startup to seed the default id — this is what makes a promotion survive an rsync-deploy restart.
- **`orchestrator.py`** — never imports `cv_pb2`/`grpc`. `JobEvent(kind, epoch=0, total_epochs=0, loss=0.0, map50=0.0, message="", model_id="")` — `kind` is `"running"` (one per epoch) or terminal `"succeeded"`/`"failed"`; a cancelled job yields no terminal event at all. `run_training_job(spec, *, job_id, train_fn, is_context_active, register_cancel_callback, publish_artifact) -> Iterator[JobEvent]` — runs `train_fn` on a background worker thread, the generator only polls a queue and yields, staying responsive to cancellation.

### `cv_service/tracking/` — the detect-then-track duty cycle

> Since CV-ORCHESTRATION wave W0 the per-frame CHAIN lives in `cv_service/orchestration/` (next section). What stays here is the vocabulary that chain is written in: params, policy, identity, geometry, engines.

Pure stdlib except `engines/{bytetrack,lk,ncc}.py` (need `numpy`/`ultralytics`) and `engines/{flow_gmc,histogram}.py` (need `cv2`) — everything else, including `engines/base.py`, is importable/testable with no `cv` extra at all, which is what keeps `python -m cv_service.grpc.server` runnable in echo mode and the scheduler/lifecycle/session tests running against a fake clock with no frames. No module here imports `cv_pb2`.

| Mode | Every received frame | Detector pass when |
|---|---|---|
| `OFF` (default) | — | every frame. **Byte-identical to no tracking at all** — no tracking fields set on the wire |
| `ASSOCIATE` | associate the detector's boxes to existing tracks | every frame (cv-service only ever receives already-sampled frames) |
| `FOLLOW` | `engine.update(frame)` on the locked target | cadence elapsed (`verify_every_millis`) · tracker reported lost/low-confidence · no lock held (on `reacquire_millis` cadence) · predicted box collapsed/left frame · coasted past `max_age_frames`/`max_age_millis` |

- **`params.py`** — `MODE_OFF`/`MODE_ASSOCIATE`/`MODE_FOLLOW`/`MODE_UNSPECIFIED`. `TrackingRequest`/`LockRequest` — plain, sentinel-preserving counterparts of the wire `TrackingConfig`/`TargetLock`. `TrackingParams(mode, engine_id, verify_every_millis, redetect_iou_threshold, max_age_frames, min_hits, track_max_age_millis, min_tracker_confidence, motion_engine_id, appearance_engine_id, cost_weights, cost_gates, memory_params, follow_top_k, roi_enabled, roi_crop_factor, capability_level, reupdate_max_gap_millis, reupdate_max_velocity_per_second, reupdate_max_track_count, ...)` + `.active`/`.effective_reacquire_millis`. `resolve(request, settings) -> TrackingParams` — the only place a `<=0` wire sentinel becomes a number; `motion_engine_id`/`appearance_engine_id` are the exception — resolved only as far as "which engine id", never to "does it actually serve", which needs live state only `session.py` has.
- **`levels.py`** — the capability ladder: `LEVEL_L1..LEVEL_L5` (`RELAY`/`FILL`/`DETECT`/`IDENTIFY`/`STUDY`), `MIN_LEVEL`/`MAX_LEVEL`. `probe() -> int` — the highest level *this host* affords, checked via `importlib.util.find_spec` only (never a real import): no `cv2`+`numpy` → L1; no `ultralytics`+`torch` → L2; below a 512 MiB available-memory floor → L2; no `openvino` → L3; else L4. Never caches. Never auto-selects L5 (reachable only by an explicit request, capped by what `probe()` found). `resolve(requested, probed) -> (served, reason)` — `requested<=0` auto-probes; a positive `requested` is a ceiling, `min(requested, probed)`.
- **`scheduler.py`** — `REASON_*` (match `cv_pb2.DetectorReason`). `Decision(run_detector, reason)`. `SchedulerState(mode, has_lock, last_detector_millis, tracker_failed, box_invalid, coasting_frames)`. `DutyCycleScheduler(params).decide(now_millis, state) -> Decision` / `.retune(params)` — pure policy, no literal thresholds live in this file. In FOLLOW, triggers are evaluated most-specific-first and fire only on a tracker-only frame (never re-raised on the verify frame that already answered them — see Gotchas).
- **`track.py`** — `STATE_*` (match `cv_pb2.TrackState`). `Track(track_id, key, box, label, confidence, first_seen, last_seen, last_confirmed, state, source, velocity_x, velocity_y, age_frames, hits, misses, descriptor, history, history_transform, reupdated)`. `RecoveredIdentity(track_id, first_seen, descriptor=None, velocity=(0.0,0.0))`. `TrackBook(params, *, memory=None)`: `.apply(observations, now, *, detector_ran, recoveries=None) -> list[Track]` (books, ages, settles, expires — **must be called exactly once per `process()` call**, see Gotchas), `.tracks`, `.get(track_id)`, `.retune(params)`, `.bump_epoch()` (namespaces future engine keys without retiring live tracks), `.forget_keys()` (a genuine wipe — tracking OFF only), `.warp(transform)` (moves every live track's stored `box`/`velocity_*` through `transform`, once per frame, before anything reads one), `.last_reupdate_millis`/`.last_reupdated_tracks`/`.reset_reupdate_stats()`. Module-level `observe_descriptor(track, descriptor, *, alpha=...)` — EMAs the appearance signature from detector evidence only.
- **`history.py`** — `TimedObservation(timestamp, observation)`. `ObservationRing(capacity=16)`: `.record(observation, now)` (a no-op unless `source==SOURCE_DETECTOR and not predicted` — the ring itself decides, not callers), `.latest()`, `.before(timestamp)` (last real observation strictly before it — ORU's t₁), `.span(frames)`, `__len__`. Bounded by construction (`deque(maxlen=capacity)`).
- **`reupdate.py`** — ORU (Observation-Centric Re-Update). `Reupdate(steps, gap_millis, drift_before, drift_after, velocity_x, velocity_y)`. `reupdate(track, ring, observation, now, *, max_gap_millis, max_velocity_per_second=0.0, max_track_count=0, live_track_count=0) -> Reupdate | None` — reconstructs a track's true position across a coasted gap from its own bracketing real observations (warped through `track.history_transform`); refuses (never clamps) when the gap has no bracket, is too long, implies implausible velocity, or the scene is too dense. `late_correction(...)` — the FOLLOW/detection-lag counterpart, calls `reupdate()` internally so both guards cover it too.
- **`lock.py`** — `LockTarget(track_id, point, box)`. `LockArbiter`: `.apply(LockRequest|None) -> bool` (strictly-greater `lock_seq` only), `.bind`/`.unbind`/`.drop`, `.target`/`.bound_track_id`/`.generation`/`.applied_seq`. Plus `select_by_point(boxes, x, y)` and `best_iou_match(box, candidates, min_iou)`.
- **`assign.py`** — the `cost` associator's cost-matrix engine, pure stdlib, property-tested against brute force. `Candidate(key, box, label, descriptor, confirmed)`. `Target(box, label, confidence, descriptor, det_index)`. `Assignment(matches, unmatched_candidates, unmatched_targets)`. `AssignWeights(iou=1.0, appearance=0.0, label=0.0)` / `AssignGates(min_iou=0.0, max_appearance=1.0, max_cost=FORBIDDEN, high_confidence=0.0)`. `CostAssociator`: `engine_id="cost"`, `.cost(candidate, target)`, `.assign(candidates, targets) -> Assignment` (two-stage high/low confidence, ByteTrack's own idea kept), `.retune(*, weights, gates)`. `hungarian(cost) -> list[(row, col)]` — O(n³), pure stdlib, `FORBIDDEN` pairs never returned.
- **`memory.py`** — the dormant gallery. `MemoryParams`, `ObjectMemory`: `.remember`/`.match`/`.match_identity`/`.forget_expired`/`.claim`/`.size`/`.identities`/`.clear`/`.retune`. Four required match gates: label, appearance, motion plausibility, TTL. `.match` (whole-gallery search, ASSOCIATE's unmatched-target recovery) and `.match_identity` (one specific dormant id, FOLLOW's targeted re-acquire) are deliberately separate methods.
- **`registry.py`** — `BUILTIN_ASSOCIATORS={"cost"}` (`bytetrack` retired in CV-ORCHESTRATION W4, decision E16 — see Status), `BUILTIN_FOLLOWERS={"lk","ncc"}`, `BUILTIN_COMPENSATORS={"flow","pose"}`, `BUILTIN_APPEARANCES={"histogram"}` (lazy-imported factories). `TrackerRegistry(*, associators, followers, compensators, appearances, default_*_id)`: `.probe() -> dict[str, list[str]]` (constructs every roster once, drops what raises, logs the surviving roster once at startup), `.associator(engine_id, *, max_age_frames, level=None)` / `.follower(...)` / `.compensator(engine_id, level=None)` / `.appearance(engine_id, level=None)` → `(serving_engine_id, engine) | None`, a **new instance per call**. `level=` filters the roster against a per-role minimum *before* any factory runs (what makes L1 provably `cv2`/`numpy`-free): `cost`/`pose` selectable from L1 (pure stdlib), `lk`/`ncc`/`flow`/`histogram` only from L2. `build_default_registry(settings, *, probe=True) -> TrackerRegistry` — never `None`.
- **`engines/`** — `base.py`: `SOURCE_DETECTOR`/`SOURCE_TRACKER`. `Box(x,y,width,height)` + `.center`/`.valid`/`.iou`/`.contains`. `Observation(key, box, label, confidence, source, det_index, authoritative)`. `TrackerUpdate(box, confidence)`. `Associator`/`SingleObjectTracker` protocols. `CameraPose(yaw_degrees, pitch_degrees, roll_degrees, hfov_degrees, vfov_degrees, timestamp_millis)` + `.known`. `Transform(a,b,c,d,e,f)` — normalized-image affine, `.apply_point`/`.apply_box`/`.compose`; `IDENTITY`; **maps a point in the PREVIOUS frame to the CURRENT one** (direction is load-bearing, see Gotchas). `MotionCompensator` protocol. `METRIC_HELLINGER`/`METRIC_COSINE`. `Descriptor(engine_id, values, metric=METRIC_HELLINGER)` + `.distance`/`.blend`. `AppearanceExtractor` protocol. — `bytetrack.py`: `ByteTrackEngine` (Associator, adapts ultralytics' `BYTETracker`). — `lk.py`/`ncc.py`: `LkFlowEngine`/`NccEngine` (SingleObjectTracker); `init()` returns `False` (never raises) for an untrackable target; `lk` rejects corners via forward-backward optical-flow round trip and re-seeds once the surviving set thins past half. — `flow_gmc.py`: `FlowMotionCompensator` — sparse optical flow + RANSAC affine over the *whole* frame (unmasked, deliberately — see Gotchas), refuses (`IDENTITY`) on too few points, a failed fit, low inlier ratio, or a non-similarity fit. — `pose_gmc.py`: `PoseMotionCompensator` — pure trigonometry from `CameraPose`, no pixels; refuses on no/stale/implausible pose. — `histogram.py`: `HistogramAppearanceExtractor` — coarse joint H×S colour histogram (value/brightness dropped deliberately), stateless across frames.
- **`outcome.py`** — `TrackedBox(label, confidence, box, track, identity_confidence=0.0, dormant_millis=0)` (`track is None` = untracked). `FrameOutcome(boxes, inference_millis, detector_ran, detector_reason, tracker_millis, engine_id, locked_track_id, motion_millis, motion_engine_id, reupdate_millis=0, reupdated_tracks=0, capability_level_served, capability_level_reason, detection_lag_millis, detector_roi)`. Split out of `session.py` in W0 and re-exported from it, so every `from cv_service.tracking.session import FrameOutcome, TrackedBox` still works.
- **`session.py`** — **composition only, 400 lines** (2 362 before W0). `StreamTrackingSession(*, settings, registry_provider)`: `.active`/`.params`/`.tracks`/`.applied_wire_config`/`.stream_id`, `.apply_config(TrackingRequest, wire_token)` (on change only), `.process(*, now_millis, detect, frame, pose=CameraPose(), detection_lag_millis=0, dropped_frames=0, trace=False, frame_width=0, frame_height=0) -> FrameOutcome`, `.ledgers` (the `LedgerRing`), `.facts() -> SessionFacts`, `.declarations()`, `.reset_for_reconnect()`. `process()` does exactly five things: resolve the lazily-built collaborators, ask `BudgetPolicy` who may run, seed the frame's GIVEN facts onto a `FrameContext`, run the orchestrator, and turn what the aggregator produced into a `FrameOutcome`. `detect`/`frame` are callables the servicer supplies — this class holds no `InferenceGate` reference and structurally cannot acquire one. `trace`/`frame_width`/`frame_height` (CV-ORCHESTRATION wave W5b, plan §8 E23) — when `trace` is true, read `Key.DETECTIONS` off `ctx` right after the orchestrator run and stamp it plus the frame size onto the returned ledger's `detections`/`frame_width`/`frame_height`; `False`/`0` (every pre-W5b caller) leaves them `()`/`0`. Mirrors `grpc/servicers.py`'s own `request.trace` wire-attachment gate rather than adding a second flag.

### `cv_service/orchestration/` — the per-frame chain, as contributors (`docs/plans/active/CV-ORCHESTRATION-PLAN.md` W0)

Pure stdlib, no `cv_pb2`, no `cv2`/`numpy` — the frame arrives as an opaque object from a memoized `frame()` callable only an engine ever unwraps. Every per-frame responsibility is a **contributor**: it declares what it reads and writes, the orchestrator derives the order from those declarations, and each turn produces one ledger row.

```
detect.full ─┬─ egomotion.* ─ predict.cv ─ appearance.* ─ assoc.cost ─ detect.roi ─ memory.gallery ─ propose.cost ─┬─ aggregate
             └─ egomotion.* ─ follow.<engine> ────────────────────────────────────────────────────────────────────┘
```

- **`keys.py`** — `Key`, the blackboard vocabulary: `FRAME`, `POSE`, `LOCK` (the three `SEEDED` given facts no contributor may declare as a write), `TRACKS_PREV`, `PREDICTIONS`, `TRANSFORM`, `DETECTIONS`, `DETECTIONS_ROI`, `DESCRIPTORS`, `ASSIGNMENT`, `RECOVERIES`, `FOLLOW_OBS`, `CORRECTIONS`, `OBSERVATIONS`. *(This doc named two of them wrong until CV-ORCHESTRATION W1 — there is no `MOTION` or `TRACKS_PRED`; they are `TRANSFORM` and `TRACKS_PREV`.)* `PREDICTIONS` carries whole `Prediction`s, not bare boxes, since W1: `Prediction.horizon_seconds` is knowable only before the fold.
- **`contract.py`** — `FrameContext` (`.seed`/`.put`/`.get`/`.has`, one writer per key, enforced). `Contribution(outcome, reason, summary, evidence)`; `skipped(reason)`. `OUTCOME_RAN`/`OUTCOME_SKIPPED`/`OUTCOME_FAILED` — the proto enum's own value names, so the wire mapping is `LedgerOutcome.Value(name)` with no table. `Contributor` Protocol: `id`, `family`, `reads`, `writes`, `phase`, `min_level`, `run(ctx) -> Contribution`.
- **`orchestrator.py`** — `Orchestrator(contributors)`: Kahn topological sort over reads→writes, tie-broken by phase (`PHASE_PRE` before `PHASE_TRACK`) then registration order; `.run(ctx, budget, ledger) -> tracker_millis`, `.declarations()`. A contributor the budget did not make eligible is SKIPPED with a reason; one that raises is FAILED and the frame continues. `tracker_millis` spans the `PHASE_TRACK` contributors only — the same span the pre-W0 code measured.
- **`budget.py`** — `BudgetPolicy(params)` wraps `DutyCycleScheduler`: `.decide(now_millis, BudgetState) -> FrameBudget(run_detector, detector_reason, eligible)`, `.retune(params)`. Eligibility is keyed by contributor **family**, never by id, so an engine-id change never silently drops a contributor out of the budget. `AGGREGATE` is unconditionally eligible: a frame that books nothing still has to say so.
- **`aggregator.py`** — the **sole writer of `Track` and the sole caller of `TrackBook.apply`**, at most once per frame. `Proposal(observations, captured_at, detector_ran, recoveries, fold, boxes, settle, summary)` — `fold=False` means "do not book" (a raw echo), distinct from "book an empty list", which is what ages a live track. `settle` is the proposer's post-fold callback (FOLLOW's bookkeeping rides on it).
- **`ledger.py`** — `ObjectEvidence(contributor_id, claim)`, `LedgerEntry(contributor_id, outcome, reason, cost_ms, summary)`, `FrameLedger` (+ `.record`/`.claim`/`.entry_for`), `LedgerRing(capacity)` (`deque(maxlen=…)`, `.last(n)`). `FrameLedger.detections: tuple[object, ...]` + `frame_width`/`frame_height: int` (CV-ORCHESTRATION wave W5b, plan §8 E23) — `detect.full`'s own raw boxes (duck-typed `label`/`confidence`/`x`/`y`/`width`/`height`, never the inference module's `Detection` type — this package stays `cv2`-free) and this frame's pixel size, populated by `session.process()` **only when asked to trace**; `()`/`0` otherwise. Never `detect.roi`'s rescue-pass boxes: that pass writes the distinct `Key.DETECTIONS_ROI`.
- **`facts.py`** — `SessionFacts` / `ProcessFacts` / `session_facts(...)`, `Inspect`'s cold-path answer. `session_facts` reads only ALREADY-resolved engines and the roster the session ALREADY built — a debug read that resolved an engine would be mutating a session in order to describe it.
- **`detector.py`** — where detections come from, and the **only door to `InferenceGate` in the whole package**, enforced by `tests/orchestration/test_gate_seam.py`, which greps every module under `orchestration/` for `acquire(`/`admit(` and for `cv_service.inference` and fails on any hit outside this file.
  - `DetectorClient` Protocol (`id`, `.bind(detect)`, `.detect(roi=None) -> DetectorPass`, `.passes`, `.wait_ms`); `DetectorPass(detections, inference_millis, wait_ms, roi, served_by, hops)`.
  - `LocalDetectorClient` (`id="local"`) — in-process, the default and every pre-W4 deployment unchanged.
  - `PoolDetectorClient(targets, *, local, health)` (`id="pool"`, W4) — tries the ordered `RemoteDetector` list first to last, moving on over `DetectorBusy` (refused: the fleet budget working) and `DetectorUnavailable` (did not answer: a fault), raising `NoDetectorAvailable` when the list is exhausted. Never silently queues and never silently falls back. `.health` is per-target `served`/`refused`/`failed`/`last_error` as OBSERVED (never a probe); `.served_by` is which target answered the last pass and `DetectorPass.hops` how many were tried before it.
  - `FramePayload` — this frame's pixels and model as plain values, carried by the servicer's per-frame callable on `.payload` (the `FrameDetect` Protocol). The local client never reads it, which is why every bare-lambda `detect()` double still satisfies the contract.
  - `RemoteDetector` Protocol (`.target`, `.detect(payload, roi)`) — its one production implementation is `grpc/detector_transport.py`; nothing under `orchestration/` imports `grpc` or `cv_pb2`.
- **`engines.py`** — `EngineSet`: every lazily-resolved collaborator (engine, motion compensator, appearance extractor, dormant gallery, capability level), the FOLLOW → ASSOCIATE → OFF degradation ladder, and `reconfigure(previous, params)` — the config-invalidation rules (which changed field releases which collaborator).
- **`state.py`** — `StreamState`: what survives a frame and has more than one reader (the held target, its extras, the scheduler triggers, this frame's lag, the per-frame cost counters).
- **`corrections.py`** — the ORU/late-correction seam `reupdate.py` is called through.
- **`mirror.py`** (W1) — `object_states(book, memory, lock, ctx, ledger, boxes) -> tuple[ObjectState, ...]`: the wire mirror, one entry per LIVE track then one per DORMANT identity, each set already id-ordered by its source. A **pure read** — it mutates no `Track`, book, gallery, lock, context or ledger, and `tests/orchestration/test_mirror.py` asserts that by deep-copy comparison. Called by `session.process()` AFTER the run, not by the aggregator (see Conventions).
- **`contributors/`** — `roster(...)` builds the list for the current configuration; `signature(engines)` is what a rebuild is keyed on. `detect.py` (`DetectFull` — the only contributor that HALTS a frame, for "no model resolved at all"), `egomotion.py`, `predict.py`, `appearance.py`, `associate.py` (`AssociateByteTrack`, `AssociateCost`, `ProposeCost`), `roi.py` (`RoiRescue`), `memory.py` (`MemoryGallery`), `follow.py` (`Follow`).

### `cv_service/grpc/`

- **`servicers.py`** — the **sole** module touching generated `cv_pb2` types; every other module works with plain Python values.
  - `InferenceServicer(cv_pb2_grpc.InferenceServicer)` — `__init__(detector=None, *, inference_gate=None, registry=None, settings=None, tracker_registry=None, pull_source_open=None)`. `detector=` pins one model regardless of `model_id`; omitted/`registry=` routes through `ModelRegistry.resolve`/`detect_composite` (composite `model_id` is comma-separated). `DetectStream(request_iterator, context)` — a background `_StreamReader` thread drains frames into a `LatestOnlyMailbox` so network receipt overlaps inference within a stream; every `detect()` call across all streams shares one process-wide `InferenceGate`; "no model" or any per-frame exception degrades to an echo response, never kills the stream. `DetectPulled(request_iterator, context)` — the pull counterpart: claims the first `PullControl` (must carry `source_url`), opens a `cv_service.pull.source.PullSource`, drives a `cv_service.pull.loop.PullDecodeLoop`, and feeds every served frame through the exact same `_handle_request`/`SessionRegistry`/`ModelRegistry`/`InferenceGate` machinery `DetectStream` uses.
  - `Inspect(request, context)` — empty `stream_id` → `ProcessFacts` + the live stream ids; a named one → `SessionFacts` + the last `frames` `FrameLedger`s (`frames<=0` = the whole ring), `found=false` when nobody is serving that id. Read-only and non-blocking by construction: `SessionRegistry.snapshot()` copies under its own lock, `session.facts()` resolves nothing, and the ledger ring is a bounded `deque`. Ledger→proto mapping (`_session_facts_message`/`_frame_ledger_message`/`_ledger_entry_message`/`_ledger_outcome`/`_traced_detection_message` — W5b) lives only here. `_frame_ledger_message` encodes `FrameLedger.detections`/`frame_width`/`frame_height` unconditionally off the domain object, so it is the same no-op it always was on every ledger the W5b `trace` gate left empty.
  - Tracking wire translation (module-level, lives only here): `_tracking_request_from_wire`/`_lock_request_from_wire`/`_tracking_mode_name`/`_camera_pose_from_wire`/`_tracked_detection`/`_tracked_response`/`_object_state_message`/`_bounding_box` (W1). `_handle_request` (W5b) passes `trace=request.trace, frame_width=request.width, frame_height=request.height` into `session.process()` — the same `request.trace` `_tracked_response` already gates the `response.ledger` wire attachment on, so a trace-off `DetectionResponse` is unaffected: the ledger itself is empty of the new fields before `_frame_ledger_message` ever runs. Proto enum values cross the boundary as their own value-name strings (`"TRACK_STATE_CONFIRMED"`, etc.) via `cv_pb2.X.Name()`/`.Value()` — no lookup table.
  - `TrainingServicer(cv_pb2_grpc.TrainingServicer)` — `__init__(*, registry=None, model_dir=None, dataset_dir=None, train_fn=None, max_upload_bytes=...)`, shares the same `ModelRegistry` instance `InferenceServicer` routes against. `ListModels`/`PromoteModel`/`StartTraining`/`UploadDataset` — see Gotchas for their reported-vs-aborted error semantics.
  - `GeolocationServicer` — implements all four `Geolocation` RPCs; the sole `cv_pb2` touchpoint for that service. Constructor DI (`encoder=`/`matcher_handle=`/`match_keypoints_fn=`/`pull_source_open=`) mirrors `InferenceServicer.detector=`, letting `tests/geo/**` exercise the pipeline with zero real torch/network dependency.
- **`detector_servicer.py`** (W4) — `DetectorServicer(cv_pb2_grpc.DetectorServicer)`, the stateless half of the split. `Detect(request, context)` takes `InferenceGate.admit(max_queue)` first: a queue already at `CV_DETECTOR_MAX_QUEUE` answers `RESOURCE_EXHAUSTED` immediately instead of making a caller that has somewhere else to go wait. The admission permit is deliberately NOT held across the detection call itself (`ModelRegistry.detect_composite` re-acquires the same gate per member, which would self-deadlock a 1-permit gate). Every response carries `occupancy`/`queue_depth`/`capacity`/`max_queue`, so the caller can see the refusal coming.
- **`detector_transport.py`** (W4) — `GrpcRemoteDetector(target, *, settings, stub=None)` + `remote_detectors(settings)`: one channel + `DetectorStub` per configured target, built ONCE per process. Translates `RESOURCE_EXHAUSTED` → `DetectorBusy` and every other `grpc.RpcError` → `DetectorUnavailable` — the two outcomes the pool distinguishes. Imports `cv_service.inference.detector.Detection` lazily, so a `tracker`-role process needs no torch/YOLO installed at all.
- **`server.py`** — `serve(settings=None) -> grpc.Server` — resolves `Settings`, builds the gRPC server (`ThreadPoolExecutor(max_workers=settings.grpc_workers)`, HTTP/2 keepalive options), the `ModelRegistry`, one `InferenceGate`, a probed `TrackerRegistry`, registers servicers per `Settings.role` (see "Process roles" above), binds `[::]:{port}`, starts. `main()` — installs `SIGTERM`/`SIGINT` handlers calling `server.stop(grace=settings.shutdown_grace_seconds)`.

### `cv_service/geo/` — visual geolocation pipeline (`docs/plans/done/VISUAL-GEO-V2-PLAN.md` §4/§5)

Wire-agnostic (no module here imports `cv_pb2`). One file per pipeline stage: `pack.py` (reference-pack zip landing, zip-slip guards), `index.py` (`ReferenceIndex` — descriptors + tile metadata, cosine search, `descriptors.npy`/`tiles.json`/`index.json`; `VerifyTileCache` — write-side only, see Gotchas), `encoder.py` (`eigenplaces_r18_512` global-descriptor encoder via `torch.hub`, lazy import), `matchers.py` (`xfeat` default, `loftr` alternative, behind one `build(name)` seam), `rectify.py` (telemetry-conditional IPM perspective rectification, gated on pitch-from-nadir), `rerank.py` (re-rank scoring ranked by inlier count + gate evaluation G-a..G-f), `calibrate.py` (holdout-based threshold calibration + per-cell never-accept table), `sequence.py` (`SequenceLocalizer`, particle-filter sequence gate — re-ranked geometric likelihood, not raw similarity, plus independent convergence gates), `pose.py` (MAGSAC homography fit + reprojection RMS), `localize.py` (`localize_frame()` — the single entry point: texture gate → rectify-if-telemetry → retrieve top-k → geometric re-rank → gates → sequence update → convergence gate → pose → `FrameResult`), `orchestrator.py` (`build_region_index()` — encode, self-calibrate against a holdout split, persist; the full holdout split is encoded into the final index, not just the calibration split).

Not ported (config default or absent field, none wire-breaking): `lightglue_aliked`/`lightglue_disk`/`eloftr` matchers, OSM tie-breaker (`CV_GEO_OSM_WEIGHT=0.0`, inert), `implied_agl_meters` (always `None`).

`spikes/geo/**` is a read-only eval-harness/spike reference — copies of these production modules used to measure the matcher/gate/rectification choices baked in above. Nothing under `cv_service/**` imports it. Full measurement record: `docs/plans/done/VISUAL-GEO-V2-PLAN.md` §9/§9.8; human-readable digest and raw per-frame JSON: `spikes/geo/results/`.

### `cv_service/pull/` — the `DetectPulled`/`LocalizeStream` worker-pull substrate

- **`source.py`** — `PullSource` protocol; `OpenCvPullSource` (`cv2.VideoCapture(url, cv2.CAP_FFMPEG)`) is the sole backend. `open_source(backend=...)` logs and falls back to `opencv` for any other name, never crashes.
- **`clock.py`** — `CaptureClock`: `capturedAt = anchorWallclock + (pts - anchorPts)` (`anchor` mode) or plain receipt wallclock (`arrival`); re-anchors when skew exceeds `CV_PULL_CLOCK_REANCHOR_THRESHOLD_MILLIS`.
- **`loop.py`** — `PullDecodeLoop`: a background reader thread pushes into a non-blocking latest-wins mailbox; `frames()` yields one `(PulledFrame, captured_at_millis, PullDiagnostics)` per served deadline via a ported `DeadlineSampler` (one clock read per iteration, `max(now,...)` debt clamp — no catch-up bursts after a long stall). `dropped_frames` counts only overwrites that land while a served frame is genuinely out for inference — not routine downsampling (see Gotchas).

### Routable models (`request.model_id`, comma-separated for composite)

| `model_id` | Role | Notes |
|---|---|---|
| `yolo26n.pt` **(default)** | General, fast, 80 COCO classes | `DEFAULT_MODEL` in `config.py` |
| `orion12l.pt` | Military vehicles, user-provided YOLO12-L | ~5-6x slower per frame than the default on CPU |
| `yoloe-26s-seg-pf.pt` | Open-vocabulary (~4585 LVIS+Objects365 classes incl. people/vehicles/**buildings**) | opt-in, not the default; routes via plain `ultralytics.YOLO(name)` — no `YOLOE` class or `set_classes()` call, prompt-free vocabulary auto-loads; instance-segmentation checkpoint but `map_detections` only reads `.boxes`, masks are dropped |

## Conventions

- `cv_service/grpc/servicers.py` is the sole translation point between wire types and every other module's plain types (`Detection`, `TrackingRequest`/`LockRequest`/`FrameOutcome`, `JobEvent`, `UploadOutcome`, `FrameResult`/`GeoFix`). No other module imports `cv_pb2` — this is what keeps them unit-testable without running codegen.
- Proto enum values cross that boundary as their own value-name strings (`"TRACKING_MODE_FOLLOW"`, `"DETECTION_SOURCE_TRACKER"`, ...), mapped via `cv_pb2.X.Name()`/`.Value()` — no lookup table to drift when the proto grows a value.
- `cv_service/orchestration/` is where a new per-frame responsibility goes — a contributor with declared `reads`/`writes`, never a branch in `session.py`. Two rules have teeth: only `orchestration/detector.py` may reach `InferenceGate`, and only `orchestration/aggregator.py` may call `TrackBook.apply`. Both are test-enforced.
- **Describing a frame is not contributing to one.** `orchestration/mirror.py` (W1) is a pure function `session.process()` calls AFTER the run, not a contributor and not part of the aggregator — CV-ORCHESTRATION §4.5 says "the aggregator fills `objects[]`", and this is a recorded deviation from it. Two of the mirror's fields are not track facts: `provenance.contributors` comes from the `FrameLedger` (which the aggregator never receives, by design) and `belief.confidence_raw` from the response boxes it has only just produced. Handing the aggregator a ledger reference to close that gap would give the one class that MUTATES track state a second responsibility plus a reference to the record of what it did.
- `cv_service/tracking/` is pure stdlib except `engines/{bytetrack,lk,ncc,flow_gmc,histogram}.py`; `cv_service/inference/detector.py` and `registry.py` need the `cv` extra at module scope. `cv_service/grpc/server.py`/`servicers.py` import both lazily inside their own `_build_default_registry()`, so `python -m cv_service.grpc.server` stays runnable (echo mode) with no `cv` extra installed at all.
- `cv_service/config.py` is the one place any `CV_*` env var is read — no other module calls `os.environ.get` directly.
- Generated stubs live under `cv_service/gen/`, never committed — run `scripts/gen_proto.sh` after cloning or after a `proto/vision/v1/cv.proto` change.
- Tests live in `tests/` (not under `cv_service/`), mirroring the package layout (`tests/{inference,training,grpc,tracking,orchestration,geo,pull,trackeval}/` + `tests/test_config.py`), plain `pytest`, fixtures in `tests/conftest.py`.

## Gotchas

- **`ultralytics.BYTETracker.__init__` resets a process-global `BaseTrack._count`** (verified against ultralytics 8.4.104) — two concurrent streams' engines would otherwise both allocate id 1. `ByteTrackEngine._new_tracker` restores `BaseTrack._count` after construction (`getattr`-guarded, degrades silently if a future ultralytics drops the attribute). Assigning `STrack._count` directly does **not** work — it shadows the attribute while `next_id()` keeps incrementing `BaseTrack._count`. `TrackBook` never publishes an engine key anyway (it maps to its own per-stream ids), so a regression here still can't leak an id across streams.
- **`opencv-python` is pinned to a major range, not left floating** — before this pin it floated transitively from `ultralytics`; OpenCV 5 removed `TrackerKCF`/`TrackerCSRT`/`TrackerMOSSE` and dropped `cv2.legacy` entirely, so a rebuild landing on a different major changes which tracker APIs even exist. `TrackerRegistry.probe()` still checks constructibility at startup rather than trusting the pin.
- **`lap` is a hidden runtime dependency of `BYTETracker.update`** that ultralytics' AutoUpdate otherwise resolves by `pip install`ing it from the network *mid-stream* — a guaranteed in-flight failure on an offline box (GB4005, a container, a companion computer in flight). Pinned explicitly instead.
- **Never add `opencv-python-headless` alongside plain `opencv-python`** — `ultralytics` hard-depends on the GUI-enabled build, pip has no notion the two conflict, and installing both leaves whichever installs last silently overwriting the other's `cv2` files on disk. Satisfy runtime shared-library needs at the OS level instead (Dockerfile: `libgl1`/`libglib2.0-0`).
- **`CV_MODEL`/weights location**: `YOLO("name.pt")` downloads into the **current working directory**, not a global cache — gitignored, never commit a downloaded `.pt`. `ModelRegistry` discovery is instead resolved from `Settings.model_dir`, computed from `cv_service/config.py`'s own file location — robust to whatever directory the process is launched from, unlike the cwd-relative download path.
- **`imgsz`/OpenVINO export coupling**: the Dockerfile bakes a **fixed** input size into the exported IR at build time (`imgsz=416`); that export size must equal the runtime `CV_IMGSZ` or inference silently runs against the wrong size. Change both together (Dockerfile `ENV CV_IMGSZ` and `config.py`'s `DEFAULT_IMGSZ`).
- **Docker's baked OpenVINO export only covers the default model** (`yolo11n` at image-build time) — every other roster model (`orion12l`, `yoloe-*`, etc.) runs plain PyTorch inside the container too, without the ~2-3x OpenVINO speedup.
- **`confidence_threshold` ambiguity**: proto3 `float` means an unset `FrameRequest.confidence_threshold` reads as `0.0`, indistinguishable from "explicitly zero". Both the servicer and `YoloDetector.detect()` treat falsy as "use `DEFAULT_CONFIDENCE`" — requesting threshold `0.0` (accept everything) isn't representable on the wire today.
- **First-request latency**: `YoloDetector.__init__` pays Ultralytics' warmup `predict()` cost at *construction*, not on the first real `detect()` call — this is what protects `adapter-cv-grpc`'s 2s response timeout from tripping into outage backoff right at stream start.
- **`LatestOnlyMailbox` drops a frame with no response at all for that frame's sequence** — never a queue. On the Java side that specific pending future simply times out (`adapter-cv-grpc`'s `RESPONSE_TIMEOUT_SECONDS=2s`) rather than being answered late; expected given how bounded the sender's own in-flight window is, not a bug.
- **grpc Python servers GOAWAY ("too_many_pings") a client that pings with no active calls, by default** — `adapter-cv-grpc` pings while idle (needed because an outage-backoff stream has no in-flight RPC to piggyback a ping on). `_KEEPALIVE_SERVER_OPTIONS`' `grpc.keepalive_permit_without_calls=1` is required or this server tears down that exact connection as abusive.
- **`tracker_millis` spans the `PHASE_TRACK` contributors only — it does NOT include ego-motion**, which is `PHASE_PRE` and has its own `motion_millis` wire field. Charging ego-motion to `tracker_millis` would double-count it against a field that already exists, which is why `egomotion.*`'s phase is load-bearing rather than cosmetic. Within that span it is still the whole path including frame decode, not just the engine call — 3-5x the engine's own cost on a JPEG feed. It is an `int64` of milliseconds, so a sub-half-millisecond frame reports `0` (common on small frames, not a bug).
- **`track_max_age_frames` and `track_max_age_millis` mean different things.** `max_age_frames` counts consecutive failed *verify passes* — in ASSOCIATE that's every received frame, but in FOLLOW a verify pass only happens on cadence, so the same count can span up to a minute of real time. `track_max_age_millis` is a wall-clock backstop from `Track.last_confirmed`, independent of verify-pass count. Whichever rule trips first declares LOST. `max_age_frames` is also, separately, `ByteTrackEngine`'s own `track_buffer` size.
- **An engine reset (an exception, or an operator changing engine/mode) bumps the book's key epoch (`TrackBook.bump_epoch()`) rather than wiping it** — namespaces future engine keys into a fresh epoch without retiring a single live track. `forget_keys()` (a genuine wipe) is used only by tracking going fully OFF. A stream reconnect must **not** bump the epoch on the `cost` path specifically — `cost` mints its own keys from the book itself (an `object()` sentinel or the matched track's existing key), so there is nothing an epoch bump protects there; bumping it anyway orphans every live track for no reason (`EngineSet.book_owns_keys()` is the predicate that keeps this from happening).
- **`ObjectState.Timing` is NOT epoch time, and cv-service has two clocks.** Tracks are aged on `time.monotonic()` (`session.process(now_millis=…)`), so `Track.first_seen`/`.last_seen`/`.last_confirmed` are monotonic SECONDS and `DormantIdentity.lost_at_millis`/`.first_seen_millis` are monotonic MILLIS. `_object_state_message` rebases all of them once, at the wire, by `request.timestamp_millis - now_millis` — so the three `Timing` instants are on the same timebase as the response's own `timestamp_millis` and on no other. Compare them against that field, never against a reader's wall clock: under `DetectStream` the anchor is the JVM caller's clock and under `DetectPulled` it is this host's. Durations (`horizon_ms`, `since_confirmed_ms`, `dormant_ms`) are timebase-free and are not rebased.
- **`Track.reupdated`/`displacement_x`/`_y` are THIS-FRAME facts on a per-frame-mutated object.** `_observe` resets them on every booking, so a live ASSOCIATE track the associator did not match still carries whichever earlier frame's values. `detections[]` never shows a stale one (an untouched track emits no `Detection` at all), but the W1 mirror emits EVERY live track — so `mirror.py` gates all three on `track.last_seen == ctx.now`, the exact equality that means "booked this frame". Anything new read off `Track` by the mirror needs the same question asked of it.
- **Two defaults this document got wrong until CV-ORCHESTRATION W0**, both found by reading `config.py` rather than the doc: the ASSOCIATE associator is **`cost`**, not `bytetrack` (`config.py:90`), and the **ROI rescue ships ON** (`config.py:370`), flipped in TRACKING-V2 wave C5c. A reader who trusted the old rows would have mis-predicted both which code path runs and what a frame costs.
- **"Recovery is `cost`-only" was also wrong.** ASSOCIATE recovers through `memory.gallery` (whole-gallery `ObjectMemory.match`, registered on the `cost` roster only), but FOLLOW recovers too, through a targeted `ObjectMemory.match_identity` re-anchor inside the follow contributor. Gallery resolution is unconditional in every mode; what differs is *which* recovery question gets asked.
- **The ledger is evidence, not a log.** `CV_LEDGER_RING` frames per session, in memory, never persisted, never pushed, and nothing is serialised unless somebody calls `Inspect`. It is also the only thing a session keeps from a finished frame — do not start reading it back into a decision, or the debug surface becomes load-bearing.
- **`Inspect` can race a running frame, and that is the intended trade.** It runs on a different gRPC thread; it copies the session list under the registry's lock and reads only already-built state, so it never blocks the tracker. A frame that lands mid-read is simply not in the answer. A session that has never run a frame reports an empty contributor list, because engines resolve lazily and there genuinely is no roster yet.
- **`ObjectMemory.claim`'s first-come-first-served semantics are preserved by ORDER, not by a comment** — the topological sort puts `detect.roi` before `memory.gallery` on the `cost` path because ROI rescue claims a dormant identity first. Changing either contributor's declared `reads`/`writes` can silently reorder them.
- **`TrackBook.apply()` must be called exactly once per `process()` call** — it ages *every* live track once per call, so a second call in the same frame silently double-ages every track not actually touched that frame. Multi-target FOLLOW batches every target's observation into one list before calling `apply()` once.
- **`TrackBook._retire` is the only place a track may leave `self._tracks` for "it might come back"** — it hands the track to `ObjectMemory.remember()` immediately before deletion. A future lifecycle path that pops a track out of `self._tracks` without routing through `_retire` reintroduces "deleted without being remembered" silently. `forget_keys()` (a full stop) is the one deliberate exception.
- **`ObjectMemory.claim()` returning `None` during a recovery attempt is a same-frame race, not a failure** — two unmatched targets in one frame can both score above threshold against the same dormant identity; whichever's turn comes first wins the id, the rest fall back to a fresh one. This is intended "refuse rather than guess" behaviour, not a bug to fix by scoring globally.
- **A track's velocity is evidence-only and EMA-smoothed** (`Observation.predicted`, set only by the session, never an engine) — feeding a coasted/predicted box back in as an "observation" makes the velocity estimate self-confirming and can walk a static target's box off it across an occlusion. Any new observation path must decide deliberately whether its box is evidence or extrapolation.
- **A coasting box predicts forward (`predict.py`, constant-velocity, clamped by `_MAX_EXTRAPOLATION_SECONDS=2s`) instead of freezing** — freezing made the FOLLOW re-anchor test compare against a long-stale position, which could never re-anchor. `TrackBook.warp()` mutates every live track's *stored* `box`/`velocity_*` once per frame, before anything reads it, rather than threading a `transform` into `predict()` at read time — a stalled track needs the sum of every frame's camera motion since it was last touched, not just the last frame's delta. If a `transform` parameter reappears on `predict()` or on the coast/select paths in `orchestration/contributors/`, that is very likely this undercorrection bug coming back.
- **`Transform` direction is load-bearing, not a documentation nicety** — it maps a point in the PREVIOUS frame to where it appears in the CURRENT one. A compensator warping backwards is exactly as plausible in isolated unit tests as one warping forwards, while making association strictly worse than no compensation at all.
- **`flow`'s `goodFeaturesToTrack` runs over the whole frame, unmasked, including the tracked target's own box** — deliberate, since ego-motion is a background property and excluding the target's box would couple the compensator to the thing it's supposed to be agnostic about. `_MIN_INLIER_RATIO` is what refuses a fit when a moving foreground subject dominates the point cloud.
- **Ego-motion compensation only ever fires for FOLLOW, and for ASSOCIATE when the resolved associator is `cost`** — `bytetrack` never compensates (its state lives inside a third-party Kalman filter with no seam to warp).
- **FOLLOW with no lock held re-acquires on a cadence (`CV_TRACK_REACQUIRE_MILLIS`, default 250ms), not every frame** — a target that is genuinely gone would otherwise cost a detector pass on every remaining frame of the stream, worse than ASSOCIATE and the opposite of what FOLLOW exists for. Effective cadence is `min(reacquire, verify_every_millis)` so a short verify cadence still wins.
- **The ROI rescue's gate is deliberately stricter than the primary `cost` match's** (`CV_TRACK_ROI_MIN_IOU=0.2` vs. the primary match's permissive `0.0`) — a rescue crop has no whole-scene competition to explain each candidate box, so reusing the permissive gate let a rescue lock onto a neighbouring object in a dense scene.
- **`StartTraining` runs on CPU on the real deploy box** (GB4005 — Intel Gemini Lake, no NVIDIA GPU) and is genuinely slow; logged once (`trainer._warn_cpu_once`). `CV_DEVICE` is never hard-pinned to CPU anywhere, so a GPU training host works with zero code change — the practical path stays *train on a GPU box → rsync the artifact in → `PromoteModel`*. GB4005's own inference speedup path is **OpenVINO, not CUDA** (`~230ms/frame` PyTorch CPU vs. `~135-150ms/frame` OpenVINO IR for `yolo26n` there); full runbook `cv/cv-service/DEPLOY-GPU.md`.
- **`StartTraining`'s dataset must already be on the training host** — it does not receive dataset bytes over gRPC itself; `TrainingJobSpec.dataset_id` resolves to an already-present exported-YOLO dir, landed by rsync or `UploadDataset` beforehand. A missing dataset is a normal reported `FAILED`, never a gRPC abort.
- **Ultralytics fires `on_fit_epoch_end` one extra time** after the last epoch (a trailing validation pass, re-reporting the same epoch's metrics) — `ultralytics_train` suppresses it so the stream carries exactly one `RUNNING` per epoch.
- **`BuildReferenceIndex`'s `land_pack()` call must run after the temp-zip write handle closes, not inside the `with` block** — `land_pack` reopens the path through its own separate file descriptor; calling it before the write buffer flushed made every upload fail with "File is not a zip file", 100% of the time (a real, found-and-fixed production defect).
- **`torch.hub.load("gmberton/eigenplaces", ...)` fails non-interactively on a cold cache even with `trust_repo=True`** — its `hubconf.py` nests a `torch.hub.load("gmberton/cosplace", ...)` call that doesn't forward `trust_repo`, hitting torch.hub's interactive trust prompt (`EOFError`, no stdin, on a server process). `servicers.py`'s `_apply_geo_model_cache_dir`/`_GEO_PRETRUSTED_HUB_REPOS` pre-seed torch.hub's persisted trust list for both `gmberton/*` repos before the first real build.
- **`DetectionResponse.detector_ran` is the SCHEDULER'S DECISION, not "a detector answered"** — it is `budget.run_detector` and has been since TRACKING-V2. Before W4 the two were the same thing; with a pool they can diverge, and on a frame where every target refused, `detector_ran` is still `true` while no boxes were produced. W4 deliberately did not redefine a wire field the Java side already reads. **The ledger is the only surface that says whether a pass actually happened** — `detect.full` is `LEDGER_OUTCOME_FAILED` with every refusing target named in its reason. Asserted, so it cannot drift silently, in `tests/orchestration/test_detector_affinity.py`.
- **Affinity is a DEPLOYMENT property, not code** — §4.9's "one tracker per app instance" is enforced by the Java side's ordered target list + gRPC `pick_first` (`cv/grpc/MODULE.md`), never by anything in this module. A `docker compose up --scale cv-service=3` behind ONE DNS name breaks it silently: Docker's round-robin would hand consecutive frames of one stream to different trackers, and each would mint its own ids. Name tracker instances individually and give each Java app instance its own single target. The detector side has the opposite rule — any instance may serve any frame, which is exactly why the pool can fail over mid-stream without touching an id.
- **A detector's admission permit is NOT held across the detection call** — `ModelRegistry.detect_composite` (and the pinned single-detector path) acquire the SAME process-wide `InferenceGate` per member, so holding `admit()` around the call self-deadlocks a 1-permit gate on the first frame. `admit()` bounds the QUEUE (who is allowed to wait); `acquire()` bounds CONCURRENCY (who may run). Two doors, one gate.
- **`VerifyTileCache` is write-side only wired — a real gap, not a design choice.** `orchestrator.build_region_index()` persists a pre-scaled grayscale tile cache (`verify_tiles.npz`) into every region built, but nothing on the query path reads it back — `rerank.load_region_tile_image` does a fresh full-color `cv2.imread` off disk on every re-rank candidate, every query. Every `BuildReferenceIndex` currently pays to build a cache that buys nothing at query time.

## Status

`Inference.DetectStream`/`DetectPulled` run real Ultralytics YOLO inference (CPU by default, OpenVINO on the GB4005 deploy target), falling back to an echo response when the `cv` extra is absent or the model can't load. Per-stream frame receipt and inference overlap, bounded across streams by one process-wide `InferenceGate`. The model registry supports multiple routable checkpoints and comma-separated composite (multi-model) requests.

The detect-then-track duty cycle (`cv_service/tracking/`) is fully implemented: `OFF`/`ASSOCIATE`/`FOLLOW` modes, four pluggable engine rosters (associators, followers, motion compensators, appearance extractors) behind a capability ladder (L1-L5) that gates which engines are even constructible on a given host, a dormant-identity gallery that survives a track's expiry, session pooling across a stream reconnect, multi-target FOLLOW, ROI re-detection rescue, Observation-Centric Re-Update (ORU) for coasted-gap correction, and track-level open-vocabulary label election. `ASSOCIATE` is the deployed default (`vision.tracking.default-mode=ASSOCIATE`, Java side); `OFF` stays byte-identical to a pre-tracking response. Two outcomes remain undemonstrated for lack of camera hardware: stable ids on live (non-synthetic) video, and the cockpit follow-lock demo end to end — recorded as awaiting H1 hardware, not as passed.

CV-ORCHESTRATION wave **W0 is complete**: the 2 362-line per-frame chain in `session.py` is now `cv_service/orchestration/` — contributors with declared inputs/outputs, a Kahn-ordered orchestrator, a frame budget, one aggregator that is the sole writer of `Track`, a per-frame ledger ring, and an `Inspect` RPC to read it. **Zero behavioural delta**: the 30 golden per-frame fixtures in `tools/trackeval/` and `BASELINE.md` are byte-identical and were never regenerated. Push mode now also reports `DetectionResponse.dropped_frames`.

Three responsibilities did **not** become contributors, and the reason is the same each time — moving them would have changed an outcome, which W0 forbids. Label election runs inside `Track._observe` inside `TrackBook.apply`, so it is surfaced as aggregator evidence instead of being lifted out. ORU re-update is per-track, not per-frame, so `Key.CORRECTIONS` has no registered writer in W0. FOLLOW ships as ONE contributor rather than the plan's `follow.verify`/`follow.predict`/`follow.coast` split, because its five outcomes share the post-fold bookkeeping that now rides on `Proposal.settle`; every `TrackBook.apply` call site did move to the aggregator. `emit.raw` is likewise not a contributor (it would be a second writer of `OBSERVATIONS`); the aggregator's no-proposal branch is that path.

Two real defects surfaced during the move, both caught by the golden fixtures rather than by review: the budget never marked the aggregator eligible (every frame would have emitted zero boxes), and `Proposal` collapsed "no observations" with "do not book" (which would have frozen every scene the moment detections stopped, since `apply([])` is what ages a live track).

CV-ORCHESTRATION wave **W1 (the wire mirror) is complete on the cv-service side**: every `DetectionResponse` now carries `objects[]` — one `ObjectState` per LIVE track plus one per DORMANT identity — and, when `FrameRequest.trace` is set, that frame's whole `FrameLedger` on field 28. `detections[]` is untouched and the 30 golden fixtures plus `BASELINE.md` are again byte-identical and were never regenerated (`FrameOutcome.objects` is deliberately absent from `golden.py`'s explicit dump list, because it describes state the fixtures already pin through `boxes`). A DORMANT identity reaching the wire is the state this platform could not express at all before — an id the book has retired but the gallery still remembers — asserted end-to-end in `tests/grpc/test_object_state_wire.py`.

W1 added a little genuinely new state, all of it written where the fact was already computed and then discarded, and read only by the mirror: `Track.label_tally`/`.label_stability`/`.confidence_smoothed`/`.displacement_x`/`_y`, `Recovery.match_distance`/`.gallery_considered`, `CostAssignment.costs`, and `Prediction.horizon_seconds`. None of it is read by any decision in `track.py`, `assign.py`, `memory.py` or the scheduler — the unchanged fixtures are the evidence. `Key.PREDICTIONS` changed payload from `list[Box]` to `list[Prediction]` for the last of those: the extrapolation interval is knowable only before the fold, because by the time the mirror runs every touched track's `last_seen` has already advanced to now.

`Training.ListModels`/`PromoteModel`/`StartTraining`/`UploadDataset` are all implemented — a real Ultralytics fine-tune with cancellation and off-thread execution, never auto-promoted.

`Geolocation` (`LocalizeStream`/`BuildReferenceIndex`/`ListRegions`/`DeleteRegion`, `cv_service/geo/`) is the production port of the measured `spikes/geo/` pipeline — texture gate, telemetry-conditional IPM rectification, retrieval + geometric re-rank, a particle-filter sequence gate, and per-cell calibrated accept/reject thresholds. `VerifyTileCache` is a known write-only gap (see Gotchas).

Process roles (`CV_SERVICE_ROLE`) let Inference and Training+Geolocation run as separate processes/containers (`docker-compose.yml`'s `cv-split` profile, ports 50061/50062) — the default combined process is unaffected. The Java-side multi-target config (`vision.cv.inference.targets`/`vision.cv.training.target`) exists and defaults to empty (single-target, unaffected); see `cv/grpc/MODULE.md` for that half.

ARM64 (Raspberry Pi companion computer) is dependency-verified only — every pinned `cv` extra package has a real aarch64 wheel (checked by downloading them), but no runtime numbers exist on real hardware and none of this document's Pi figures are measurements. Nothing in this module changes for that placement; it is deployed the same way as the GB4005 box, by `pip install` + rsync, no separate architecture image.

Populated ONLY when tracing (unlike `entries`/`objects`, which are unconditional) — the plan's own wave-row text says so, and it keeps an untraced frame's ring entry exactly as cheap as before this wave.
