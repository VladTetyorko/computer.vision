# adapter-tiles

HTTP raster reference-tile fetch — `HttpTileSource` and `WaybackTileSource` both implement `ReferenceTileSourcePort` over the JDK `HttpClient`, no third-party HTTP dependency (docs/plans/done/VISUAL-GEO-V2-PLAN.md §1.3/§3.6, harvested from the parked `feat/visual-geo` branch's `adapter-tiles`). `HttpTileSource` fetches one tile from a single configured provider; `WaybackTileSource` fetches the same tile from multiple historical Esri "Wayback" captures in parallel and picks the least-occluded one, wrapping `HttpTileSource` internally rather than duplicating its HTTP/retry logic.

**Dial-only**: no listen/bind side — a plain outbound HTTP client against a configurable slippy-map tile-source URL template (default: the same Esri World Imagery endpoint `vision-web`'s satellite basemap already uses).

**Depends on:** `contexts/vision-perception` (for `ReferenceTileSourcePort`, `TileGrid` conceptually — no code shared, see Gotchas) · **Used by:** nobody yet — H5 (VISUAL-GEO-V2-PLAN.md) wires one implementation into `vision-app` behind `vision.geo.visual.enabled`; not wired as of H3.

**Build/test:** `./mvnw -B -pl cv/tiles -am test` (or `-pl cv/grpc,cv/tiles -am test`, the H3 task's combined scope) — 58 tests + 1 `@Disabled` live-network test (skipped, counted separately by surefire: `Tests run: 58, Failures: 0, Errors: 0, Skipped: 1`). No docker/external prerequisite for the 58 (a real loopback `com.sun.net.httpserver.HttpServer`, JDK built-in, stands in for the tile provider — nothing gated by `assumeTrue`). ~26-45s wall time (real HTTP retry/backoff sleeps in the 429/503/network-error tests dominate). The disabled test, `WaybackTileSourceLiveManualTest`, hits the real Esri/Wayback services and is `@Disabled` by design (same convention as `FfmpegVideoSourceLiveManualTest` in `video-input/rtsp`) — see its own javadoc for how to run it manually.

## API surface
### `com.drones.vision.adapter.tiles`
- `final class HttpTileSource implements ReferenceTileSourcePort` — `boolean supports()` (always `true`: an instance cannot exist without a configured settings template), `byte[] fetch(int zoom, int x, int y)` (never `null`; throws on any failure, see Conventions). Two constructors: `HttpTileSource(TileSourceSettings)` (builds its own `HttpClient`) and package-private `HttpTileSource(HttpClient, TileSourceSettings)` (test seam, and the seam `WaybackTileSource` reuses internally). Both reject `null` with `NullPointerException`. Package-private `Optional<byte[]> fetchOptional(int, int, int)` is the internal seam `WaybackTileSource` uses to tell "this release doesn't cover the tile" (empty) apart from a genuine failure (throws) — not part of the port, not public.
- `record TileSourceSettings(String urlTemplate, int zoom, int maxTiles, int concurrency, double requestsPerSecond, Duration timeout, String userAgent, int maxRetries)` — the single source for every `vision.geo.visual.tiles.*` tunable (§3.6). No Spring annotations (mirrors `cv/grpc`'s `GrpcCvSettings`): `vision-app` owns a `VisionGeoProperties` record bound to `application.yaml` and maps it to one of these (H5) — never constructed from a `@ConfigurationProperties` type directly. Compact-ctor validated (`urlTemplate` non-blank + must contain `{z}`/`{x}`/`{y}`; `zoom` ∈ [0,22]; `maxTiles`/`concurrency`/`maxRetries` positive; `requestsPerSecond` positive+finite; `timeout` positive non-null; `userAgent` non-blank). `static defaults()` — url-template = Esri World Imagery **`{z}/{y}/{x}`** order (not `{z}/{x}/{y}`), zoom=17 (§4.6's frozen default — z16 measured a 0.75-0.96 false-fix rate), maxTiles=50 000, concurrency=4, requestsPerSecond=20.0, timeout=10s, userAgent=`vision-geo/0.0.2`, maxRetries=5. `zoom`/`maxTiles` are carried purely as configured defaults a region-ingest caller reads — `fetch` itself takes an explicit `zoom` per call and enforces no cap of its own.
- `final class TileMath` — pure, stateless slippy-map (Web Mercator) tile math, ported line-for-line from the Wave 0 spike's `geomath.py`; private ctor, static methods only (java-clean-code SKILL.md §1). `static TileXY degToTile(double lat, double lon, int zoom)`; `static GeoPosition tileToDeg(double x, double y, int zoom)` (NW corner; `x`/`y` accept fractional values); `static GeoPosition tileCenter(int x, int y, int zoom)`; `static List<TileXY> tilesForBbox(double lat1, double lon1, double lat2, double lon2, int zoom)` (corners any order, ordered south-to-north then west-to-east). Latitude/longitude results clamped to valid ranges (pole/antimeridian edge cases). **Deliberately duplicated** (not shared) by `contexts/vision-perception`'s own `TileGrid` — that context may never depend on any adapter module (ArchUnit-enforced), so it carries its own small copy of just the degree→tile piece it needs (`TileGrid#cover`); this class additionally has the tile→degree direction (`tileToDeg`/`tileCenter`) which `TileGrid` has no need for.
- `record TileXY(int x, int y)` — a bare tile coordinate at whatever zoom the caller already knows; unvalidated (a pure coordinate pair).
- `final class TileRateLimiter` (package-private) — shared token-interval limiter (`acquire()`, blocks the calling thread until its slot), ported from the spike's `_RateLimiter`. Bookkeeping under a lock, the actual sleep outside it, so concurrent callers don't serialize on each other's sleep.
- `final class TileOcclusionScorer` — pure static utility, no instances (mirrors `TileMath`'s shape). `static double score(byte[] imageBytes)` / `static double score(byte[] imageBytes, int darknessThreshold)`: decodes via `javax.imageio.ImageIO`, converts to grayscale with the standard ITU-R BT.601 luma weights, returns the fraction of pixels below the threshold (`DEFAULT_DARKNESS_THRESHOLD = 60`, out of 255) as a `double` in `[0,1]`. Bytes that fail to decode (truncated, garbage, empty, an HTML error body) score `WORST_SCORE = 1.0` — maximally occluded, deliberately unusable — rather than throwing, so a caller comparing several candidates never has to special-case decode failure separately from genuine heavy shadow.
- `record WaybackReleaseCatalog(List<WaybackRelease> releases)` — a small, curated, compile-time list of Esri World Imagery "Wayback" historical release captures. `static defaults()` ships the releases the original investigation confirmed are genuinely distinct captures for the reference (Chavdar) tile (`17/76687/44230`), sourced from `cv-service/spikes/geo/wayback_curated_releases.json` (that file is the origin, not read at runtime). Nested `record WaybackRelease(String date, String releaseNumber, String urlTemplate)` — `urlTemplate` uses Wayback's **own** `{level}`/`{row}`/`{col}` placeholder names (not `TileSourceSettings`'s `{z}`/`{x}`/`{y}`); package-private `zxyUrlTemplate()` translates `level→z`, `row→y`, `col→x` so the template can be handed to a plain `HttpTileSource` unmodified. Compact-ctor validated (every field non-blank, `urlTemplate` must contain all three Wayback placeholders); the outer record rejects a null/empty release list.
- `final class WaybackTileSource implements ReferenceTileSourcePort` — wraps one `HttpTileSource` per configured release (same `TileSourceSettings` for all of them except `urlTemplate`, which comes from each release's own `zxyUrlTemplate()` — the caller-supplied `settings.urlTemplate()` is therefore ignored, only its other fields are used). `boolean supports()` always `true`. `byte[] fetch(int zoom, int x, int y)` queries every release in parallel (one virtual thread each, same idiom as `DefaultDiscoveryService#scanAsync`) and returns the lowest-`TileOcclusionScorer`-scoring successful candidate, or throws `IllegalStateException` when no release covers the tile. `public Optional<WaybackFetchResult> fetchWithDiagnostics(int, int, int)` is the same selection but also reports which release won and its score (`record WaybackFetchResult(byte[] bytes, String releaseDate, String releaseNumber, double occlusionScore)`) — `fetch()` is a one-line delegation to it. `static TileSourceSettings recommendedPerReleaseSettings()` returns `TileSourceSettings.defaults()` with concurrency tuned down 4→1 and requests-per-second tuned down 20→2 (a single `fetch()` call already multiplies request volume by the release count, 10 by default). Two constructors mirroring `HttpTileSource`'s own shape: `WaybackTileSource(WaybackReleaseCatalog, TileSourceSettings)` (production) and package-private `WaybackTileSource(HttpClient, WaybackReleaseCatalog, TileSourceSettings)` (test seam, shared across every release).

## Conventions
- Plain class, no Spring, no framework annotations. `System.Logger`: INFO none (a per-tile fetch is too frequent for INFO), WARNING on retry/give-up and on a Wayback release failing.
- **Port-contract adaptation from the harvest (D3).** The parked branch's `ReferenceTileSourcePort#fetch` returned `Optional<byte[]>` (`empty()` = honest 404). The current port (`contexts/vision-perception`'s `ReferenceTileSourcePort`) instead declares `byte[] fetch(int, int, int)` (never null) plus a separate `boolean supports()` readiness check, and folds "tile not found" into the documented `RuntimeException` contract — `DefaultReferenceRegionService` builds a `Tile` straight from the return value with no `Optional` to unwrap, so an uncovered tile now fails the ingest loudly rather than silently shipping a thinner-than-requested pack. `HttpTileSource.fetch` throws `IllegalStateException` on 404; its package-private `fetchOptional` keeps the old `Optional`-returning shape purely as an internal seam so `WaybackTileSource` can still distinguish "this release doesn't cover it, try the next" from "this release genuinely failed" without leaking `Optional` back across the port boundary.
- HTTP 200 → bytes returned. **HTTP 404 → `fetch` throws `IllegalStateException` immediately, no retry** (honest absence, not worth retrying, but no longer representable as an empty return). HTTP 429/5xx → retried with exponential backoff (1s→2s→4s→…, capped 30s) up to `maxRetries`, then throws `IllegalStateException`. Any other HTTP status → throws `IllegalStateException` immediately, no retry (not absence, and retrying a response that won't change is pointless). A network-level `IOException` → same retry/backoff, then throws `UncheckedIOException` wrapping the last failure. This is a deliberate departure from the Wave 0 spike's own script (which silently drops an exhausted tile) — a real ingestion job must learn about a genuine failure, not silently thin out its coverage.
- **Self-governs beyond the bare port contract, on purpose.** `HttpTileSource` enforces both a `Semaphore(concurrency)` gate (held across all retries of one `fetch()` call) and a shared `TileRateLimiter`, even though the port itself sets no such requirement — read as a floor, not a ceiling: a real implementation talking to a third-party, ToS-bound tile provider shouldn't rely on every future caller getting politeness right. Both limits are per-`HttpTileSource`-*instance*, so they hold even if a caller parallelizes `fetch()` across its own threads.
- **`WaybackTileSource`'s selection, composed across releases.** At least one release returns bytes → returns the lowest-scoring candidate, *regardless* of whether other releases had no coverage or genuinely errored (a release missing/failing must not sink a result another release can supply). No release returns bytes and every one honestly reported no coverage → `fetch` throws `IllegalStateException` (there is no `Optional` to return empty into at the port boundary; `fetchWithDiagnostics` is the richer form that does return `Optional.empty()`). No release returns bytes and at least one threw a genuine failure → that failure propagates (the first one encountered), mirroring `HttpTileSource`'s own "a real failure must not silently degrade to 'just missing'" reasoning.
- **`WaybackTileSource` queries every configured release in parallel on one virtual thread each**, no shared `ExecutorService` to size or shut down (same idiom as `DefaultDiscoveryService#scanAsync`). Each release's own `HttpTileSource` still self-governs its own concurrency/rate independently, so the effective ceiling on simultaneous outbound requests across however many threads a caller uses to assemble a whole region's pack is `concurrency × releaseCount` — this is why `recommendedPerReleaseSettings()` tunes concurrency/rate down from the single-date defaults rather than leaving them as-is.

## Gotchas
- The Esri default template's placeholder order is **`{z}/{y}/{x}`**, not the more "obvious" `{z}/{x}/{y}` — `TileSourceSettings`'s compact ctor only checks all three placeholders are *present*, not their order; get this wrong and every tile silently 404s (or worse, fetches the wrong tile) with no compile-time signal.
- `Math` has no `asinh` — `TileMath` implements it via the standard identity `ln(x + sqrt(x*x + 1))`. `contexts/vision-perception`'s duplicated `TileGrid` does the same independently (see API surface above for why it's duplicated, not shared).
- The concurrency `Semaphore` permit is acquired **once per `fetch()` call**, held across every internal retry attempt (not re-acquired per attempt) — a tile stuck retrying through backoff still counts against the concurrency budget, which is intentional (don't pile more load on a source that just told you to back off).
- **Wayback's placeholder names are `{level}`/`{row}`/`{col}`, not `{z}`/`{x}`/`{y}`** — a second, distinct instance of the "get the tile URL convention wrong and it silently fetches the wrong tile" trap above. `WaybackReleaseCatalog.WaybackRelease#zxyUrlTemplate()` is the one place this gets translated; nothing else in this module re-does that translation.
- `TileOcclusionScorer` scores a **solid-color image as a step function**, not a gradient — every pixel shares one luma, so the result is either 0.0 or 1.0 depending on whether that luma clears the threshold, never something in between (the test fixtures use a half-and-half image for a genuinely intermediate score, not a "medium gray" fill — see `TileOcclusionScorerTest`/`WaybackTileSourceTest`).
- No ArchUnit violation: depends only on `contexts/vision-perception`, imports nothing from another adapter module (verified by grep, not just by the pom) — satisfies D3 (adapters never depend on each other).
