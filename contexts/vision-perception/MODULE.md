# vision-perception

The ingest and CV runtime: resolves a device's stream, decodes/samples/publishes video, runs
detection and tracking against it, debounces detections into events, probes a device before it's
trusted, and orchestrates asset-level streaming (`DefaultAssetStreamService`) plus the live-state
facts warehouse needs (`StreamBackedAssetLiveState`). Does **not** own asset/device inventory
(`vision-warehouse` — reads it, never the reverse), flight-controller command/telemetry transport
(`vision-flight` — this context only opens the telemetry ports `UsageTracker` needs, and runs
flight's pure `FlightPhaseRule` state machine, translating its verdict into warehouse's
`UsagePhase`), or replay/history (`vision-events` — a downstream reader, never a dependency). The
largest of the eight contexts by a wide margin (99 main source files, 58 test classes).

**Depends on:** `vision-kernel`, `vision-platform` · `vision-warehouse` (`AssetDirectoryService`
resolves device/asset identity for `DefaultStreamService`/`DefaultAssetStreamService`/
`UsageTracker` — **never** `DeviceRepositoryPort`/`AssetRepositoryPort` directly; devices
`DefaultAssetStreamService` resolves by capability still go through `DeviceService`; this context
**implements** warehouse's `AssetLiveStatePort` via `StreamBackedAssetLiveState`; `UsageTracker`
reads/writes warehouse's `UsagePhase` on `AssetUsage` and the entire `AssetUsage` lifecycle via
`UsageSessionService`, never a repository port) · `vision-flight` (`UsageTracker` opens
`TelemetrySourcePort`/`TelemetryLiveUpdatePort`, persists telemetry via `TelemetryService`, and
runs flight's `FlightPhaseRule`/`FlightPhase`, translated to/from `UsagePhase` entirely inside this
context — see Gotchas)
**Used by:** `vision-events` (reads `DetectionRepositoryPort`), `vision-learning` (reads
`StreamService#latestRawFrame`/`latestDetections`, `ModelRegistryPort`), `vision-map` (live
telemetry), `vision-simulation`; adapters `adapter-rtsp`/`adapter-mjpeg`/`adapter-v4l2`/
`adapter-cv-grpc`/`adapter-mavlink`/`adapter-simulation`/`adapter-persistence`/
`adapter-publish-hls`; `vision-api`, `vision-app`
**Build/test:** `./mvnw -B -pl contexts/vision-perception test`

## Package shape
```
domain.model        detection/tracking/streaming/geo-ingest records + enums
domain.port          13 driven ports (implemented by adapters)
application.stream   stream lifecycle: StreamService, AssetStreamService, StreamBackedAssetLiveState
application.pipeline the hot path: StreamPipeline + collaborators, UsageTracker, two registries
application.device   ProbeService (test-before-save connection probe)
application.geo      ReferenceRegionService / GeolocationSessionService — visual-geolocation seam
```
No `port.in` package — driving interfaces collapse into one service interface + one `Default*`
implementation; commands/read-models are top-level records (`.claude/skills/java-clean-code/SKILL.md`).

## API surface

### domain.model
- `BindingScope` enum — `ORGANIZATION | CATEGORY | ASSET` — which kind of thing a `CvProfileBinding` attaches a `CvProfile` to (docs/plans/active/CV-SETTINGS-PLAN.md §3.1); ordered least→most specific; the asset→category→organization→platform resolution order is an application-layer concern (resolver, wave W2), not this enum's
- `CameraAttitude(yawDegrees, pitchDegrees, rollDegrees, hfovDegrees, yawRateDegreesPerSecond, Instant at)` — camera pose at frame capture, for ego-motion compensation (docs/conclusions/CV-RATE-BUDGET.md §2); `at` non-null. `ofYaw(yaw,hfov,at)`; `from(Telemetry,hfovDegrees)` → `null` when the sample is null/has no heading — never a zeroed attitude
- `CvProfile(CvProfileId id, String name, String description, boolean builtIn, GroupId groupId, ModelRef model, double confidenceThreshold, int inferenceFps, List<String> labelFilter, List<String> labelDenyFilter, boolean detectionEnabled, TrackingConfig tracking, EventRuleConfig eventRule, Instant createdAt, Instant updatedAt)` — a named, persisted CV configuration a `CvProfileBinding` attaches to organization/category/asset (docs/plans/active/CV-SETTINGS-PLAN.md §3.1); `groupId` is **`null` if and only if `builtIn` is `true`** — a built-in (one of the four migration-seeded templates) is a global template with no owner, every other profile belongs to exactly one group; `confidenceThreshold`/`inferenceFps` share `PipelineConfig`'s own range checks (reused, not new constants); `labelFilter`/`labelDenyFilter` are **`List`, not `Set`** — unlike `PipelineConfig`'s corresponding fields, order here is a display concern worth preserving; `eventRule` is start-time only (the debounce engine is built once at `StreamService#start`, never re-armed by a live PATCH); `updatedAt`≥`createdAt`. `toPipelineConfig(PipelineConfig defaults)` — pure fold: every `PipelineConfig` field comes from the profile **except `maxInFlightInferences`**, always `defaults.maxInFlightInferences()` (host capacity, not a profile concern, docs/plans/active/CV-SETTINGS-PLAN.md §5.1); `labelFilter`/`labelDenyFilter` convert list→set. A profile whose fields mirror `PipelineConfig.defaults()`'s own components folds to a byte-identical `PipelineConfig.defaults()`
- `CvProfileBinding(BindingScope scopeKind, String scopeId, CvProfileId profileId, Instant createdAt)` — attaches a profile to one scope; `scopeId` is a **plain string**, not a typed sealed union, so it mirrors the wire contract exactly (`{"scopeKind":"ASSET|CATEGORY|ORGANIZATION","scopeId":"…"}`, docs/plans/active/CV-SETTINGS-PLAN.md §5.2) — a UUID string for `ORGANIZATION`/`ASSET`, a kebab-case slug for `CATEGORY` (since `CategoryId` isn't UUID-shaped); parsing/validating `scopeId` against the concrete kernel id type for its `scopeKind` is the resolver's job, not this record's (it imports no kernel id types). At most one binding per `(scopeKind, scopeId)`, enforced by storage's composite primary key, not here
- `CvProfileId(UUID value)` — `random()`/`of(String)`
- `Detection(String label, double confidence, BoundingBox box, ModelRef model, TrackRef track)` — confidence [0,1]; `track` nullable = untracked; 4-arg ctor defaults `track=null`
- `DetectionEvent(DetectionEventId id, StreamId streamId, AssetId assetId, String label, double peakConfidence, Instant firstSeen, Instant lastSeen, DetectionEventState state, GeoPosition position)` — a debounced "label X seen for a while" occurrence; `assetId`/`position` nullable; `peakConfidence` [0,1]; `lastSeen`≥`firstSeen`; `withObservation(Instant,double)` advances `lastSeen`/raises `peakConfidence`; `closed()` flips `state`; `position` stamped once at open, never updated after
- `DetectionEventId(UUID value)` — `random()`/`of(String)`
- `DetectionEventState` enum — `OPEN | CLOSED`
- `DetectionQuery(StreamId streamId, Instant from, Instant to, String label, int limit)` — all but `limit` nullable = "don't filter"; `limit` positive
- `DetectionResult(StreamId streamId, long frameSequence, Instant capturedAt, List<Detection> detections, Duration inferenceLatency, TrackingTelemetry tracking)` — `frameSequence`≥0, `inferenceLatency`≥0; `tracking` nullable = tracking off; 5-arg ctor defaults it null
- `DetectionSource` enum — `DETECTOR | TRACKER`
- `DetectionState` enum — `OFF | IDLE_NO_VIEWERS | RUNNING` — which of two independent gates explains a stream's boxes-or-no-boxes state; `OFF` = operator's own `detectionEnabled=false`, `IDLE_NO_VIEWERS` = enabled but no demand, `RUNNING` = both open. **Reports gating, never health** — a stalled `DetectionPort` still reads `RUNNING` throughout its outage
- `StreamState` enum — `STARTING | LIVE | STALLED | RECONNECTING | UNOBSERVED` — the video-flow axis only (see `DetectionState` for CV gating, `AssetUsage` for session lifecycle); no `STOPPED` member (a stopped stream is simply absent from `streams()`); `UNOBSERVED` = a proxied stream, this JVM opens no `VideoSourcePort`. `static resolve(sourceObservable, reconnecting, framesObserved, nanosSinceLastFrame, staleAfterNanos)` pure/total; `RECONNECTING` outranks `STARTING`/`STALLED`
- `StopReason` enum — `OPERATOR | IDLE_NO_VIEWERS` — carried as the `STREAM_STOPPED` event's `reason` attribute
- `DetectorReason` enum — `ALWAYS | CADENCE | TRACKER_FAILED | NO_LOCK | BOX_INVALID | COASTED_OUT` — mirrors `cv.proto`'s enum minus `UNSPECIFIED`
- `EventRuleConfig(Set<String> labels, double confidenceThreshold, int consecutiveToOpen, Duration absenceToClose)` — debounce rule for `DetectionEvent`, referenced by `PipelineConfig#eventRule()`; `labels` empty = "track nothing"; `confidenceThreshold` [0,1]; `consecutiveToOpen`>0; `absenceToClose` positive; `defaults()` = {person,car}@0.5, N=3, 5s
- `FeedId(UUID value)` — `random()`/`of(String)`
- `FeedSpec(String protocol, URI source, Map<String,String> options)` — `protocol` lower-case-validated; `source`/`options` non-null, no defaulting ctor
- `GeoPrior(double latitude, double longitude, double radiusMeters)` — `radiusMeters` positive, lat/lon range-checked
- `GeoSessionConfig(String regionId, float targetFps, GeoPrior prior)` — `regionId` non-blank, `targetFps` positive, `prior` nullable = "search the whole reference index"
- `IngestProgress(String regionId, String phase, int done, int total, IngestState state, String message, ReferenceIndexSummary summary)` — one tick of `ReferenceIndexPort#build`'s progress stream; `summary` non-null iff `state==SUCCEEDED`
- `IngestState` enum — `RUNNING | SUCCEEDED | FAILED` — deliberately mirrors, not shares, `vision-learning`'s `JobState` (this module must not depend on `vision-learning`)
- `ModelRef(String id, String version)`
- `PipelineConfig(ModelRef model, double confidenceThreshold, int inferenceFps, int maxInFlightInferences, Set<String> labelFilter, EventRuleConfig eventRule, boolean detectionEnabled, TrackingConfig tracking, Set<String> labelDenyFilter)` — 9-arg canonical, with 5/6/7/8-arg convenience ctors; `labelDenyFilter` drops labels even when `labelFilter` would keep them, applied at the single drop site in `StreamPipeline#onDetectionResult`; `detectionEnabled` is the per-stream **operator-intent** gate, ANDed with the system-derived `StreamPipeline#detectionDemand()`. `defaults()` = `yolo26n.pt`/latest, 0.4, 10fps, 2 in-flight, no filter, no deny, `EventRuleConfig.defaults()`, detection **off** by default (`vision.cv.detection-default-enabled=true` flips deployment-wide), tracking `ASSOCIATE`. Convenience ctors still default `TrackingConfig.off()` (deliberate: "unmentioned keeps old value" vs. `defaults()`'s "what a new stream should be" — see Gotchas). **No server-side burn-in** — every published frame is the clean source frame; boxes render client-side
- `PixelFormat` enum — `BGR24 | RGB24 | YUV420P | JPEG | H264_PACKET | UNKNOWN`
- `PullTelemetry(long decodeMillis, float sourceFps, float achievedFps, long droppedFrames, ...)` (docs/plans/done/MEDIA-SOT-PLAN.md §7) — a **pulling worker**'s own decode-cost/achieved-rate/dropped-frame facts, since it opens the source itself; feeds `DetectionRateWindow`/`PipelineLatencyWindow` in pull mode
- `ReferenceIndexSummary(regionId, name, RegionBounds bounds, zoom, builtAt, tileCount, descriptorCount, descriptorDim, encoderId, acceptSimilarity, acceptMargin, holdoutRecallAt1, holdoutMedianErrorMeters, indexBytes, neverAcceptCells)` — a built region's full identity+stats view (cv-service is the source of truth); `impliedStatus()` → `NEVER_ACCEPT` when every cell is never-accept, else `READY`
- `ReferenceRegion(regionId, name, RegionBounds bounds, zoom, RegionStatus status, ReferenceIndexSummary summary)` — `ReferenceRegionService`'s read model, merging an in-flight job with cv-service's built regions; `summary` non-null iff `status` is `READY`/`NEVER_ACCEPT`
- `RegionBounds(double north, double south, double east, double west)` — corners range-checked ([-90,90]/[-180,180]), `south<north`/`west<east` strict — no antimeridian spanning
- `RegionIngestSpec(String regionId, String name, RegionBounds bounds, int zoom)` — `regionId` kebab-case slug, `name` non-blank, `zoom` in [15,19]
- `RegionStatus` enum — `BUILDING | READY | NEVER_ACCEPT | FAILED`
- `TargetLock(long lockSeq, Long trackId, Double pointX, Double pointY, boolean release)` — which object `FOLLOW` should hold, restated every frame, idempotent by `lockSeq` (strictly increasing, allocated by the application layer). Accepts **exactly one** of `trackId` / `pointX`+`pointY` (normalized [0,1]) / `release=true`
- `Tile(TileCoordinate coordinate, byte[] content)` — `content` not defensively copied
- `TileCoordinate(int z, int x, int y)` — `z`≥0, `x`/`y` in `[0,2^z)`; `id()` → `"z/x/y"`
- `TileGrid` (final, pure utility) — `static List<TileCoordinate> cover(RegionBounds, zoom)`; `static long count(RegionBounds, zoom)` — lets `DefaultReferenceRegionService` refuse an oversized ingest before fetching a tile
- `TrackedObject(long trackId, Detection detection, Instant firstSeen, Instant lastSeen)` — `trackId`≥0, `lastSeen`≥`firstSeen`; the application layer's `TrackBook` entry type; deliberately not cross-validated against `detection.track()`
- `TrackingConfig(TrackingMode mode, String engineId, int verifyEveryMillis, int followFps, int redetectIouPercent, int maxAgeFrames, int minHits, int capabilityLevel, int reupdateMaxGapMillis, TargetLock lock)` — 10-arg canonical, 8-arg convenience ctor defaults the last two to `0`; `engineId` empty = server default; `redetectIouPercent` int percent [0,100]; `capabilityLevel` [0,5] is a **ceiling, not a demand** — cv-service serves `min(requested, affordable)`, `0`=auto-probe; `reupdateMaxGapMillis`≥0, `0`=server default; `off()`/`defaults()` both leave the two new fields at `0`. `off()` — mode OFF, verify=2000ms/follow=15fps/IoU=30%/maxAge=30/minHits=3; `defaults()` — mode `ASSOCIATE`, same cadences
- `TrackingCapability(int levelServed, String reason)` — what the capability ladder **actually served** vs. `capabilityLevel`'s requested ceiling; `levelServed` [1,5], never the `0` sentinel; `reason` never null, `""`=served as requested; `levelServed` always ≤ requested
- `TrackingMode` enum — `OFF | ASSOCIATE | FOLLOW`
- `TrackingTelemetry(boolean detectorRan, DetectorReason reason, Duration trackerLatency, String engineId, long lockedTrackId, Duration detectionLag, Duration reupdateLatency, int reupdatedTracks, TrackingCapability capability)` — per-**frame** tracking facts; `reason` non-null iff `detectorRan`; `lockedTrackId`≥0 (0=none); `detectionLag`/`reupdateLatency` non-null `Duration`s, `ZERO`=unknown; `capability` nullable = pre-V3 server reported no level; 5-arg convenience ctor defaults the last four
- `TrackRef(long trackId, TrackState state, DetectionSource source, double velocityX, double velocityY, int ageFrames, boolean reupdated)` — per-detection track facts; `trackId`≥1 (0 is the wire's untracked sentinel — an untracked `Detection` carries `track=null`); `velocityX`/`velocityY` finite, normalized frame-widths/heights per second; `reupdated` = this track's gap was ORU-reconstructed this frame; 3-/6-arg convenience ctors
- `TrackState` enum — `TENTATIVE | CONFIRMED | COASTING | LOST`
- `VideoFrame(StreamId streamId, long sequence, Instant capturedAt, int width, int height, PixelFormat format, ByteBuffer data)` — `sequence`≥0, width/height>0; ctor stores `data.asReadOnlyBuffer()`; `data()` returns a fresh `duplicate()` each call

### domain.port (14, driven — implemented by adapters)
- `CvProfileRepositoryPort` — persistence for `CvProfile` (`findById`, `findAll`, `findAllByGroup(GroupId)` excludes built-ins, `save` upsert by id, `delete` idempotent) and `CvProfileBinding` (`findBinding(BindingScope,String)`, `findAllBindings`, `saveBinding` upsert by `(scopeKind,scopeId)`, `deleteBinding` idempotent), plus `countBindingsFor(CvProfileId)` — the still-bound check behind the delete-profile 409 rule (docs/plans/active/CV-SETTINGS-PLAN.md §5.2). **No implementation exists yet** — wave W3 (`storage/persistence`, `V29__cv_profiles.sql`) adds one; nothing in this module calls it yet either (wave W2's `CvProfileService`/`CvProfileResolver`/`CvProfileCache` are not built)
- `DetectionEventRepositoryPort` — `DetectionEvent save(DetectionEvent)` (**upsert** by id — mutates over its open lifetime); `List<DetectionEvent> findRecent(Instant sinceInclusive, int limit)` (`sinceInclusive` nullable); `List<DetectionEvent> findByStream(StreamId, int limit)`
- `DetectionDemandPort` — `boolean detectionWanted(StreamId, AssetId)` (`assetId` nullable); the **system-derived** half of the two independent gates `StreamPipeline` ANDs (the other is `PipelineConfig#detectionEnabled()`). Must be cheap/non-blocking, no network I/O, must not throw (caller wraps in `catch(Throwable)` regardless); called from one dedicated poll thread, must be safe for concurrent different-stream calls
- `VideoDemandPort` — `boolean videoWanted(StreamId, AssetId)`; drives `IdleStreamReaper`. **Not `DetectionDemandPort` reused** — since detection is off by default, plain-video viewing is the ordinary case, and reusing it would reap watched streams. **Fails open** (`true` on uncertainty); may do network I/O (mediamtx Control API) and must apply its own timeout
- `DetectionLiveUpdatePort` — `void publishDetections(AssetId, DetectionResult)`; `void publishDetectionEvent(DetectionEvent)`; both must not throw and must return quickly
- `DetectionPort` — `CompletionStage<DetectionResult> detect(VideoFrame, PipelineConfig)` — **must not block**, no internal queuing (caller bounds in-flight count and skips, never queues); `default detect(VideoFrame, PipelineConfig, CameraAttitude)` adds pose additively — `null` attitude is the normal state, only the gRPC adapter overrides
- `DetectionRepositoryPort` — `void save(DetectionResult)` (append-only); `List<DetectionResult> query(DetectionQuery)`
- `FeedTransmitterPort` — `boolean supports(FeedSpec)`; `StreamDescriptor start(FeedId, FeedSpec)`; `void stop(FeedId)` (idempotent). TX half of the RX/TX doctrine (`docs/main/CYCLES-PLAN.md` §0) — simulation infra, unrelated to `StreamPublisherPort`
- `PulledDetectionPort` — the **pull** counterpart of `DetectionPort` (worker opens video itself): `Flow.Publisher<DetectionResult> open(StreamId, URI sourceUrl, PipelineConfig)`; `void reconfigure(StreamId, PipelineConfig)`; `void attitude(StreamId, CameraAttitude)`; `void close(StreamId)` (idempotent)
- `PulledGeolocationPort` — pull-shaped counterpart for visual geolocation: `Flow.Publisher<VisualFix> open(StreamId, URI sourceUrl, GeoSessionConfig)`; `void telemetry(StreamId, Telemetry)` (latest-wins); `void close(StreamId)` (idempotent). `cv/grpc` is the intended sole implementer
- `ReferenceIndexPort` — `Flow.Publisher<IngestProgress> build(RegionIngestSpec, Iterable<Tile>)`; `List<ReferenceIndexSummary> list()` (proxies cv-service, the single source of truth for built regions); `void delete(String regionId)` (idempotent)
- `ReferenceTileSourcePort` — `boolean supports()`; `byte[] fetch(int z, int x, int y)` — the tile-provider seam `DefaultReferenceRegionService#ingest` fetches through before `ReferenceIndexPort#build`; kept separate since fetching pixels and indexing them have different failure modes
- `StreamPublisherPort` — `void streamStarted(StreamId, Device)`; `void publish(StreamId, VideoFrame)` (adapter owns latest-wins drop policy); `void streamEnded(StreamId)` (idempotent); `default Optional<URI> viewUrl(StreamId)` (HLS); `default Optional<URI> whepUrl(StreamId)` (WebRTC, never proxied); `default Optional<URI> playbackUrl(StreamId, Instant, Duration)` (never proxied)
- `VideoSourcePort` — `boolean supports(StreamDescriptor)`; `Flow.Publisher<VideoFrame> open(StreamId, StreamDescriptor)` (per-open, hot/live, latest-wins backpressure); `void close(StreamId)` (idempotent)

### application.stream — command/read-model records
- `PipelineConfigPatch(confidenceThreshold, inferenceFps, labelFilter, detectionEnabled, modelId, tracking)` — `StreamService#updateConfig`'s partial-patch command; every field nullable = "leave unchanged"; `labelFilter` present-but-empty = "keep all labels"; `modelId` is the checkpoint id only; `tracking` is a `TrackingConfigPatch`
- `TrackingConfigPatch(TrackingMode mode, String engineId, Integer verifyEveryMillis, Integer followFps, Integer redetectIouPercent, Integer maxAgeFrames, Integer minHits, Integer capabilityLevel, Integer reupdateMaxGapMillis, TargetLock lock)` — all ten nullable = "leave unchanged"; `NOTHING` the identity; `TrackingConfig foldOnto(TrackingConfig current, LongSupplier lockSequence)` — the fold lives on the record; `lockSequence` consulted only when the patch carries a lock; 8-arg convenience ctor defaults the two new fields to `null`
- `ActiveStream(StreamId streamId, DeviceId deviceId, Instant startedAt, StreamState state, boolean detectionEnabled)` — 5-arg canonical, what `streams()` returns and `GET /api/streams` serializes; 3-arg convenience ctor defaults `state`/`detectionEnabled` to `UNOBSERVED`/`false` ("we were not told", never optimistic). No `burnedIn` field — removed with server-side overlay
- `UpdateOutcome(boolean modelReArmed, boolean trackingChanged)` — `StreamService#updateConfig`'s result; `modelReArmed` true only when `modelId` differed; `trackingChanged` true iff the folded `TrackingConfig` differs, independent of `modelReArmed`

### application.stream — services
- **`StreamService`** (interface) → **`DefaultStreamService`** — **one canonical constructor**: `DefaultStreamService(AssetDirectoryService, VideoSourceRegistry, DetectionPort, StreamPublisherPort, DetectionRepositoryPort, EventPublisherPort, DefaultStreamServiceSettings)`. `start` resolves the device via `assetDirectory.findDevice(deviceId)` — `NoSuchElementException` for an unknown device. `DefaultStreamServiceSettings(Optional<UsageTracker>, Optional<DetectionEventRepositoryPort>, Optional<DetectionLiveUpdatePort>, StreamPipelineSettings, Optional<PullDetectionSettings>, Optional<DetectionDemandPort>)` bundles every optional collaborator; `defaults()` reproduces the old shortest-ctor behavior (push mode, no demand port). A present `DetectionDemandPort` schedules `pollDetectionDemand` on the existing `retryScheduler` at `StreamPipelineSettings#detectionDemandPollInterval()`; the per-stream evaluation (package-private `evaluateDetectionDemand`) stamps `RunningStream#lastDemandAt` when wanted, and the effective demand is `now - lastDemandAt < detectionDemandGrace`. **`lastDemandAt` is seeded to `Instant.EPOCH` at `start`**, deliberately not `now()` — demand must be observed, never assumed (see Gotchas). `pollDetectionDemand` wraps each stream's evaluation in its own `catch(Throwable)` — `scheduleAtFixedRate` cancels all future runs on one uncaught exception
  - `StreamId start(DeviceId, PipelineConfig)` / `start(DeviceId, PipelineConfig, TrackingConfigPatch)` — at most one active stream per device; `IllegalStateException` if already streaming, `NoSuchElementException` if unknown. Wraps the source in a `SupervisedPublisher<VideoFrame>` so I/O failure retries with backoff. Tracking fold: `requested.foldOnto(seed.foldOnto(config.tracking()))` — per-stream request > deployment seed (`StreamPipelineSettings#trackingSeed`) > code default
  - `Optional<StreamState> streamState(StreamId)` — video-flow axis; empty for unknown/stopped; consults only the **video** `SupervisedPublisher` (not the pull-mode detection supervisor)
  - `void stop(StreamId, StopReason)` — `stop(StreamId)` = `OPERATOR`; publishes `STREAM_STOPPED` with `attributes["reason"]` and a reason-specific message
  - `List<ActiveStream> streams()` — fills `state`/`detectionEnabled` off the pipeline's live `config()`; `Set<DeviceId> activeDeviceIds()`
  - `Optional<VideoFrame> latestFrame(StreamId)` / `latestRawFrame(StreamId)` — one-line delegations; both the same clean source frame (no burn-in distinguishes them), kept as separate names only because out-of-scope callers (`vision-learning`, `vision-app`) reference `latestRawFrame` by name
  - `List<Detection> latestDetections(StreamId)`; `List<TrackedObject> tracks(StreamId)`; `Optional<TrackingStats> trackingStats(StreamId)`; `Optional<PipelineLatency> pipelineLatency(StreamId)`; `Optional<DetectionRate> detectionRate(StreamId)`; `Optional<DetectionState> detectionState(StreamId)` — all forgiving: unknown/stopped stream reads empty, never an error
  - `UpdateOutcome updateConfig(StreamId, PipelineConfigPatch)` — resolves the `RunningStream` (404 unknown/stopped), computes `modelReArmed` before merging, merges (only confidence/inferenceFps/labelFilter/labelDenyFilter/detectionEnabled/model-id/tracking are foldable; `maxInFlightInferences`/`eventRule`/model-version always from the running config), constructs the merged `PipelineConfig` (its compact ctor validates → 400 before the pipeline is touched)
- **`AssetStreamService`** (interface) → **`DefaultAssetStreamService(AssetDirectoryService, DeviceService, StreamService)`** — starting a stream resolves a device and hands it, with `PipelineConfig`/`TrackingConfigPatch`, to the runtime. `require` throws `NoSuchElementException` for an unknown asset
  - `StreamId startStream(AssetId, DeviceId, PipelineConfig)` / `startStream(AssetId, DeviceId, PipelineConfig, TrackingConfigPatch)` — resolves the asset's single active `VIDEO`-capable device when `device` is `null` (`IllegalArgumentException` if zero/>1 candidates); `IllegalStateException` if not in service; `IllegalArgumentException` if a named device isn't the asset's
- **`StreamBackedAssetLiveState(StreamService, UsageTracker, DetectionEventRepositoryPort)`** — no interface, implements **warehouse's** `AssetLiveStatePort` (the class allowed to compose those three since `perception → warehouse` is already legal)
  - `Map<DeviceId, StreamId> activeStreamsByDevice()`; `int stopStreamsForDevices(Collection<DeviceId>)` (synchronous); `Optional<Telemetry> latestTelemetry(AssetId)`; `Map<AssetId, Integer> openDetectionEventCounts(int scanLimit)`
- `UnsupportedProtocolException extends RuntimeException` — `protocol()`; thrown by `VideoSourceRegistry#sourceFor`

### application.pipeline — the hot path
- **`StreamPipeline`** implements `Flow.Subscriber<VideoFrame>`, `AutoCloseable` — **one canonical constructor**: `StreamPipeline(StreamId, Device, PipelineConfig, Flow.Publisher<VideoFrame>, DetectionPort, StreamPublisherPort, DetectionRepositoryPort, EventPublisherPort, StreamPipelineCollaborators)`. `StreamPipelineCollaborators(Optional<DetectionEventEngine>, Optional<AssetId>, Optional<DetectionLiveUpdatePort>, Optional<Supplier<Telemetry>> telemetrySupplier, LongSupplier nanoTimeSource, StreamPipelineSettings settings, LongSupplier latencyNanoSource, Optional<PullDetectionBinding>)` — the two `LongSupplier` clocks are deliberately separate (frame-cadence/outage backoff vs. wall-clock latency); no `OverlayPort` at any level
  - `void start()` — call exactly once
  - `List<Detection> latestDetections()` — `volatile`, the raw un-extrapolated result (`DetectionExtrapolator`'s smoothed view has no reader — see Gotchas)
  - `List<TrackedObject> tracks()` — `TrackBook#tracks()`, ordered by `trackId`
  - `TrackingStats trackingStats()`; `int effectiveInferenceFps()` — `max(inferenceFps, followFps)` in `FOLLOW`, else `inferenceFps()`
  - `Optional<VideoFrame> latestFrame()` / `latestRawFrame()` — both `volatile`, byte-identical values (no burn-in stage exists), kept as separate accessors for out-of-scope callers
  - `void close()` — idempotent
  - `boolean detectionDemand()` / `void updateDetectionDemand(boolean)` — `volatile`, initializes `true` (fail-open); `effective = detectionEnabled() && detectionDemand()`, two independent conjuncts
  - `DetectionState detectionState()` — the same two fields as a three-value read model; reports gating, never health
  - `PipelineConfig config()` / `void updateConfig(PipelineConfig next)` — `config` `volatile`, hot swap visible next frame; a **model-id** change clears `extrapolator`/`latestDetections`/`trackBook`/`trackingStats`; a **tracking**-only change clears nothing
  - Sampling: `everyNth = max(1, round(effectiveFps/inferenceFps))`, recomputed every frame off a measured EWMA cadence; once `maxInFlightInferences` is reached a sampled frame is **skipped, never queued**

## Conventions
- No Spring/framework imports anywhere in this module.
- **The acting user is a method parameter (`UserId actor`), never a constructor dependency.**
- Constructor injection; every collaborator `Objects.requireNonNull`'d **except** the deliberately-nullable ones: `DefaultStreamService`'s `usageTracker`/`detectionEventRepositoryPort`/`liveUpdatePublisherPort`; `StreamPipeline`'s `eventEngine`/`assetId`/`liveUpdatePublisherPort`/`telemetrySupplier`; `UsageTracker`'s `liveUpdatePublisherPort`/`telemetryObserver`; `DetectionEventEngine`'s `usageTracker`.
- Injected collections defensively copied at construction (`List.copyOf`): `VideoSourceRegistry.sources`, `UsageTracker.telemetrySources`, `FeedTransmitterRegistry.transmitters`.
- `Flow.Subscriber` used identically in two places — `StreamPipeline` (video) and `UsageTracker`'s internal `TelemetrySubscriber` (telemetry) — both request one item at a time and re-request after processing.
- Concurrency: `ConcurrentHashMap` for shared registries; `AtomicInteger`/`AtomicBoolean` for pipeline counters/close-flags; `volatile` for single-writer/many-reader fields (`StreamPipeline.config`/`latestDetections`/`latestFrame`/`latestRawFrame`). One dedicated daemon `ScheduledExecutorService` per service (`DefaultStreamService`, `UsageTracker`), scheduling `SupervisedPublisher` retries.
- Per-asset mutable state in `UsageTracker` (`Tracking`) is synchronized on the `Tracking` instance itself, not a module-wide lock — different assets never contend.
- Every port interface's javadoc documents **Contract** and **Threading**; ports with backpressure concerns (`VideoSourcePort`) add **Backpressure**.
- Records validate in the compact constructor with manual `if (…) throw new IllegalArgumentException(…)`; `Objects.requireNonNull` is application-layer only.

## Gotchas
- **`DetectionExtrapolator#at()` is dead code** since server-side burn-in was removed — `.accept()` still runs on every result, buffering state nothing reads. Do not wire a new "what's currently detected" feature onto `.at()` assuming it is live.
- **A detection failure never closes `StreamPipeline`** — only `onError` (source) and a synchronous publish exception are fatal. One `PIPELINE_ERROR` fires per outage (false→true transition), not per failed frame; every failure after that is silently counted.
- **Only a failed *probe* doubles the backoff** — an in-flight call that fails after the outage began is counted but must not touch `backoffNanos`/`nextProbeAtNanos`.
- **Exactly one probe in flight at a time** — `probeInFlight` and the deadline check are claimed together inside one `synchronized (outageLock)` block.
- **In-flight inference bound is skip-not-queue** — a slow `DetectionPort` degrades detection *rate*, never blocks video.
- **`StreamPipeline`'s sampling rate is measured**, not fixed — trusted only after 5 warmup frames, seeded from the first observed delta.
- **The `/live` stop-freeze bug was a real backend bug**: `DefaultStreamService#stop` used to call `VideoSourcePort#close` synchronously on the request thread; a stuck native grab (up to 20s) starved a browser's connection pool. Fixed: `stop()`/`UsageTracker#unsubscribeTelemetry` do fast in-memory work synchronously and defer `close()` to a fire-and-forget virtual thread.
- **What survives a reconnect vs. re-establishes**: the `StreamPublisherPort` session, `UsageId`/`AssetUsage`, and the pipeline's own outage/backoff state survive untouched — a reconnect resubscribes the *same* pipeline to a freshly-opened publisher. Only the source-side `Flow.Publisher`/`Subscription` re-establishes. Source backoff is 1s→30s doubling, deliberately different from the pipeline's 1s→10s detection-outage backoff.
- **`VideoFrame#sequence()` is not guaranteed monotonic across a reconnect** — the adapter regenerates it fresh on every `open()`; sampling still works, it just restarts its cycle.
- **`DetectionEventEngine.accept`'s per-label absence check only runs when a new `DetectionResult` completes** — no background timer; during a detection outage or gated-off period, an open event stays open, un-evaluated, until the next completed result's timestamp reveals the gap.
- **`DetectionEvent#position` is frozen at open time, not live-tracked.**
- **`PipelineConfig#eventRule`'s labels are independent of `labelFilter`/`labelDenyFilter`** — three sets, no cross-validation; a label excluded by `labelFilter`/`labelDenyFilter` but still named in `eventRule.labels()` silently never opens an event (the deny-list is enforced once, centrally, upstream of the event engine).
- **A model-id re-arm cannot close/reopen any adapter-side detection session from here** — `DetectionPort` exposes only `detect(frame, config)`, no per-stream lifecycle method on the interface; `updateConfig` only clears this pipeline's own model-bound state.
- **Toggling `detectionEnabled` does not reset outage/backoff state** — that answers "is cv-service healthy," independent of the operator's local switch.
- **`UsageTracker.TelemetrySubscriber.onError` is an empty method by design** — best-effort telemetry must never affect stream/usage lifecycle.
- **`UsageTracker` drops a telemetry sample that arrives after its usage has closed**, rather than reopening — reopening from a straggler racing a legitimate close would risk fabricating a phantom usage. A telemetry-only session's opening is always explicit (`engage`), never an implicit side effect of a sample arriving.
- **`evaluateLinkHealth(AssetId)` is not wired to any scheduler** — a directly-callable, deterministically-testable entry point; production periodic wiring is left to `vision-app`. Until something calls it repeatedly, a silent aircraft's phase only updates when a sample happens to arrive or `evaluateLinkHealth` is invoked by hand.
- **No code path in this module ever closes a usage on a source/pipeline failure alone** — confirmed for both video (`DefaultStreamService#stop`'s own javadoc: "a source failure alone never does") and telemetry (`UsageTracker.TelemetrySubscriber.onError` is deliberately empty, `SupervisedPublisher` retries forever and never signals a stop). `docs/plans/active/OPERATOR-UX-5-PLAN.md` finding U1's idle-usage-close sweep (`UsageIdleCloseService`, `vision-warehouse`) is therefore the **only** recovery for a usage orphaned by a crashed process, a killed station, or a lost MAVLink link — it closes such a usage from the outside, on a coarse timer (default 10 minutes), not by fixing this gap; it does not replace `evaluateLinkHealth`'s finer-grained `LINK_LOST` phase transition, and no code in this module changed for it.
- **`Tracking#activeDevices` and `Tracking#activeVideoStreams` count different things — do not collapse them.** `activeDevices` drives usage open/close for *any* device (video or telemetry-only); `activeVideoStreams` is video-only and is the sole `streamCount` `FlightPhaseRule` sees (must read `0` for a telemetry-only asset).
- **`AssetUsage#phase` is typed `com.drones.vision.warehouse.domain.model.UsagePhase`, never `com.drones.vision.flight.domain.model.FlightPhase`**, despite the two being name-parallel — deliberate: warehouse is the ArchUnit-enforced pure leaf and may not depend on flight. `UsageTracker#toFlightPhase`/`toUsagePhase` are the only conversion point; nothing else in this module or warehouse should import the other context's phase enum.
- **`UsageTracker` must never import a `*RepositoryPort` from `vision-warehouse` or `vision-flight`** — a new asset/device/usage need belongs on warehouse's `AssetDirectoryService`/`UsageSessionService`; a new telemetry-persistence need belongs on flight's `TelemetryService`. The phase translation is the one thing that legitimately crosses as a bare type (`FlightPhaseRule`/`FlightPhase`), run only here since warehouse may never depend on flight.
- **`AssetDirectoryService` deliberately wraps warehouse's repository ports directly rather than reusing `AssetService`/`DeviceService`** — those two already depend on `AssetLiveStatePort`, whose only implementation (`StreamBackedAssetLiveState`, here) depends on `UsageTracker`, so routing `UsageTracker` through `AssetService` would close a Spring bean cycle (`UsageTracker → AssetService → AssetLiveStatePort → UsageTracker`). Anyone "cleaning that up" by folding `AssetDirectoryService` into `AssetService` reintroduces the cycle.
- `storage/persistence`'s `AssetUsageMapper` **does** round-trip `AssetUsage#phase`; its `PREFLIGHT` fallback on read fires only for rows written before `V19__asset_usage_phase.sql`, whose column is null. A usage saved today reloads with the phase the tracker computed.
- **A non-immediate `UsageSummaryBatchSettings` bounds, but does not eliminate, how stale `AssetUsage#sampleCount`/positions can read** — up to `batchWindowMillis` behind the freshest fold, lost (not delayed) on a crash before flush. Safe by construction: the durable `telemetryService.record` write for the same sample already landed synchronously regardless of batching.
- **`UsageTracker.onStreamStarted`'s `streamId` is only ever recorded on the call that opens the usage** — for a multi-device asset, only the first device's stream is visible on `AssetUsage#streamId`.
- **`DefaultStreamService` allows only one active stream per device** — starting a second throws `IllegalStateException` rather than replacing it.
- **The tracking component of the `PipelineConfig` passed to `start`/`startStream` is the *bottom* layer of the fold, not the final answer** — the deployment seed and request patch apply on top inside the service.
- **A `TrackingConfigPatch`'s `lock` is null-means-unchanged** — releasing a lock is the explicit `TargetLock{release=true}` form, never an omission.
- `ProbeService#probe` never registers anything — a probe's `StreamId` is fresh, transient, looked up nowhere else.
- **A `detectionEnabled` but currently-undemanded stream produces no `DetectionResult` at all** — `DetectionEventEngine`, training-sample capture, `DetectionRepositoryPort#save`, and `DetectionLiveUpdatePort#publishDetections` all go quiet; video and `latestFrame()`/`latestRawFrame()` are unaffected.
- **A freshly started stream's `lastDemandAt` starts at `Instant.EPOCH`, not the stream's own start time** — do not "simplify" this back to `Instant.now()`; that reopens a 30s-of-free-inference-per-stream bug.
- **Pull mode's gate stops the JVM from forwarding a result, not the worker from producing one** — `PullResultSubscriber#onNext` drops a gated-off result, but the Python worker behind `PulledDetectionPort` keeps pulling/inferring at full rate regardless (`detectionEnabled` isn't on the pull wire).
- **A true→false transition of the detection gate clears every detection-derived read model, in both transports** — `latestDetections()`/extrapolator/track book/rate-and-latency windows all clear, not just future detections. An outage leaves the last value alone (still trying, no fresher answer *yet*); a closed gate never tries again, so holding the last value would assert something false (CLAUDE.md §9). `StreamPipeline#handleDetectionGateTransition()` is the single funnel point for both gate inputs, `synchronized` and edge-triggered; `onDetectionResult` re-checks the gate on entry to close the late-completion race.
- **`DetectionState` reports gating, never health** — a stalled cv-service reads `RUNNING` throughout its entire outage; the outage/backoff machinery and `PIPELINE_ERROR` events are the only source of truth for detector health.
- **`CvProfile` is domain-only as of CV-SETTINGS wave W1** — no service, no resolver, no cache, no persistence adapter exists yet, and `CvProfileRepositoryPort` has zero implementations. `DefaultStreamService#start` does **not** consult it; a stream still starts from whatever `PipelineConfig` its caller passes in, exactly as before this wave. Do not assume profiles are live until wave W2 (`CvProfileService`/`CvProfileResolver`/`CvProfileCache`) lands.
- **`CvProfile#groupId` is `null` if and only if `builtIn` is `true`** — the compact constructor enforces both directions. A future "seed a built-in scoped to one group" feature is not representable with this record as-is; it would need a deliberate model change, not a validation relaxation.
