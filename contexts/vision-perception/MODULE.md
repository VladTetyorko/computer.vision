# vision-perception

The ingest and CV runtime: resolves a device's stream, decodes/samples/publishes video, runs
detection and tracking against it, burns in overlays, debounces detections into events, and probes
a device before it's trusted. Owns the stream's whole lifecycle from "start" to "stop," including the
asset-level orchestration of starting one (`AssetStreamService`) and the live-state facts warehouse
needs about it (`StreamBackedAssetLiveState`). Deliberately does **not** own asset/device inventory
(`vision-warehouse` — this context reads it, never the reverse), does not own flight-controller
command/telemetry transport itself (`vision-flight` — this context only opens the telemetry ports
`UsageTracker` needs), and does not own replay/history (`vision-events` — a downstream reader of
this context, never a dependency of it). The largest of the eight contexts by a wide margin: 345
tests, 91 source files (docs/plans/active/DOMAIN-SEPARATION-W1.md §16) — it inherited the hot
per-frame pipeline, the whole detect/track/overlay/event machinery, and (via W1.6b/d/e below) three
features that used to be filed elsewhere by first-mover rather than by owner.

**Depends on:** `vision-kernel`, `vision-platform` (every context's baseline) · `vision-warehouse`
(a stream resolves its device via `DeviceRepositoryPort`/`DeviceService`; `AssetStreamService`
resolves the asset itself; this context **implements** warehouse's declared
`AssetLiveStatePort` — see Status) · `vision-flight` (`UsageTracker` opens
`TelemetrySourcePort`/`TelemetryRepositoryPort`/`TelemetryLiveUpdatePort`, all flight-owned)
**Used by:** `vision-events` (replay reads perception's `DetectionRepositoryPort`), `vision-learning`
(training capture reads `StreamService#latestRawFrame`/`latestDetections`, `ModelRegistryPort`),
`vision-map` (geolocation reads live telemetry via the same seam), `vision-simulation`; most
adapters (`adapter-rtsp`, `adapter-mjpeg`, `adapter-v4l2`, `adapter-overlay`, `adapter-cv-grpc`,
`adapter-mavlink`, `adapter-simulation`, `adapter-persistence`, `adapter-publish-hls`); `vision-api`,
`vision-app`
**Build/test:** `./mvnw -B -pl contexts/vision-perception test`

## Package shape

```
com.drones.vision.perception.domain.model        23 records/enums
com.drones.vision.perception.domain.port          9 driven ports
com.drones.vision.perception.application.stream   stream lifecycle: StreamService, AssetStreamService,
                                                   StreamBackedAssetLiveState, config-patch records
com.drones.vision.perception.application.pipeline the hot path: StreamPipeline + its collaborators,
                                                   UsageTracker, the two registries
com.drones.vision.perception.application.device   ProbeService (moved in from warehouse, W1.6d)
```

No `port.in` package — driving interfaces collapse into one service interface + one `Default*`
implementation; commands/read-models are top-level records (`.claude/skills/java-clean-code/SKILL.md`).

## API surface

### domain.model — `com.drones.vision.perception.domain.model`
- `record AnnotatedFrame(VideoFrame frame, List<Detection> detections, Telemetry telemetry)` — `telemetry` (kernel type) nullable; `detections` defensively copied
- `record Detection(String label, double confidence, BoundingBox box, ModelRef model, TrackRef track)` — confidence [0,1]; `track` (docs/plans/done/TRACKING-PLAN.md §4.B) nullable = untracked — never a sentinel `TrackRef` with `trackId==0`; a 4-arg convenience ctor defaults `track=null`
- `record DetectionEvent(DetectionEventId id, StreamId streamId, AssetId assetId, String label, double peakConfidence, Instant firstSeen, Instant lastSeen, DetectionEventState state, GeoPosition position)` (docs/plans/done/MVP2-PLAN.md §E, E-a; **moved here from `events` in W1.6b** — it stores/shapes detections and only this context's `DetectionEventEngine`/`DefaultStreamService` ever construct it, filed by consumer not owner before that wave) — a debounced "label X was seen for a while" occurrence; `assetId`/`position` nullable (unresolvable device→asset, or no telemetry yet); `peakConfidence` [0,1]; `lastSeen`≥`firstSeen`; `withObservation(Instant,double)` advances `lastSeen`/raises `peakConfidence` (max), `closed()` flips `state`→CLOSED without moving `lastSeen`. `position` is stamped once, at open time, never updated afterward
- `record DetectionEventId(UUID value)` — `static random()`, `static of(String)`
- `enum DetectionEventState` — OPEN, CLOSED
- `record DetectionQuery(StreamId streamId, Instant from, Instant to, String label, int limit)` — all but `limit` nullable = "don't filter on this"; limit must be positive
- `record DetectionResult(StreamId streamId, long frameSequence, Instant capturedAt, List<Detection> detections, Duration inferenceLatency, TrackingTelemetry tracking)` — frameSequence≥0, latency≥0; `tracking` nullable = tracking was off for this result; a 5-arg convenience ctor defaults `tracking=null`
- `enum DetectionSource` — `DETECTOR | TRACKER`; which of the two tracking loops produced a `Detection` on a frame
- `enum DetectorReason` — `ALWAYS | CADENCE | TRACKER_FAILED | NO_LOCK | BOX_INVALID | COASTED_OUT`; why a detector pass was spent; mirrors `cv.proto`'s enum minus `DETECTOR_REASON_UNSPECIFIED`
- `record EventRuleConfig(Set<String> labels, double confidenceThreshold, int consecutiveToOpen, Duration absenceToClose)` — debounce rule for `DetectionEvent`, referenced by `PipelineConfig#eventRule()`; `labels` empty = "track nothing"; `confidenceThreshold` [0,1]; `consecutiveToOpen`>0; `absenceToClose` positive; `static defaults()` = {person,car} @ 0.5, N=3, 5s absence. Moved here from `events` alongside `DetectionEvent` (it names no other type, but it is `EventRuleConfig`'s only reader that ever moved — the old `perception ↔ events` cycle C4 was this record living in `events` while `PipelineConfig` referenced it)
- `record FeedId(UUID value)` — `static random()`, `static of(String)`; identity for a transmitted feed
- `record FeedSpec(String protocol, URI source, Map<String,String> options)` — `protocol` lower-case-validated like `StreamDescriptor.protocol` (kernel); `source`/`options` non-null, no defaulting ctor; `options` defensively copied
- `record ModelRef(String id, String version)`
- `record PipelineConfig(ModelRef model, double confidenceThreshold, int inferenceFps, int maxInFlightInferences, boolean overlayTelemetry, Set<String> labelFilter, EventRuleConfig eventRule, boolean overlayBurnIn, boolean detectionEnabled, TrackingConfig tracking)` — inferenceFps/maxInFlightInferences>0; `eventRule` non-null; `overlayBurnIn` gates whether burn-in renders at all; `detectionEnabled` (docs/plans/done/CV-CONTROL-PLAN.md §1, Wave B) is the per-stream detect-on/off switch, enforced by `StreamPipeline`; `tracking` non-null. A four-deep chain of N-1-arg convenience ctors (6/7/8/9-arg) each default the field the wave before it added, ending at the 10-arg canonical. `static defaults()` = `yolo26n.pt`/latest, 0.4, 10fps, 2 in-flight, telemetry on, no filter, `EventRuleConfig.defaults()`, burn-in on, detection on, tracking **`ASSOCIATE`** (docs/plans/done/TRACKING-PLAN.md Wave T8 — was `TrackingConfig.off()` through T2–T7). **Convenience ctors still default `TrackingConfig.off()`** — deliberate: a convenience ctor means "what you didn't mention keeps its old value," `defaults()` means "what should a new stream be," and conflating them would silently turn tracking on for every pre-T8 call site (`PipelineConfigTest` pins this with `assertNotEquals`). Turning tracking off is now an explicit act: `PATCH /api/streams/{id}/config`, or `vision.tracking.default-mode=OFF`
- `enum PixelFormat` — BGR24, RGB24, YUV420P, JPEG, H264_PACKET, UNKNOWN
- `record TargetLock(long lockSeq, Long trackId, Double pointX, Double pointY, boolean release)` — which object `FOLLOW` should hold; restated every frame, applied by cv-service only when `lockSeq` is strictly greater than the last applied one (idempotent restatement, invariant P2). Accepts **exactly one** of three forms — `trackId`, `pointX`+`pointY` (normalized [0,1]), or `release=true`; rejects zero/two/three forms and a partial point. `lockSeq` allocated by the application layer's own monotonic counter, never a client
- `record TrackedObject(long trackId, Detection detection, Instant firstSeen, Instant lastSeen)` — trackId≥0, lastSeen≥firstSeen; the application layer's track-book entry (`TrackBook`); deliberately **not** cross-validated against `detection.track().trackId()` — that would break holding an untracked detection
- `record TrackingConfig(TrackingMode mode, String engineId, int verifyEveryMillis, int followFps, int redetectIouPercent, int maxAgeFrames, int minHits, TargetLock lock)` — per-stream tracking config, joins `PipelineConfig`; `engineId` empty = server default; `redetectIouPercent` an **int** percent [0,100] (JSON-/PATCH-friendly); `followFps` is Java-side sampler rate only, no cv-service knob; `verifyEveryMillis`/`followFps`/`maxAgeFrames`/`minHits` positive; `lock` nullable. `static off()` — mode OFF, defaults `DEFAULT_VERIFY_EVERY_MILLIS=2000`/`DEFAULT_FOLLOW_FPS=15`/`DEFAULT_REDETECT_IOU_PERCENT=30`/`DEFAULT_MAX_AGE_FRAMES=30`/`DEFAULT_MIN_HITS=3`; `static defaults()` — mode ASSOCIATE, same cadences (what `PipelineConfig.defaults()` ships since T8)
- `enum TrackingMode` — `OFF | ASSOCIATE | FOLLOW`; how the two perception loops cooperate for one stream
- `record TrackingTelemetry(boolean detectorRan, DetectorReason reason, Duration trackerLatency, String engineId, long lockedTrackId)` — per-**frame** tracking facts (vs. `TrackRef`'s per-**detection** facts); joins `DetectionResult`'s nullable `tracking`; `reason` non-null iff `detectorRan`; `trackerLatency` non-null non-negative; `engineId` non-null, empty=none; `lockedTrackId`≥0, 0=none
- `record TrackRef(long trackId, TrackState state, DetectionSource source, double velocityX, double velocityY, int ageFrames)` — per-detection track facts, joins `Detection`'s nullable `track`; `trackId`≥1 (0 is the wire's untracked sentinel and must never reach here — an untracked `Detection` carries `track=null`); `velocityX`/`velocityY` finite, normalized frame-widths/heights per second; `ageFrames`≥0. 3-arg convenience ctor defaults velocity/age to 0
- `enum TrackState` — `TENTATIVE | CONFIRMED | COASTING | LOST`; lifecycle of the track a `Detection` belongs to
- `record VideoFrame(StreamId streamId, long sequence, Instant capturedAt, int width, int height, PixelFormat format, ByteBuffer data)` — sequence≥0, width/height>0; ctor stores `data.asReadOnlyBuffer()`; `data()` returns `data.duplicate()` fresh each call

### domain.port — `com.drones.vision.perception.domain.port` (driven — implemented by adapters)
- `DetectionEventRepositoryPort` (**moved here from `events` in W1.6b**): `DetectionEvent save(DetectionEvent)` — **upsert** by id (a `DetectionEvent` mutates over its own open lifetime, unlike `DetectionRepositoryPort`'s append-only rows); `List<DetectionEvent> findRecent(Instant sinceInclusive, int limit)` — across every stream, newest-first by `lastSeen`, `sinceInclusive` nullable; `List<DetectionEvent> findByStream(StreamId, int limit)` — empty (not an error) for an unknown/eventless stream
- `DetectionLiveUpdatePort` (W1.6b — this context's slice of the deleted god-port `LiveUpdatePublisherPort`): `void publishDetections(AssetId, DetectionResult)` — attributed to the stream's *owning asset*; `void publishDetectionEvent(DetectionEvent)` — a debounced event opened/advanced/closed. Both must not throw on ordinary delivery failure and must return quickly
- `DetectionPort`: `CompletionStage<DetectionResult> detect(VideoFrame, PipelineConfig)` — **must not block**; no internal queuing/limiting — caller bounds in-flight count and skips (never queues) once at the bound
- `DetectionRepositoryPort` (**moved here from `events` in W1.6b** — only this context ever constructs a `DetectionResult`/`DetectionQuery`): `void save(DetectionResult)` — append-only; `List<DetectionResult> query(DetectionQuery)`
- `FeedTransmitterPort`: `boolean supports(FeedSpec)`; `StreamDescriptor start(FeedId, FeedSpec)` — blocking setup then background transmit, returns the descriptor the RX side ingests from; `void stop(FeedId)` — idempotent. **TX half** of the RX/TX doctrine (`docs/main/CYCLES-PLAN.md` §0) — simulation infrastructure, unrelated to `StreamPublisherPort`
- `OverlayPort`: `VideoFrame render(AnnotatedFrame)` — synchronous, input frame never mutated, returns a distinct instance
- `RecordingPort`: `void streamStarted(StreamId, Device)`; `void publish(StreamId, VideoFrame)` — cheap, no blocking I/O; `void streamEnded(StreamId)` — idempotent; shape mirrors `StreamPublisherPort` but a distinct port (durable storage vs live egress)
- `StreamPublisherPort`: `void streamStarted(StreamId, Device)`; `void publish(StreamId, VideoFrame)` — adapter owns latest-wins drop policy; `void streamEnded(StreamId)` — idempotent; `default Optional<URI> viewUrl(StreamId)` — HLS; `default Optional<URI> whepUrl(StreamId)` — WebRTC, **never proxied** (a WHEP session is a POST/SDP+ICE exchange, not a byte stream); `default Optional<URI> playbackUrl(StreamId, Instant, Duration)` — recorded-clip window, **never proxied either**
- `VideoSourcePort`: `boolean supports(StreamDescriptor)`; `Flow.Publisher<VideoFrame> open(StreamId, StreamDescriptor)` — per-open, hot/live, latest-wins backpressure, unrecoverable failure → `onError`; `void close(StreamId)` — idempotent

### application.stream — command/read-model records
- `ActiveStream(streamId, deviceId, startedAt)`
- `PipelineConfigPatch(confidenceThreshold, inferenceFps, labelFilter, detectionEnabled, modelId, tracking)` — `StreamService#updateConfig`'s partial-patch command; every field nullable, `null`="leave unchanged" (`PipelineConfigPatch.NOTHING` the identity); `labelFilter` a `Set<String>`, defensively copied when present — a present-but-*empty* value means "keep all labels" (unlike `DeviceEdit#capabilities`'s empty-set rejection); `modelId` is the checkpoint id only, never the version; `tracking` is a **`TrackingConfigPatch`** (retyped from `TrackingConfig` — see Status, T3/T6 follow-up)
- `TrackingConfigPatch(TrackingMode mode, String engineId, Integer verifyEveryMillis, Integer followFps, Integer redetectIouPercent, Integer maxAgeFrames, Integer minHits, TargetLock lock)` (docs/plans/done/TRACKING-PLAN.md T3/T6 follow-up) — all eight nullable, `null`="leave unchanged"; `NOTHING` the identity; `TrackingConfig foldOnto(TrackingConfig current, LongSupplier lockSequence)` — the fold lives **on the record**, testable with no stream/ports/clock; `lockSequence` consulted only when the patch carries a lock (lazy allocation, a cadence tweak burns no sequence number); no validation here — an out-of-range cadence is rejected by `TrackingConfig`'s own compact ctor once the fold produces one
- `UpdateOutcome(boolean modelReArmed, boolean trackingChanged)` — `StreamService#updateConfig`'s result; `modelReArmed` true only when the patch's `modelId` differed from the running model; `trackingChanged` true iff the folded `TrackingConfig` differs from the one already running (independent of `modelReArmed` — a mode/engine change never re-arms the detector); 1-arg convenience ctor defaults `trackingChanged=false`

### application.stream — services
- **`StreamService`** (interface) → **`DefaultStreamService`** — `DefaultStreamService(DeviceRepositoryPort, VideoSourceRegistry, DetectionPort, StreamPublisherPort, DetectionRepositoryPort, EventPublisherPort, ...)` growing through six N-1-arg convenience ctors to a 10-arg canonical (+`UsageTracker`, `OverlayPort`, `DetectionEventRepositoryPort`, `DetectionLiveUpdatePort`, all nullable — passing `null` simply skips that feature)
  - `StreamId start(DeviceId, PipelineConfig)` / `start(DeviceId, PipelineConfig, TrackingConfigPatch)` (docs/plans/done/TRACKING-PLAN.md T3/T6 follow-up) — at most one active stream per device; `IllegalStateException` if already streaming or not `ACTIVE`, `NoSuchElementException` if unknown. Wraps the opened `VideoSourcePort` in a `SupervisedPublisher<VideoFrame>` before handing it to `StreamPipeline`, so a source I/O failure is retried with backoff instead of ending the stream (docs/plans/done/MVP2-PLAN.md §S, S-a). **Tracking fold, three layers**: `requested.foldOnto(seed.foldOnto(config.tracking()))` — per-stream request > deployment env (`StreamPipelineSettings#trackingSeed`) > code default — composed once, here, so every start path (device, asset, simulation, demo fleet) converges on the same answer
  - `void stop(StreamId)` — no-op for unknown/stopped; the **only** path that ever ends a stream. Returns promptly: map removal + `SupervisedPublisher#stop()` + the `STREAM_STOPPED` event happen synchronously, but `StreamPipeline#close()`/port `close()` run on a fire-and-forget virtual thread (the `/live` stop-freeze bug fix — see Gotchas)
  - `List<ActiveStream> streams()`; `Set<DeviceId> activeDeviceIds()`
  - `Optional<VideoFrame> latestFrame(StreamId)` / `latestRawFrame(StreamId)` (docs/plans/done/CV-TRAINING-PLAN.md §2/§D) — post-overlay vs. pre-overlay, one-line delegations to the running pipeline
  - `List<Detection> latestDetections(StreamId)`; `List<TrackedObject> tracks(StreamId)`; `Optional<TrackingStats> trackingStats(StreamId)` — all forgiving: unknown/stopped stream reads as empty/`Optional.empty()`, never an error
  - `UpdateOutcome updateConfig(StreamId, PipelineConfigPatch)` (docs/plans/done/CV-CONTROL-PLAN.md §5; tracking fold added T3) — resolves the `RunningStream` (404 unknown/stopped), computes `modelReArmed` from the patch's `modelId` **before** merging, merges via `mergeConfig` (only confidence/inferenceFps/labelFilter/detectionEnabled/model-id/tracking are foldable; `maxInFlightInferences`/`overlayTelemetry`/`eventRule`/`overlayBurnIn`/model-version always come from the running config — frozen contract §3), constructs the merged `PipelineConfig` (its own compact-ctor validation runs → 400 before the pipeline is ever touched), calls `pipeline.updateConfig`
- **`AssetStreamService`** (interface) → **`DefaultAssetStreamService`** (**split off warehouse's `AssetService` in W1.6e**) — starting a stream resolves a device and hands it, with `PipelineConfig`/`TrackingConfigPatch`, to the runtime: perception's job, not inventory's
  - `DefaultAssetStreamService(AssetRepositoryPort, DeviceService, StreamService)` — resolves the asset directly against warehouse's `AssetRepositoryPort` (`perception → warehouse` is the legal direction), devices through `DeviceService`
  - `StreamId startStream(AssetId, DeviceId, PipelineConfig)` / `startStream(AssetId, DeviceId, PipelineConfig, TrackingConfigPatch)` — resolves the asset's single **active** `VIDEO`-capable device when `device` is `null` (`IllegalArgumentException` naming candidates if zero or >1); `IllegalStateException` if not in service; `IllegalArgumentException` if a named device isn't the asset's
- **`StreamBackedAssetLiveState`** (no interface — implements **warehouse's** `AssetLiveStatePort`, W1.6e) — the class allowed to compose `StreamService`/`UsageTracker`/`DetectionEventRepositoryPort` to answer warehouse's declared read of live runtime state, since `perception → warehouse` is already legal and implementing the port here needs no third module
  - `StreamBackedAssetLiveState(StreamService, UsageTracker, DetectionEventRepositoryPort)`
  - `Map<DeviceId, StreamId> activeStreamsByDevice()`; `int stopStreamsForDevices(Collection<DeviceId>)` — **synchronous** (W2 turns this into an event warehouse publishes and perception reacts to); `Optional<Telemetry> latestTelemetry(AssetId)`; `Map<AssetId, Integer> openDetectionEventCounts(int scanLimit)` — `scanLimit` is the caller's own tuning constant, threaded through
- `UnsupportedProtocolException extends RuntimeException` — `protocol()`; thrown by `VideoSourceRegistry#sourceFor`

### application.pipeline — the hot path
- **`StreamPipeline`** implements `Flow.Subscriber<VideoFrame>`, `AutoCloseable` — seven constructors, an N-1-arg convenience chain from 8-arg (no overlay/events) up to a 14-arg package-private test seam (adds `LongSupplier nanoTimeSource`), plus a public 15-arg `StreamPipelineSettings`-taking overload; every intermediate collaborator (`OverlayPort`, `DetectionEventEngine`, `AssetId`, `DetectionLiveUpdatePort`, `Supplier<Telemetry> telemetrySupplier`) is **nullable** — `null` disables that feature only
  - `void start()` — call exactly once
  - `List<Detection> latestDetections()` — `volatile`, the **raw**, un-extrapolated result (the REST-facing surface) — overlay burn-in renders the smoothed `DetectionExtrapolator` view instead, never this
  - `List<TrackedObject> tracks()` (docs/plans/done/TRACKING-PLAN.md §4.E) — `TrackBook#tracks()`, ordered by `trackId`; survives an empty result (a track is a lifetime, not a frame)
  - `TrackingStats trackingStats()` — the stats window's counters stamped with the **live** configured mode
  - `int effectiveInferenceFps()` — `max(inferenceFps, followFps)` in `FOLLOW`, plain `inferenceFps()` otherwise; `everyNth()` divides by this
  - `Optional<VideoFrame> latestFrame()` (docs/plans/done/MVP3-PLAN.md C-a) — `volatile`, the exact instance last handed to `streamPublisherPort.publish` (post-overlay when one was drawn)
  - `Optional<VideoFrame> latestRawFrame()` (docs/plans/done/CV-TRAINING-PLAN.md §2/§D) — sibling `volatile` field, written unconditionally at the top of `onNext`, before overlay runs — always the source's own pixels, never burned-in. Backs training-sample capture
  - `void close()` — idempotent
  - `PipelineConfig config()` / `void updateConfig(PipelineConfig next)` (docs/plans/done/CV-CONTROL-PLAN.md Wave C) — `config` is `volatile`, not `final`; a hot swap visible to the very next frame, no lock, no restart. A **model-id** change additionally clears `extrapolator`/`latestDetections`/`trackBook`/`trackingStats` (stale, wrong-model state); a **tracking**-only change clears nothing (tracking is a hot knob, must never re-arm the detector)
  - Sampling: `everyNth = max(1, round(effectiveFps / inferenceFps))`, recomputed every frame; `effectiveFps` a measured EWMA of the source's own inter-frame deltas; once `maxInFlightInferences` is reached a sampled frame is **skipped, never queued**
  - Two failure policies (docs/plans/done/MVP1-PLAN.md §C7): source errors/synchronous publish exceptions are fatal (one `PIPELINE_ERROR`, then close); detection failures never close the pipeline — one `PIPELINE_ERROR` per **outage**, exponential backoff (1s→10s, doubling), a single probe inference once the deadline passes
  - Debounced events (docs/plans/done/MVP2-PLAN.md §E): every completed result — empty or not — feeds `eventEngine.accept(result)`
  - `applyLabelFilter` runs once, centrally, before every downstream fan-out (`latestDetections`/extrapolator/eventEngine/live-update/persistence) — the CV-CONTROL §A dormant-field fix
- **`DetectionEventEngine`** (public, final — widened from package-private in the LAYERING-REFACTOR wave since `DefaultStreamService` now constructs it from a different package) — per-stream debounce rule engine
  - `DetectionEventEngine(StreamId, DeviceId, EventRuleConfig, UsageTracker, DetectionEventRepositoryPort)` — `UsageTracker` nullable
  - `void accept(DetectionResult)` (`synchronized`) — per tracked label: a qualifying streak of `consecutiveToOpen` opens an event (`firstSeen`=streak start); while open, further qualifying results advance `lastSeen`/raise `peakConfidence`; a gap reaching `absenceToClose` closes it. Every timestamp from `DetectionResult#capturedAt()`, never wall-clock. `assetId`/`position` resolved **once, at open time**, via `usageTracker.resolveAsset`/`latestPosition` — frozen thereafter even while the event stays open
- **`SupervisedPublisher<T>`** (public, final, generic — docs/plans/done/MVP2-PLAN.md §S, S-a) — the "a started stream survives source failures; only Stop ends it" mechanism, a `Flow.Publisher<T>` decorator wrapping a re-openable source, shared by video (`DefaultStreamService`) and telemetry (`UsageTracker`)
  - `SupervisedPublisher(Supplier<Flow.Publisher<T>> opener, Consumer<Throwable> onOutageBegan, ScheduledExecutorService scheduler)` — production; a 5-arg test seam takes explicit backoff bounds
  - `subscribe(...)` — opens the source, forwards `onSubscribe`/`onNext` untouched; `onError`/`onComplete` are intercepted, **never forwarded** — the wrapped subscriber never sees a source ending. `onOutageBegan` fires exactly once per outage, backoff doubles on each failed retry (capped), resets on the first successful `onNext`
  - `stop()` — cancels any pending retry, permanently disables further retries; idempotent; does **not** close the currently-open source (caller's responsibility)
- **`DetectionExtrapolator`** (package-private, final — docs/main/CYCLES-PLAN.md §12, CP-c) — smooths burned-in boxes between completed inferences instead of freezing them
  - `void accept(DetectionResult)` — keeps only the two most recent results; a `frameSequence` ≤ current is ignored
  - `List<Detection> at(Instant t)` — two-pass matching since docs/plans/done/TRACKING-PLAN.md §5.F/T3: (1) exact, ungated match **by `track().trackId()`**, wherever both results carry the same id — the tracker already decided identity; (2) the pre-existing gated (0.15 normalized center distance) nearest-center pass over whatever pass 1 left, which **never** considers a pair where both sides already carry ids. With tracking off, pass 1 matches nothing and behavior is byte-identical to before T3
  - Both methods `synchronized`; called at most once per sampled/published frame
- **`TrackBook`** (package-private, final — docs/plans/done/TRACKING-PLAN.md §5.E, Wave T3) — the stream's `Map<Long, TrackedObject>`, keyed by track id. **Does no association** — identity is decided by cv-service's tracker and arrives stamped as a `TrackRef`; this books what arrived
  - `TrackBook(Duration retention)` (plus a no-arg ctor using `StreamPipelineSettings.defaults().trackRetention()`)
  - `void accept(DetectionResult)` — books every detection whose `track()` is non-null; `firstSeen` preserved, `lastSeen` advances. Two expiry rules run every `accept`: (1) `TrackState.LOST` is **terminal** — leaves the book at once (re-recognizing an id after occlusion is cv-service's own `maxAgeFrames` buffer's job, not this class's); (2) anything unobserved for `retention` is dropped, the safety net for a track that stops arriving without ever being reported `LOST`
  - `void clear()` — called on a **model** re-arm only
  - `List<TrackedObject> tracks()` — immutable snapshot ordered by `trackId`
  - **Invariant P3**: a read model for *any* registered consumer (UI today; geo/COP and guidance sinks later), not the SSE topic's private cache — no consumer-specific field, no map/FOV/screen/camera-pose concept, no SSE/topic reference
- **`TrackingStatsWindow`** (package-private, final — TRACKING-ORCHESTRATION.md §2.3/§5.4, Wave T3) — a **peer** of `TrackBook`, not a field on it: rolling counters over `TrackingTelemetry`, retained by a fixed time window and carrying only counts/timings (vs. `TrackBook`'s track-lifetime read model of full `Detection`s — a `LOST` track leaves the book at once yet keeps counting here until it ages out)
  - `TrackingStatsWindow(Duration window)`; `void accept(DetectionResult)` — a `null` `tracking()` is ignored entirely (not counted as a zero-latency pass); hard-capped at 4000 retained samples
  - `void clear()`; `TrackingStats snapshot(TrackingMode mode)` — `mode` is a **parameter**, stamped at read time, not cached per sample
- `record TrackingStats(TrackingMode mode, String engineId, Duration window, long detectorPasses, long trackerFrames, double dutyRatio, double trackerMillisP50, double trackerMillisP95, DetectorReason lastDetectorReason, long lockedTrackId, Map<TrackState,Integer> byState)` (public, docs/plans/done/TRACKING-PLAN.md §4.E) — `GET /api/streams/{id}/tracks`'s `stats` read model; `static empty(TrackingMode, Duration)`. `detectorPasses`/`trackerFrames` **partition** the window by `detectorRan`; percentiles are nearest-rank over every sample's latency (including detector-only frames' `Duration.ZERO`); `engineId`/`lockedTrackId` from the **newest** sample; `byState` counts distinct track ids by newest state, zero-filled across all four `TrackState`s

  - `Optional<Telemetry> latestTelemetry(AssetId)` (docs/plans/done/MVP3-PLAN.md C-a) — the freshest sample ever received, **not** scoped to the open usage (unlike `latestPosition`) — stays answerable once a usage closes, which is exactly when staleness matters most

### application.device
- **`ProbeService`** (interface, **moved from `warehouse.application.device` in W1.6d**) → **`DefaultProbeService`** — CONTRACT 1's test-before-save connection probe: the read side behind `POST /api/devices/probe`

Telemetry detection: builds a synthetic `Device` and asks every registered `TelemetrySourcePort#supports` whether it claims it, opens the first match for one sample
  - `static String friendlyMessage(Throwable, StreamDescriptor)` (package-private) — pattern-matches well-known substrings in the message text only, **never** a concrete exception type (this module may not depend on the adapter that threw it)

## Conventions
- No Spring/framework imports anywhere in this module.
- **The acting user is a method parameter (`UserId actor`), never a constructor dependency.**
- Constructor injection; every collaborator `Objects.requireNonNull`'d **except** the deliberately-nullable ones: `DefaultStreamService`'s `usageTracker`/`overlayPort`/`detectionEventRepositoryPort`/`liveUpdatePublisherPort`; `StreamPipeline`'s `overlayPort`/`eventEngine`/`assetId`/`liveUpdatePublisherPort`/`telemetrySupplier`; `UsageTracker`'s own `liveUpdatePublisherPort`/`telemetryObserver`; `DetectionEventEngine`'s `usageTracker`.
- Injected collections defensively copied at construction (`List.copyOf`): `VideoSourceRegistry.sources`, `UsageTracker.telemetrySources`, `FeedTransmitterRegistry.transmitters`.
- `Flow.Subscriber` used identically in two places — `StreamPipeline` (video) and `UsageTracker`'s internal `TelemetrySubscriber` (telemetry) — both request one item at a time and re-request after processing.
- Concurrency primitives: `ConcurrentHashMap` for shared registries (`DefaultStreamService.activeStreams`/`streamByDevice`, `UsageTracker.trackingByAsset`); `AtomicInteger`/`AtomicBoolean` for pipeline counters/close-flags; `volatile` for single-writer/many-reader fields (`StreamPipeline.config`/`latestDetections`/`latestFrame`/`latestRawFrame`). One dedicated daemon `ScheduledExecutorService` per service (`DefaultStreamService`, `UsageTracker`), shared across every stream/subscription it supervises, scheduling `SupervisedPublisher` retries.
- Per-asset mutable state in `UsageTracker` (`Tracking`) is synchronized on the `Tracking` instance itself, not a module-wide lock — different assets' start/stop/telemetry never contend.
- Every port interface's javadoc documents **Contract** and **Threading**; ports with backpressure concerns (`VideoSourcePort`) add a **Backpressure** section describing the latest-wins drop policy.
- Records validate in their compact constructor with manual `if (…) throw new IllegalArgumentException(…)`; `Objects.requireNonNull` is application-layer only.

## Gotchas
- **`StreamPipeline` has two distinct detection surfaces — do not conflate them.** `latestDetections()` is the raw, most-recently-completed result (what REST/audit/persistence should read); overlay burn-in renders `DetectionExtrapolator.at(frame.capturedAt())`, a *smoothed* view whose **positions** can differ (matched detections move toward their predicted position, frozen `MAX_EXTRAPOLATION_MILLIS`=800ms past `L.capturedAt()`) while `latestDetections()` stays exactly as last set. Wiring a new "what's currently detected" consumer onto the wrong one is an easy, silent bug.
- **A detection failure never closes `StreamPipeline`** (docs/plans/done/MVP1-PLAN.md §C7) — only `onError` (source) and a synchronous publish exception are fatal. Get this wrong and a flaky/absent CV service takes the whole video path down with it.
- **One `PIPELINE_ERROR` event per outage, not per failed frame** — fires exactly once on the `inOutage` false→true transition; every failure after that (including every failed retry probe) is silently counted (`outageFailureCount`), never a second event.
- **Only a failed *probe* doubles the backoff** — a detection call already in flight when the outage began can still fail afterward; that failure is counted but must not touch `backoffNanos`/`nextProbeAtNanos`, or a stray straggler could stomp a backoff a probe already advanced.
- **Exactly one probe in flight at a time** — `probeInFlight` and the deadline check are claimed together inside one `synchronized (outageLock)` block; two separate lock-free reads would let a racing thread start a second concurrent probe or skip the first backoff window outright.
- **In-flight inference bound is skip-not-queue** — once `maxInFlightInferences` is reached, a sampled frame is dropped outright, never buffered; a slow `DetectionPort` degrades detection *rate*, never blocks video.
- **`StreamPipeline`'s sampling rate is a *measured* source cadence**, not fixed — trusted only after `WARMUP_FRAMES`=5 frames, seeded directly from the first observed delta (not blended toward the 30fps fallback) so a constant-cadence source converges immediately.
- **The `/live` stop-freeze bug was a real backend bug, not (only) a frontend one.** `DefaultStreamService#stop` used to call `VideoSourcePort#close` **synchronously** on the calling (MVC request) thread; `FfmpegVideoSource`'s close can block up to 20s on a stuck native grab, and one stuck `DELETE` starves a browser's small per-origin connection pool — reading, from the Network panel, exactly like "the whole app froze." Fixed: `stop()`/`UsageTracker#unsubscribeTelemetry` now do only fast in-memory work synchronously and defer the actual `close()` calls to a fire-and-forget virtual thread.
- **Source supervision (docs/plans/done/MVP2-PLAN.md §S, S-a) — what survives a reconnect vs. what re-establishes.** Survives untouched, exactly once per stream: the `StreamPublisherPort` session (`streamStarted`/`streamEnded` fire only at `start()`/`stop()`), the `UsageId`/`AssetUsage`, and the pipeline's own detection-outage/backoff state, `latestDetections()`, `DetectionExtrapolator`/`DetectionEventEngine` instances — none of this is pipeline-instance-changing, a reconnect just resubscribes the *same* pipeline to a freshly-opened publisher. Re-establishes on every reconnect: only the source-side `Flow.Publisher`/`Flow.Subscription` (a fresh `open()` call each time). Backoff 1s→30s doubling (deliberately different from the pipeline's own 1s→10s detection-outage backoff and `MediamtxStreamPublisher`'s 500ms→10s — reconnecting a whole source is more expensive to hammer than either finer-grained retry loop).
- **Frame/sample sequence numbers are not guaranteed monotonic across a reconnect, and this isn't fixed** — the *adapter* generates `VideoFrame#sequence()` fresh on every `open()`; `StreamPipeline`'s sampling modulo still works correctly against the reset sequence, it just restarts its cycle.
- **A brief, bounded, non-leaking race is possible between an explicit `stop()` and an in-flight reopen attempt** in `SupervisedPublisher` — never leaks, since `stop`'s caller always calls the underlying port's own `close(id)` afterward regardless of supervision state.
- **`DetectionExtrapolator.accept`'s out-of-order guard is `frameSequence` ≤, not <** — a duplicate/retried completion for the same sampled frame is ignored exactly like a strictly-older one.
- **`DetectionEventEngine.accept`'s per-label absence check only runs when a new `DetectionResult` completes** — no background timer. During a detection outage, sampled frames are withheld from `DetectionPort` entirely, so an event left open when the outage began stays open, un-evaluated, until detection recovers and the next completed result's timestamp reveals the gap.
- **`DetectionEvent#position` is frozen at open time, not live-tracked** — `DetectionEventEngine.open` calls `usageTracker.latestPosition` exactly once, at the streak→OPEN transition; a long-open event reports where the asset *was* first confidently seen, not where it is now.
- **`PipelineConfig#eventRule`'s labels are independent of `labelFilter`** — two separate label sets with no cross-validation; `labelFilter={"car"}` with `eventRule.labels()` still defaulting to `{"person","car"}` means "person" events can never open, which is not treated as a configuration error.
- **A model-id re-arm does not actually close/reopen any adapter-side detection session — it can't from here, deliberately.** `DetectionPort` exposes only `detect(frame, config)`, no per-stream lifecycle method; the `streamEnded(StreamId)` hook lives only on the concrete `GrpcDetectionPort` class (adapter-cv-grpc), never on the port interface this module is wired against. `updateConfig` clears this pipeline's own model-bound state and lets the volatile config swap carry the new model into the next `detect()` call — whether an adapter's own session genuinely switches models per call (true for cv-service today) is that adapter's concern.
- **`maybeDetect`'s `detectionEnabled` gate does not reset outage/backoff state** — toggling detection off then on leaves `inOutage`/`backoffNanos` exactly where they were; this answers "is the CV service healthy," a question that doesn't reset just because the operator flipped a local switch.
- **`UsageTracker.TelemetrySubscriber.onError` is an empty method by design** — a telemetry source failure is completely silent, not even logged, because best-effort telemetry must never affect stream/usage lifecycle.
- **`UsageTracker` drops a telemetry sample that arrives after its usage has closed** instead of reopening a new usage for it.
- **`UsageTracker.onStreamStarted`'s `streamId` is only ever recorded on the call that opens the usage** — for an asset with several devices, only the first device's stream is ever visible on `AssetUsage#streamId`.
- **`DefaultStreamService` allows only one active stream per device** (Phase 0 scope) — starting a second throws `IllegalStateException` rather than replacing the existing stream.
- **The tracking component of the `PipelineConfig` you pass to `start`/`startStream` is the *bottom* layer of the fold, not the final answer** — the deployment seed and the request patch are applied on top of it inside the service. Pass `PipelineConfig.defaults()` and say what you mean in the patch.
- A present `TrackingConfigPatch` folds mode/engine/cadences **per field** (each nullable component independently), but its `lock` is itself null-means-unchanged — releasing a lock is the explicit `TargetLock{release=true}` form, never an omission. (The whole-`TrackingConfig`-replace T3 originally shipped was a defect: it silently reset every knob the caller didn't restate — see Status.)
- `ProbeService#probe` never registers anything and never touches any repository — a probe's `StreamId` is fresh, transient, and looked up nowhere else.

- **W1.6b** — `DetectionRepositoryPort`/`DetectionEvent`/`DetectionEventId`/`DetectionEventState`/`DetectionEventRepositoryPort` moved in from `events` (they store/shape detections; only this context's `DetectionEventEngine`/`DefaultStreamService` ever construct them).
